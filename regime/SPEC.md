# 全球大类资产方向框架（Regime）· 设计规范

> 版本 v0.1 · 2026-11-20 · 独立模块，不依赖也不改动主看板（`scripts/tpl.html` / `build_dashboard.py` / `server.py`）

---

## 0. 这个模块是什么

把「政策 / 宏观 / 产业 / 技术」四层判断，拆成可复核的读数，输出**三件并列的东西**：

1. **风险偏好总分**（-100 ~ +100）：决定总仓位与对冲比例
2. **模块 × 资产矩阵**（4 × 6）：决定结构调整，减谁加谁
3. **每格证据与分歧度**：决定这个判断敢下多重

它**不是**一个「红黄绿灯看涨看跌」的信号机。单一总分只能承载「风险偏好」这一个标量，承载不了「全球大类资产方向」——同样的利空，对美债可能是利多。

## 1. 不做的事

- 不生成观点文字。判断由人写，程序只搬运、算分位、算分歧。
- 不与主看板共享代码、数据目录、构建流程。删掉整个 `regime/` 不影响主看板任何功能。
- 不在第一期做回测（用户决定后置）。但**从第一天开始存每日快照**，否则将来无从回测。
- 不优化权重与弹性系数。先验固定，回测只用于证伪，不用于调参。

## 2. 结构

```
第 1 层  政策  ── 规则变化：立法、管制、关税、地缘        （人工 rubric + 少量可数指标）
第 2 层  宏观  ── 资金价格：利率、通胀、流动性            （全自动，FRED）
第 3 层  产业  ── 现金流：订单、产能、库存、融资条件       （全自动，FRED + 行情）
第 4 层  技术  ── 价格行为：趋势、破位、宽度、波动结构     （全自动，行情 + CBOE）

确认层  市场内部 ── 信用利差、波动率期限结构、股债相关性、仓位
                    （不产生方向，只调制置信度）
```

四层权重（**中期口径，1~6 个月**）：宏观 30 / 政策 20 / 产业 30 / 技术 20。

理由：主战场是中期，技术面半衰期只有 1~4 周，给 20% 是让它负责「时点」，不负责「方向」。政策与产业各占 20/30，因为它们决定中期的主线。

## 4. 评分口径

### 4.1 单指标 → 五档（-2 ~ +2）

1. 取**滚动 5 年（约 1250 交易日）分位** `p`，不用 Z 值——金融数据尾部厚，Z 值会被极值绑架。
2. 水平项：`dir=+1` 时，`p≥0.90 → +2`，`0.70~0.90 → +1`，`0.30~0.70 → 0`，`0.10~0.30 → -1`，`<0.10 → -2`。`dir=-1` 全反。
3. 变化项：同法算 3 个月变化的分位，权重 0.4；水平项权重 0.6。中期口径下，水平比变化重要。
4. `dir=0` 的倒 U 指标：先算偏离度 `|x − 中枢|` 的分位，越偏越不利。
5. 任何指标取不到 → 记为 `null`，**不填 0**，在证据表里显示「未获取」，并从模块分里剔除该项、按剩余权重重新归一。

**例外：核心 PCE 3M 年化改用绝对档位**，不看分位（`≤2.0 → +2`，`2.0~2.5 → +1`，
`2.5~3.0 → 0`，`3.0~3.5 → −1`，`>3.5 → −2`）。理由是 5 年窗口含 2022 年高通胀：
2.90% 在窗口里只排 34 分位，看着温和，可它离 2% 目标还差 0.9pp。
**凡有明确政策目标的指标，按「离目标的距离」分档；其余按历史分位。**

### 4.2 模块分（-100 ~ +100）

- 各指标档位（-2~+2）→ **截尾均值**：去掉一个最高、一个最低再平均（指标数 ≤3 时不去尾）。
  选截尾均值而非普通均值，是为了防止「一个 +2 一个 −2 抵消成 0」这种伪中性；也防止单一极端指标绑架整块。
- `模块分 = 截尾均值 / 2 × 100`。
- 模块内仅剩 1 个有效指标时，标 `weak=true`，该模块权重按一半计。

### 4.3 分歧度与强制降级

- `分歧度 = 剩余指标档位的标准差`（单位：档）。
- `>1.0` → 该模块**强制降一级灯**（深绿→浅绿、浅红→黄…），并在页面标「指标互相打架」。
  不确定就该显示为不确定，给个假精度比不给更糟。

### 4.5 资产分（矩阵）

对政策/宏观/产业三层，用**先验弹性矩阵**映射到 14 类资产；技术层直接取该资产自身的分数。

```
asset_a = [ Σ_{m∈政策,宏观,产业} w_m · s_m · e_{m,a}  +  w_tech · s_tech_a ]
          / [ Σ_{m} w_m · |e_{m,a}|  +  w_tech ]  × 100
```

`s_m` 为模块分/100，`w` 为权重（0.2/0.3/0.3/0.2），结果落在 -100 ~ +100。

**符号约定（先看这一条，踩过坑）**

`e` 的含义是「**该模块对 risk-on 的支持度上升 1 单位时，这个资产往哪走**」：
正 = 跟涨，负 = 反跌。因为 `s_m` 已经定义成「支持度」，符号必须与它配套。

实现时曾把政策与宏观两行按「恶化时资产往哪走」来填，两种约定混用，
结果宏观转鹰（s=−23）反而给美股贡献了 +5.6 分，方向全反。
所以：**填表前先默念一遍「支持度升，这个资产涨还是跌」**。

**弹性矩阵（先验，固定，不优化）**

14 类资产，全部美元计价（亚太与商品用美股上市 ETF）。按组分块，顺序与 `score.py` 的
`ASSETS`、`GROUPS` 一致——三处只此一份，改一个必须改全部，`build.py` 会在不一致时直接退出。

v0.2.0 新增八类的填法依据（别只留数字）：

- **SPY 每档比 QQQ 低 0.05~0.1**：宽基少了久期型成长股的权重。
- **SOXX 政策 1.0 / 产业 1.1**：出口管制与资本开支两头直接命中，全表最高。
- **白银**：政策 −0.5 弱于黄金的 −0.7（避险不如黄金，工业需求托底），
  产业 +0.5 远高于黄金的 +0.1（光伏与电子的真实用量在这里）。
- **原油政策为负**：地缘紧张 = 支持度降 = 油价涨，符号不能写成正。
- **亚太四地按对管制的暴露度排**：台湾 1.0 最敏感（半导体链 + 台海），
  韩国 0.9（存储与晶圆代工），日本 0.8（盟友且是转移受益方），印度 0.6（关联弱）。
  产业行同理分化：韩国/台湾 0.9，日本 0.6，印度 0.4。

**宏观行按历史 beta 重排（v0.2.1）**

原来亚太五个全是 0.4，等于假设「美国利率对日韩台印的传导完全一样」。
实测近 250 日（2Y 每 100bp 对应的资产涨跌）差 8 倍：
韩国 −14.8 / 印度 −6.1 / 中国 −5.0 / 日本 −4.9 / 台湾 −1.8。

但 e 是**净值**，不是单一机制：美债利率升 → 折现率升（压估值）+ 美元升
（未对冲 ETF 的美元回报被抬），两条方向相反。所以不能从「跟美国紧不紧」
直接推 e，要看轧差。台湾最低不是因为它跟美国疏远，而是它由半导体周期驱动——
它的高暴露在产业行（0.9）。

**本地政策不在模型里（v0.2.1 加表，不加分）**

政策与宏观两个模块的输入全是美国的。摊到亚太时隐含「本地政策跟着美联储走」，
而这个假设现在不成立：日本 +75bp / 韩国 +50bp / 印度 −25bp / 美国 0 /
台湾自 2024-03 起停在 2%。

处理方式是**加一张对照表，不加一个新模块分**，两条理由：

1. 台湾、印度的政策利率在 FRED 没有可用序列（台湾无，印度停在 2022-07），
   硬造本地模块分会有一半地区靠猜；
2. 加本地分会污染「风险偏好标量」的语义——它现在回答的是「美元体系的风险状态」，
   掺进本地项之后就说不清它代表什么了。

数据源：BIS CBPOL 月度库（US/JP/KR/CN/IN，**不含台湾**）、台湾央行官网
重貼現率（一手来源，带生效日）。BIS 那个 zip 有 284KB，本地缓存 7 天。

**归一化会压缩弹性差异（必须知道）**

资产分是 `num/den`，而 `den` 里也有 `|e|`。所以调大某个资产的 e，分子分母同时变，
总分只向该模块分靠拢一部分，不会等比例放大。

实测：韩国宏观 e 从 0.4 调到 0.7，资产分只从 −33.8 变 −32.4（1.4 分），
而矩阵里那一格从 −2.8 变 −4.9（差 75%）。

**结论：要看传导强度的差异，看矩阵那一行，不要看资产总分的差值。**
总分是被归一化钝化过的。这一条不写下来，下次会有人以为弹性没生效。

**美债那一行的符号必须一正一负，这是本框架最关键的一处设定。**

同样叫「利空」，两种机制对债券方向相反：
- **地缘型 risk-off**（政策分低）→ 资金涌入国债，债券**涨** → 支持度升时债券跌，故 `e` 取**负**（−0.3）
- **货币型 risk-off**（宏观分低、联储转鹰）→ 收益率上行，债券**跌** → 支持度升（转松）时债券涨，故 `e` 取**正**（+0.5）

如果统一用「risk-off 就买债」的直觉，会在 2022 型（通胀驱动）环境里给出完全错误的债券方向。这一条写在这里，是为了防止后来的人「顺手改成一个符号」。

同一个道理横过来看：政策行对黄金、美元取负（支持度升=避险退=金跌、美元跌），
对美股、工业金属、A股取正。这不是拍脑袋，是逐格问过「支持度升时它涨还是跌」的结果。

**政策未确认时怎么显示（v0.1.1 补）**

政策模块 `score is None` 时，资产分里不含政策那 20% 权重（分母同步剔除，其余模块按比例分摊）。
但页面上仍须让人看到「四层」——否则每张资产卡只剩三条，看起来像框架塌了一层：

- 矩阵的政策行、资产卡的政策条，都用 `preview_score` 算一条**参考贡献**，画灰柱 + 星号；
- 这条参考值**不进 `asset_a` 的计算**，合计行与资产分不受影响；
- 只有 `state=confirmed` 后才替换成正式贡献（绿/红柱，无星号）。

实现位置在 `score.py` 的资产循环：**必须先判 `score is None` 再判 `weak`**。
政策 pending 时 `weak=True`，顺序反了会被 `weak` 提前跳过，
卡片又只剩三层——v0.1.0 就是这么错的，改的时候别把顺序再调回去。

**技术模块分随资产数量变化（v0.2.0 起必须知道）**

技术模块分是**全部资产各自技术分的均值**，不是某一只指数。所以：

- 增删资产会直接改变技术模块分，进而改变风险偏好总分（技术权重 20%）；
- v0.2.0 从 6 类扩到 14 类，同一日 tech 由 −41.4 变 −52.7、风险偏好 −12.3 → −15.2，
  **历史读数不可比**，所以这次按 MINOR 处理，不是 PATCH；
- 样本重心偏了：14 类里亚太 5 个、商品 4 个。技术模块分现在更接近「全球风险资产的
  平均位置」，而不是「美股技术面」。想回到美股口径要单独看 SPY/QQQ/SOXX 三张卡。

## 4.6 数据滞后必须显示

宏观与产业指标大多是月度、且发布有延迟：核心 PCE 与新订单的最新值通常比当天晚 60~80 天。
每个指标都要带 `lag`（数据日距今天数），页面在滞后超过 45 天时标黄。

理由：不加这个数，读者会把「9 月的新订单」当成「今天的基本面」。产业模块给正分而
技术面已经破位，这种矛盾有一半来自滞后——页面必须让读者自己看见这一点，
而不是靠总分把它们揉平。

## 5. 时间尺度

各指标前瞻窗口见 §3。聚合时：

- 模块分只在**同一窗口内**聚合，跨窗口不平均。
- 对外只给三档结论：短期（1~4 周，几乎由技术面决定）、**中期（1~6 月，主战场）**、长期（6~18 月，由政策与产业决定）。
- 页面上明确写出「本期口径 = 中期」。

## 6. 政策模块：人工 rubric

政策无法自动打分，采用「**判据表 + 事实条目**」：

- `data/policy_rubric.json`：四个维度、每维 5 档、每档写明「什么样的事实算这一档」。**只由维护者改**。
- `data/policy_answers.json`：当前打分，一条一档，每条必须挂 `fact`（发生了什么）、`date`（事件日，不得推算）、`source`（链接）、`state`（`confirmed` / `pending`）。
- `pending` 的条目不进分数，只在页面显示为「待确认」。这样「我听说」和「有通稿」在页面上是两种东西。

维度与权重：

| 维度 | 权重 | 问的问题 |
|---|---|---|
| P1 产业政策 | 0.35 | 对 AI 基建/半导体的公共支持在变强还是变弱？ |
| P2 地缘风险 | 0.25 | 军事与贸易摩擦在升级还是缓和？ |
| P3 技术管制 | 0.25 | 对华出口管制在收紧还是放松？ |
| P4 财政与监管 | 0.15 | 财政是扩张还是紧缩？有无反垄断/加税动作？ |

方向统一为「**对 risk-on 的支持度**」：支持度越高分越高。所以管制升级、地缘紧张都是负分。

## 7. 数据与产物

```
regime/
├── SPEC.md                  本文件
├── fetch.py                 抓数 → data/series.json
│                            （FRED / CBOE / Yahoo / BIS CBPOL / 台湾央行）
├── score.py                 分位、五档、模块分、矩阵、分歧度 → data/score.json
├── build.py                 生成 out/regime.html
├── data/
│   ├── raw/                 原始响应缓存（*.csv / *.json / *.zip），不入库
│   │                        bis_cbpol.zip 本地缓存 7 天，月度数据不必天天抓
│   ├── series.json          解析后的序列，不入库（可重抓）
│   ├── score.json           评分结果，不入库（可重算）
│   ├── policy_answers.json  dims 判据表 + answers 当前打分（**人工维护，入库**）
│   ├── notes.json           人写的结论与理由（**人工维护，入库**）
│   └── snapshot/YYYY-MM-DD.json   每日快照，回测的唯一依据（不入库）
└── out/regime.html          独立页面，可直接双击打开（产物，不入库）
```

三档文件严格分开，是为了让「机器搬的」「人判断的」在仓库里就是两种东西：
`series.json` 可随时删掉重抓，`policy_answers.json` 与 `notes.json` 丢了就找不回来。

## 8. 红线

1. **日期必须来自原始数据**，不推算、不编造。
2. **取不到就标「未获取」**，不填 0、不用近似值冒充。
3. **不生成判断文字**。页面上的结论句由人写（`data/notes.json`），程序只渲染读数。
4. **不改主看板**。任何跨模块引用都算违规。
5. **权重与弹性先验固定**。想改，先写下改的理由与预期影响，再改。

## 9. 已知限制

1. **利率路径抓不到真值**。CME FedWatch 与 OIS 期货需付费/需 key，本模块用「2Y 收益率 20 日变化」作代理。代理能反映「重新定价的方向与速度」，但给不出「计价了多少 bp」。这一点在页面上必须写明，不能让读者以为看到的是 FedWatch。
2. **盈利修正广度缺失**。需要 Refinitiv/Bloomberg 级数据，本模块用「新订单 + 产能利用率 + 半导体相对强弱」三角替代，颗粒度更粗。
3. **云厂 capex guidance 缺失**。季度数据需人工录入，第一期先在 `data/manual.json` 留位，不做自动。
4. **政策分完全依赖人工**。这是设计选择，不是缺陷——但也意味着政策的时效取决于填写频率。
5. **分位用滚动 5 年**。在制度突变（如 2022 年加息周期）后，5 年窗口会把「新常态」判成极端值，需要人工识别。
