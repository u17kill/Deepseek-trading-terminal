## 零、版本修正记录

### v4（2026-10-29）：拥挤度模块重构

**动机**：v3 的拥挤模块由「换手率 / 成交额比 20 日均额 / 量价相关性」组成，三者都是价格衍生量。实测其与位置模块的相关性为 0.63（科创 50）/ 0.58（创业板指），意味着 35% 的权重里有相当部分在重复计权位置信息。

**候选子项的独立性检验**（与位置模块的相关系数）：

| 子项 | 科创50 | 创业板指 | 结论 |
|---|---|---|---|
| 成交额占两市比重 | 0.29 | 0.26 | 采用 |
| 20 日已实现波动率 | **0.05** | **−0.03** | 采用 |
| 换手率分位 | 0.49 | 0.46 | 降权至 20% |
| 融资买入额占成交额（两融） | **0.64** | **0.65** | **剔除** |
| 成交额 / 20 日均额（原） | 0.60 | 0.54 | 剔除 |
| 量价相关性（原） | — | — | 剔除 |

**两融的结论值得单独说明**：数据本身完全可得（沪深两市融资买入额，日频，2021 年以来无缺失），但检验证明它与价格位置高度正相关——涨的时候加杠杆、跌的时候撤杠杆。它是价格的影子，不是独立维度。因此**没有纳入分数**，只在页面作为「杠杆环境」观察项展示。这推翻了「补两融能提升拥挤度质量」的初始假设。

**权重方案对比**：

| 方案 | 拥挤~位置 | IC(5日) 科创 | IC(5日) 创业板 | 总分 科创 / 创业板 |
|---|---|---|---|---|
| v3 原方案 | 0.63 / 0.58 | 0.078 | 0.062 | 19.9 / 22.0 |
| P1 占比45/波动25/换手30 | 0.40 / 0.36 | 0.056 | 0.049 | 23.8 / 27.9 |
| **P2 占比50/波动30/换手20（采用）** | **0.36 / 0.33** | **0.052** | **0.049** | **25.3 / 30.0** |
| P3 占比55/波动45（纯独立） | 0.24 / 0.21 | 0.047 | 0.050 | 27.9 / 34.0 |

选择 P2 而非 P3：P3 独立性更好，但完全剔除换手率会丢掉「筹码换手速度」这一层语义，且 IC 并未更好。

**代价**：IC 由 0.078 降至 0.052（科创 50），预测力下降约三分之一。同时 IC 由正转微负（20 日 -0.074），方向更符合「超买超卖」的本意。本页定位是状态播报而非择时，因此接受这个交换——用预测力换独立性与可解释性。

**总分变化的原因**：拥挤模块数值整体上移（科创 34.4→50.7，创业板 39.7→64.7），因为当前两只指数的成交占比与波动率都在高分位（创业板成交占比 78.8、波动率 75.6）。这不是 bug，是真实信息：**放量下跌意味着交易激烈，而交易激烈本身就是拥挤的一种形态。**


### v3.2（2026-10-29）：一键更新 + 估值分位页

**新增一：本地取数服务与「更新数据」按钮**

页面右上角按钮 → POST `/api/refresh` → 服务端调 westock 取全量日线 → 按固定算法重算 → 返回新数据并重渲染，全程约 7 秒。

实现要点：
- `scripts/server.py` 托管页面并提供 `/api/refresh`、`/api/data`；
- 计算逻辑抽到 `scripts/indicator_core.py`，与 v3.1 逐项比对一致（分数、三个分项完全相同）；
- Windows 下 subprocess 必须用绝对路径调用 `westock.exe`，只写命令名会报 `WinError 2`——subprocess 不会自动补 `.exe`；
- 双击 `start-dashboard.bat` 启动服务并自动打开浏览器。直接双击 HTML 文件仍可查看，但按钮不可用（页面会提示）。

**新增二：估值分位 Tab**

第二个主 Tab，回答与第一页完全不同的问题：不看“多热”，看“多贵”。

**这一页最重要的发现：两只指数的“跌”性质完全不同。**

| | 短期位置（第一页） | PE 分位 | 性质 |
|---|---|---|---|
| 科创50 | 5.8（接近近一年最低） | **77.1%（偏高）** | 跌了，但**没有变便宜**——盈利下滑速度快于股价 |

**估值口径的重要提醒**

同一日（2026-10-28）科创 50 的 PE：蛋卷 105.19，中证指数官网 84.64（总股本法），差约 24%。差异来自成分股加权方式与亏损股处理规则。因此：

- 只用分位做纵向比较（同一口径内排第几）；
- 不用 PE 绝对值做横向比较（105 与 30 不可直接比）；
- 页面已明确标注这一点，避免误用。

**已知限制**：估值数据为周频且为 T-1，不适合日内或短线择时；低估值可以更低，2022 年创业板指 PE 跌至 23 倍附近后仍有漫长磨底。该模块只用于“定位置”，不用于“定时机”。

### v3.1（2026-10-29）：三处缺陷修正

**缺陷一：原始数据日期字段带前后空格（根因级）**

`data/oos/kc50.csv` 与 `cyb.csv` 的 date 列是从 markdown 表格解析而来，保留了 `| 2026-10-29 |` 中的首尾空格，实际值为 `" 2026-10-29 "`。这个空格引发的连锁问题：

- 事件表用 `e.from.slice(2)` 截取短日期，因首字符是空格，截出 `"023-03-23 "`，**日期首位被吃掉了**；
- 图表 X 轴 category 标签实际宽度为 12 字符而非 10，此前多次调整 `axisLabel` 的 width / formatter 均无效，原因就在这里——不是 ECharts 的问题，是数据脏；
- 页眉"样本区间"显示双空格。

修正方式：在 `run()` 读入 CSV 后立即 `df["date"].str.strip()`。修正后 X 轴标签、事件表日期、页眉均恢复正常，`axisLabel` 恢复 ECharts 默认渲染即可。

**缺陷二：`trigger_pct` 字段逻辑错误**

原实现为 `o.bk.isin(["极端超卖","极端超买"]).groupby(o.bk).mean()`。对"极端超卖"分组求布尔均值，因该组内每行都在 isin 集合中，结果恒为 100%，不携带任何信息。该字段从未在页面使用，已删除。

**缺陷三：展示层三处问题**

- 分档表的"档位"列宽不足，`极端超卖` 被挤成竖排两行；
- 年度高低点表用红/绿标注读数高低，与 A 股"红涨绿跌"习惯冲突，易被误读为涨跌。该处颜色原本表示热度，已改为不加颜色、仅加粗；
- 事件表在科创 50 下只出现超买事件，未说明原因。已补充说明：科创 50 极端超卖平均仅维持 1.4 天，从未连续 3 日以上。

### v3（2026-10-29）：动能模块定义修正

v2 的动能模块使用「RSI6 五日变化量」与「MACD 柱五日变化量」的滚动分位，导致两个问题：

v2 的动能模块使用「RSI6 五日变化量」与「MACD 柱五日变化量」的滚动分位，导致两个问题：

1. **基数效应**。2026-10-14 至 10-22 创业板指连续下跌，RSI6 从 8.3 掉到 2.7（接近归零），此后任何反弹都使「五日变化量」变成大幅正数，分位冲至 90 以上。10-23 单日反弹 4.16% 时，动能分从 53.7 跳到 84.1。
2. **语义错配**。该定义衡量的是「变化的速度」（加速度），而非「当前的速度」。在暴跌末段，由于跌势开始减速，指标反而给出高分，与「跌势动能强劲」的直觉完全相反。

v3 改用**真实推进速度**：RSI6 原值与「10 日风险调整收益分位」各占一半。同一时点，动能分从 89.7 修正为 17.9。

| 时点 | v2 动能 | v3 动能 |
|---|---|---|
| 科创50 2026-10-29 | 69.6 | 15.8 |
| 创业板指 2026-10-29 | 89.7 | 17.9 |

## 一、指标定义

总分 = 0.40 × 位置 + 0.35 × 拥挤 + 0.25 × 动能，合成后做 3 日 EMA 平滑。

| 模块 | 权重 | 子项 | 内部权重 |
|---|---|---|---|
| 位置 | 40% | BIAS20 滚动 250 日分位 | 40% |
| | | 布林带带宽内位置分位 | 30% |
| | | 距 250 日最高点回撤幅度 分位 | 30% |
| 拥挤 | 35% | 成交额占两市比重 分位 | 50% |
| | | 20 日已实现波动率 分位 | 30% |
| | | 换手率 250 日分位 | 20% |
| 动能 | 25% | RSI6 原值 | 50% |
| | | 10 日风险调整收益 分位 | 50% |

分档：≤15 极端超卖 / 15–30 警戒超卖 / 30–70 正常 / 70–85 警戒超买 / ≥85 极端超买。

## 三、四个必须正视的结论

### 3.1 极端超买之后是涨还是跌：两个指数给出相反答案

v3 曾发现一个反直觉现象：创业板极端超买后 20 日平均大涨 10.07%、胜率 80.8%。v4 改口径后这个结论分化了：

| 极端超买（≥85）后 20 日 | 科创50 | 创业板指 |
|---|---|---|
| 平均收益 | **−3.40%** | +2.99% |
| 上涨概率 | **31.9%** | 57.1% |
| 平均最深回撤 | −9.04% | −5.29% |
| 样本天数 | 47 | 21 |

科创 50 上，「极端超买」终于表现为后续下跌；创业板指上仍然是上涨。这说明**「超买该跌」不是普适规律，而是取决于该指数当前的动量/反转结构**——2022 年以来创业板经历过多轮强趋势，动量效应压过反转效应；科创 50 的波动更依赖情绪与资金，超买后的回吐更明显。

实践含义：**不能拿同一套阈值逻辑在两个指数上做同一件事**。看到科创 50 的极端超买，可以认为短期风险偏高；看到创业板的极端超买，只能说「热」，不能说「要跌」。

### 3.2 位置与动能模块高度共线

位置模块与动能模块的相关系数为 0.89（科创）、0.89（创业板）。原因很直接：BIAS、布林位置、RSI、10 日收益全部是价格衍生量，衡量的本质是同一件事。

实测对比：两模块方案（位置 60% + 拥挤 40%）的 IC 为 0.088，三模块方案为 0.086，**几乎完全相同**。第三个模块的独立信息量接近于零，它的价值在于可解释性（告诉使用者「劲还在不在」），而不在于提升预测力。

这是本次构建最重要的方法论教训：**加权合成不是维度越多越好，共线性会让权重设计失去意义**。

v4 的拥挤模块重构正是沿着这条教训做的，并且证明了改善是可能的：把拥挤从「价格衍生量」换成「资金面相对量」后，拥挤与位置的相关性由 0.63 / 0.58 降到 0.36 / 0.33。三个模块的相关性矩阵现在是：

| | 位置 | 拥挤 | 动能 |
|---|---|---|---|
| 位置 | 1.00 | 0.36 / 0.33 | **0.90 / 0.89** |
| 拥挤 | | 1.00 | 0.32 / 0.18 |

剩下的冗余集中在「位置—动能」这一对，因为 RSI 与风险调整收益终究是价格算出来的，无法脱离价格。**这说明三个模块里真正独立的只有两个多一点，不是三个。**

### 3.3 复合指标并非全面优于单指标

科创 50 上复合 IC（0.086）优于纯 RSI6（0.074），但创业板指上反而略差（0.082 vs 0.084）。复合降低方差、提升稳定性，但也稀释了单一强信号。

### 3.4 极端样本量仍然不足

科创 50 全样本极端超卖**仅剩 2 天**（v3 为 7 天），其 +2.16% 的 20 日收益基于 2 个观测值，毫无统计效力，页面上已明确标注不可单独依据。创业板极端超卖 10 天、极端超买 21 天，略好但仍偏少。

需要强调的是：极端档样本变少不是数据问题，而是**新口径让分数整体上移**的直接后果——拥挤模块的成交占比与波动率当前处在高分位，抬高了合成分数。若后续希望恢复更多极端样本，应当调整分档阈值而非回退口径。

## 五、看板第一页：超买超卖

看板不再只呈现数字，每个数字旁都写明含义。页面自上而下七个区块：

| 区块 | 回答什么问题 | 关键表述 |
|---|---|---|
| 速读三条 | 这页的分数该怎么理解 | 分数是排名不是得分；高不代表要跌；必须看分项 |
| 今日读数卡 | 现在什么状态 | 分数 + 档位 + 三根分项条 + 每个分项一句人话 + 组合判断 |
| 三模块说明 | 位置 / 拥挤 / 动能各是什么 | 比喻 + 0/50/100 三段含义 + 各指数当前状况 + 观察的具体指标 |
| 分数怎么读 | 0–100 的含义 | 同一分数的两副面孔对照、三档含义、为何要转分位 |
| 五档说明 | 每个档位的含义 | 分数区间、含义、该怎么想、各指数历史占比 |
| 走势图 | 读数与价格的关系 | 两条线经常不同步，不同步本身就是信号 |
| 分档检验 | 落进每一档之后历史上发生了什么 | 各列统计口径、样本量太小的档不能当结论 |

### 三个必须固定在页面上的定义

**一、分数是百分位，不是得分。**
把样本期内每个交易日按过热程度排队，分数即当日排名。25.3 表示过去 1116 个交易日里约 25.3% 更冷、74.7% 更热。不存在及格线或满分概念。

**二、0 与 100 都是"极端"，方向相反。**
- 位置：0 = 价格向下绷到最紧（跌到近一年最惨），100 = 向上绷到最紧（涨到近一年最贵）
- 拥挤：0 = 门可罗雀，100 = 人挤人
- 动能：0 = 往下砸得最猛，100 = 往上冲得最猛

**三、"历史占比"是可信度的前提条件。**
分档表里的占比列，指样本期内落在该档的交易日比例。占比过小意味着样本过少——科创 50 极端超卖仅占 0.6%（7 个交易日），该档的后续收益均值不具统计效力。这一列的作用是提醒读者：哪些档位的结论可以信，哪些只能当参考。

### 组合判断规则

页面底部的"合起来看"一句，由三个分项联合决定，非单一阈值：

| 条件 | 判断 |
|---|---|
| 位置低 + 拥挤低 + 动能低 | 跌得深、没人气、还在往下走 —— 超跌但未止跌 |
| 位置低 + 拥挤低 + 动能高 | 跌得深、没人气、下跌已刹住 —— 底部常见形态 |
| 位置低 + 拥挤高 | 恐慌性放量出逃，常出现在阶段性底部附近 |
| 位置高 + 拥挤高 + 动能高 | 涨得多、人挤人、还在冲 —— 过热，短期风险最大 |
| 位置高 + 动能低 | 位置还高但劲头没了 —— 强弩之末 |
| 位置高 + 拥挤低 | 缩量上行，缺后续动力 |

当前两只指数分属两条规则：科创 50（位置 5.8 / 拥挤 50.7 / 动能 15.8）落在"跌得深、还在往下走——超跌，但下跌还没止住"；创业板指（位置 6.9 / 拥挤 64.7 / 动能 17.9）落在"跌得深、交易却很激烈、还在往下走——抛压在集中释放"。v4 补上了拥挤处于 40–60 中间区间时的规则，此前该区间会错误地落到"常态波动"兜底。

## 六、看板第二页：估值分位

### 结构

| 区块 | 内容 |
|---|---|
| 两页对照 | 短期位置 vs PE 分位，直接给出性质判断（跌了是否变便宜） |
| 估值卡 | 当前 PE、绝对分位标签、近 3/5 年及长期分位条、PB、历史中位与区间 |
| PE 走势图 | 左轴 PE-TTM、右轴指数收盘、三条参考线（P20 / 中位 / P80） |
| 汇总表 | 两只指数各周期分位、中位、区间、PB、股息率 |

### 三个必须固定在页面上的概念

**一、分位是横向比较的唯一可靠口径。**
PE 绝对值 105 与 30 不能直接比（行业结构、盈利质量、亏损股处理均不同）；但“在自己历史上排第几”可以比。因此全页只做纵向分位比较，不做绝对值横向比较。

**二、估值回答位置，不回答时机。**
低估值可以更低。创业板指 2022 年 PE 跌到 23 倍附近后仍有漫长磨底。估值给出的是向下空间可能有限，不是何时上涨。它需要与第一页配合：**估值定位置，动能定时机**。

**三、两页结论冲突时，以分项结构解释，不要强行统一。**
当前科创 50 就是典型：短期位置 5.8（极低）而 PE 分位 77.1%（偏高）。这不矛盾——股价跌了，但成分股盈利下滑更快，所以估值反而更贵。这类组合在成长股杀业绩阶段很常见，它的风险恰恰高于“跌了也便宜了”的创业板指。

### 更新机制

`scripts/server.py` 提供本地服务，页面按钮触发 POST `/api/refresh`：

1. 用 `westock.exe kline` 取两只指数 2021 年至今全量日线（约 7 秒）
2. `indicator_core.run()` 按 v3.1 固定算法重算
3. 调蛋卷接口刷新估值序列
4. 覆盖写 `data/oos/*.csv`、`result_latest.json`、`valuation.json`，返回前端重渲染

估值接口失败时不阻断行情更新（降级为沿用本地缓存），页面顶部状态会显示更新时间与耗时。
