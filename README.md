# Deepseek Trading Terminal

本地运行的多市场交易终端。一个 HTTP 服务、一个单文件 HTML，九个页签回答九个不同问题。

| 页签 | 直达 | 回答的问题 | 标的 |
|---|---|---|---|
| 市场总览 | `/`、`#market` | **今天发生了什么** | 自选资产 23 个（股指/商品/外汇/加密，可增删可拖动排序）+ 自选股矩阵（拖动即改板块归类） |
| 市场新闻 | `#news` | **现在该看什么** | 头条带 7 条 + 六个互斥分类流（宏观政策 / 地缘与贸易 / 美国国内 / 中国国内 / AI 与科技 / 传统产业）共 44 条；头条取 24 小时、分类取 72 小时，每条带「为什么重要」与影响面（股/债/汇/商品/加密）；页内「更新新闻」重抓原始池并重建 |
| 最新风向 | `#wind` | **大佬们在说什么** | 六大类 111 位（宏观分「买方与媒体 12 / 卖方（美股与全球）4 / 卖方（中国区）6」，政府分五地区共 20 位，另含价值 9、科技投资人 16、科技与产业 34、央行与监管 10），近三个月 404 条要点；页内「更新风向」重载数据并体检新鲜度 |
| 动能分析 | `#hot` | 现在有多热 | A股 4：科创50、创业板指、沪深300、中证红利；美股 4：QQQ、SOXX、标普500、道琼斯 |
| 估值分位 | `#val` | 现在贵不贵 | 同上八个（道琼斯无可用估值口径，页面留空并说明） |
| 短线精灵 · A股 | `#senti` | A 股今天冷不冷 | A 股全市场 |
| 短线精灵 · 美股 | `#us` | 美股今天冷不冷 | 美股四池 + 11 个行业 |
| 港股全景 | `#hk` | 港股今天冷不冷、空头有多重 | 恒指 + 恒生科技 + 国企（去重 112 只） |
| 亚太温度 | `#apac` | 日韩台印新今天冷不冷、谁在跑赢 | 日经225 + KOSPI + 台湾加权 + SENSEX + STI（恒指作参照条） |

## 快速开始

双击 `start-dashboard.bat`，浏览器自动打开 `http://127.0.0.1:8765/`。

**必须通过 `http://127.0.0.1:8765/` 访问，不要双击 `output/` 里的 HTML 文件。** 用 `file://` 打开时页面脚本无法请求本地接口，刷新按钮一定失效，页首会显示红色提示带。

依赖：

```bash
pip install pandas numpy akshare requests
# westock CLI 需自行安装到 ~/.local/bin/westock.exe（腾讯自选股行情）
```

## 目录结构

```
scripts/
  server.py           HTTP 服务 + 七个刷新接口与一个写入接口（各自独立锁，互不阻塞）
  indicator_core.py   位置/拥挤/动能三模块计算（A 股与美股两套口径）
  market_context.py   两市成交额 + 两融 → 拥挤模块的分母与杠杆观察
  valuation.py        A 股估值（蛋卷基金）：科创50 / 创业板指 / 沪深300 / 中证红利
  us_valuation.py     美股估值（QQQ、标普500 走蛋卷，SOXX 走前瞻 PE，道琼斯无源）
  us_etf.py           QQQ / SOXX / IVV / DIA 日线（缓存优先 + 增量补尾）
  wsfeed.py           westock CLI 封装：限频重试、节流、行数完整性校验
  market.py           市场总览：资产卡 + 自选股矩阵 + 搜索（第一页）
  news.py             市场新闻：抓 RSS / 快讯 → 原料池 → 合并策展稿（第二页）
  wind.py             最新风向：装载 / 校验 / 按分类统计（第三页）
  sentiment.py        A 股情绪周期复盘（第六页）
  us_senti.py         美股八个模块（第七页）
  hk_senti.py         港股八个模块（第八页，含沽空与南向归档）
  apac.py             亚太五地指数卡 + 相对强弱（第九页，走新浪 gi 日线）
  tpl.html            页面模板（含 /*__DATA__*/、/*__MARKET__*/ 等占位符）
  build_dashboard.py  模板 + 数据 → output/指数超买超卖看板.html
  indicator_v1~v3_1.py  历史版本，仅作算法演进的对照，不被任何代码引用；
                        当前生效的是 indicator_core.py（与其 v3.1 算法一致）
research/             口径文档、公式规范、验证结论
data/                 行情缓存（不入库，例外：fng_archive.json、short_archive.json）
                      注：data/apac/ 整目录不入库，五地日线与恒指缓存可随时重抓
                      data/market/ 只入库 config.json（自选清单）与 brief.json（判断文字），
                      行情缓存 market.json 不入库
output/               构建产物（不入库）
VERSION               版本号唯一来源（纯文本，如 1.9.0）
```

改页面只动 `tpl.html`，然后 `python scripts/build_dashboard.py` 重新生成。改计算逻辑只动 `indicator_core.py`。

**版本号只在一个地方写**：根目录 `VERSION`。构建时由 `build_dashboard.py` 注入页面右上角角标
和 `/api/ping` 的返回，不要在其他文件里另写一份——两处不同步比没有版本号更麻烦。
发版流程：改 `VERSION` → 改 `CHANGELOG.md` → `python scripts/build_dashboard.py` →
`git tag -a vX.Y.Z` → `git push --tags`。

## 口径红线

这几条是踩过坑之后定的，改动前务必先看 `research/` 里对应的文档。

**1. 不同来源的 PE 绝对值不可横向比较。** 同一日科创50 的 PE，蛋卷报 105.19、中证指数官网报 84.64（总股本法），差 24%。页面只用分位做纵向比较。

**2. SOXX 用的是前瞻 PE，不是 PE-TTM。** 它放在 A 股旁边会显得极度便宜，那是口径造成的。只能在同一口径内看纵向分位。

**3. CNN 恐惧贪婪指数与 A 股自建情绪温度毫无关系。** 两套算法、两套刻度，只能各看各的趋势，绝不可放在同一根轴上比高低。且 CNN 衡量的是标普 500 全市场，不是纳指或半导体情绪。

**4. 港股页只有「位置」和「动能」两项能跨页比，热度不能。** A 股总分里 35% 权重是「成交额占两市比重」，港股没有可比的「两市」分母，所以港股热度用的是本页自建权重（位置 5 / 动能 3 / 量能 2）。两页的 60 分不是一回事。另外港股沽空率是**交易所官方披露口径**，与 A 股/美股那种自建情绪指标不同性质，也不能混着比。

**5. 亚太页不合成总分、也不做量能。** 五个市场里日经与新加坡的成交量恒为 0，韩国有量无成交额，台湾四成交易日成交量为 0——凑不出统一口径。同时缺「成交额占比」这个分母，按归一权重合成分会与 A 股页的分数不是同一把尺子。故该页只给位置与动能两个分项，用象限图表达联合状态。

**6. 亚太页的相对强弱按同一日历窗口对齐，不是「最近 N 根」。** 各市场交易日数不同，同样 60 根跨的日历长度能差好几天（实测台湾回溯到 07-31、标普回溯到 08-06）。直接相减得到的「超额」里有一半是窗口错位，不是真实强弱差。

**7. quote 不能混品种批量，混了会静默丢类。** 股票、期货、外汇放进同一批时，期货与外汇会被丢掉，退出码仍是 0。市场总览因此按三类分批取数并核对条数，缺一条即报错。

**8. 三类资产的「当天」长度不同。** 股票 4~6.5 小时、期货外汇约 23 小时、加密 24 小时、日韩台印新只有日线。迷你图不可横比波动幅度。

**9. 「今日市场」的判断文字绑定数据日期。** 跨日自动降级为「上一交易日」，宁可显示「尚未生成」也不让模板假扮判断。



另外：`data/us_senti/fng_archive.json` 是每日累积的 F&G 快照。CNN 官方只提供滚动 1 年历史，**这个文件是唯一的长周期记录，丢失不可重建**，因此单独放行入库。

## 文档约定

- **`SPEC.md`**：完整技术规格，自包含，可供外部评审或复验。含全部公式、数据源、口径红线、已知局限与待解决问题。
- `research/` 存口径与方法论：指标怎么定义、为什么这么定、验证结果、代价与局限。
- `CHANGELOG.md` 存变更记录：每次改了什么、为什么改、付出什么代价。
- 版本用 git tag 标记（`v1.4.0` 这类），对应 CHANGELOG 的段落。

需求是边做边定的，因此不维护独立的需求规格书——CHANGELOG 里的动机说明和 `research/` 里的口径文档合起来承担这个职责。
