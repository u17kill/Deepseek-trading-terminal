# 需求文档 · 持仓地图（当前持仓页）

> 这是一份**可直接开工**的需求文档：数据、口径、界面、验收数字都在里面。
> 不需要访问原项目，也不需要猜任何一处业务规则。
>
> **怎么用**：整份贴给开发方（人或模型），从 §11 的开工提示开始执行。
> §3 的三段 JSON 就是初始数据，可原样落盘；§9.1 是可以逐行对表的验收数字。
> 只想知道要做成什么样，读 §0、§2、§6；要动手，先读透 §4 和 §5。

---

## 0. 一句话

做一个**自用的个人持仓看板**，一页讲清三件事：

1. **我有多少钱，分别放在哪** —— 两个仓（核心仓 / 卫星仓）折算合并成一个总仓；
2. **这个结构合不合理** —— 七个维度对着人定的目标区间，超几 pp、欠几 pp 直接标出来；
3. **该不该动、动哪里** —— 判断文字由人写，读数由程序算，两者并排放，对不上就是判断该重写了。

### 交付物

一个**单文件 HTML**（内联 CSS + JS + 数据），双击即可打开，无需构建、无需后端也能看。
可选增强：一个极简本地服务，用于把编辑写回 JSON 文件（见 §7.4）。

### 技术约束（建议，不是教条）

- 原生 JS + 一个 HTML 文件；**不要**引入框架、构建链、CDN 依赖（离线可用是第一要求）。
- 金额一律**整数「分」**运算，禁止浮点累加（原因见 §4.2）。
- 图表用内联 SVG 手绘，不用图表库。
- 目标视口 1180px 宽，最小支持 380px。

## 1. 背景与使用场景

使用者是一个中文个人投资者，资产分成两块，**记账币种不同**：

| 仓 | 记什么 | 币种 | 文件 |
|---|---|---|---|
| 核心仓 | 基金，以及基金内部拆出来的资产行 | 人民币（`1k` = 1,000 元） | `core.json` |
| 卫星仓 | 单只个股 / ETF / 期权，按主题和地区落格子 | 美元（`1k` = 1,000 美元） | `matrix.json` |
| 总仓 | 以上两者折算合并后的读数 | 人民币 | 无独立文件，算出来的 |

**这不是券商账户**。表里填的是「我打算放多少钱在这只票上」的**仓位备注**，
不是市值、不是成本、不是盈亏。所以页面永远**不接实时行情**，也不显示涨跌。

一个月看几次：改几张卡片 → 看总仓和结构 → 读一遍判断 → 决定要不要调比例。
因此设计要求是**信息密度高、能一眼扫完**，不是好看、不是动效。

## 2. 信息架构

页签内部有三个视图，同一时间只显示一个：

```
当前持仓
├── 总仓    ← 默认视图。只读，四个区块，从上到下：
│   ├── ① 总仓合计      一个大数字 + 构成条
│   ├── ② 持仓体检      左判断 / 右读数 / 问题 / 动作 / 页脚
│   ├── ③ 两仓构成      两行表 + 合计行
│   └── ④ 合并切分      国家 / 风格 / 资产类别 三列
├── 核心仓  ← 可编辑：基金 → 资产（两层）
└── 卫星仓  ← 可编辑：策略段 × 主题列 × 地区行 的矩阵
```

**为什么体检放在合计和构成之间**：先看总数，紧接着一句「这张表合不合理」，
再往下才是构成明细。放页尾等于结论在最后一行，没人翻到；放合计之上又变成先听结论再看数。

视图选择记在 `localStorage.pmx_mode`，刷新后回到上次的视图。

### 2.1 卫星仓视图的区块顺序（从上到下）

```
├── 计数条   卡片 71 张 / 计入 52 / 观察 17 / 期权 2 / 备注不可计算 0 ＋ 保存状态 ＋「+ 添加标的」
├── 汇总     大数字（US$413.8k，标「非市值」）
│            ＋ 核对行：71 张 = 52 张计入 + 17 观察 + 2 期权
│            ＋ 三行切分胶囊：按策略 / 按地区 / 按主题，每行右侧都标同一个 Σ
├── 期权条   2 张 · 不计入，逐张列 代码 + 备注原文（「Sell put 240」）
├── 矩阵     三段 × 主题列 × 地区行（P2，见 §7.2）
├── 清单     所有卡片的表格视图（P1 先做这个）
└── 页脚     口径说明
```

汇总区那三行「按策略 / 按地区 / 按主题」右侧都写同一个 `Σ`，是刻意的：
它把「同一总额的不同视角、不可相加」这件事**做成了版式**，而不是只写在注释里。

核心仓视图同构，但汇总换成「基金 → 资产」两层：大数字（¥530万）+ 按国家 / 风格 / 资产名三切分
＋ 基金卡列表（每张卡里是资产行）。

### 2.2 交付优先级（**按此顺序，不要一次全做完**）

| 级别 | 内容 | 通过标准 |
|---|---|---|
| **P0** | 数据解析、卫星/核心/总仓三个汇总、总仓四个区块、体检七读数与轨道 | §9.1 的**每一个**数字都对上 |
| **P1** | 核心仓与卫星仓的**清单**视图、增删改、localStorage 草稿 + 写回接口 | §9.3 前四项 |
| **P2** | 卫星仓矩阵布局、饼图与矩形树图、导入导出、密度切换 | 与 §6 的视觉规格一致 |

P2 里任何一项做不动，都可以先用条形图或表格代替，**但 P0 一个数字都不能差**。
先交一个「只有总仓视图、数字全对」的版本，比交一个「四个视图都像样、账算错了」的版本有用得多。

## 4. 计算口径（**这一节是全文最重要的部分**）

写错任何一条，页面都会给出「看起来对、其实假」的数字。下面每条都写了**为什么**。

### 4.1 金额解析：只有一种写法算数

```
合法：^\d+(\.\d{1,5})?k$     大小写不敏感
      "9.5k" → 9500 × 100 = 950000 分
      "1k"   → 1000 × 100 = 100000 分
非法（返回 null，绝不返回 0）：
      ""（空）  "Sell put 240"  "2.7k–5"（区间）  "115"（无 k）  "约 3k"
```

- `k` **固定按 1000 计**，不做 `1.5K = 1024` 之类的解释。
- 金额内部一律存**整数分**（1 分 = 0.01 元 / 0.01 美元）。
- **不可计算必须返回 null，不能当 0**：「不知道多少」和「零」是两件事，
  把 null 当 0 会让合计悄悄变小，而页面看不出少了什么。
- 备注里出现 `put` / `call` **不会**自动改状态——状态是人选的，程序不猜。

### 4.2 为什么用「分」而不是浮点

`0.1 + 0.2 = 0.30000000000000004`。在十个分类、三十行、三种切法里各加一遍，
误差会显形到小数第二位，而页面上所有百分比都保留一位小数——
读者会看到「加起来不等于 100%」。整数分累加没有这个问题。

### 4.3 汇率：固定 7.00，永不取实时价

```
1 美元 = 7.00 人民币（常量，不是配置项，不是接口）
总仓 = 核心仓（已是人民币）+ 卫星仓（美元）× 7
```

两条理由必须写进实现注释：

1. **跨月可比**：汇率一动，同样的持仓会给出不同的历史合计，月度对比立刻失效。
2. **精确无舍入**：1 美分 = 0.07 元 = **7 分**。7 是整数，所以「美分 × 7 = 人民币分」
   是精确整数运算，一次舍入都不需要。这就是选 7 而不是 7.13 的附带好处。

代价必须诚实呈现：7.00 是**记账汇率**，不是今天能换回的价。
所以体检区要同时给即期汇率对照（见 §5.4），但**即期只用于对照，不参与任何合计**。

### 4.4 卫星仓汇总

对每张卡片按顺序判断：

```
status === "option"  → 计入期权清单，不进合计
status === "watch"   → 计入观察计数，不进合计
status 不在 (held, add) → 计入「无法归类」，不进合计
columnId 为空        → 计入「未归类」金额，不进合计，也不进三种切分
amount 解析为 null   → 计入「备注不可计算」，不进合计
否则                 → 计入：total += cents
                        g[groupId] += cents
                        r[regionId] += cents
                        c[columnId] += cents
                        cell[columnId+regionId] += cents
```

**未归类为什么连地区都不算**：三种切分是「同一总额的不同切法」，这是一条不变量
（§4.7）。如果地区算它、主题不算它，三个 Σ 就不再相等，读者会以为数据错了。
所以宁可整张卡都不计入，并在汇总区明写「另有 N 张未归类卡片（¥X）不计入」。

### 4.5 核心仓摊分（最容易写错的一步）

基金金额按资产权重切到资产层，**再**按国家 / 风格 / 资产名聚合。顺序不能反。

```
权重处理三种情况：
  全部留空       → 等分（每项权重 1），并在 UI 标注「等分」
  部分留空       → 已填的按原值，未填的平分「100 − 已填之和」
  全部填写       → 直接用（不要求凑满 100，按总和归一化）
  已填之和 ≤ 0   → 退回等分
```

切分算法（**必须保证 Σ 精确等于基金金额**）：

```
逐项： v_i = floor(基金金额 × w_i / Σw)
余数： 基金金额 − Σv_i → 补到 v 最大的那一项
```

用 Python/JS 的 `Math.floor` 都能实现，**不要**用四舍五入（会超发）。

当前数据的摊分校验（文档末尾也会再列一次，作为验收项）：

| 基金 | 金额 | 资产 | 摊分后 |
|---|---|---|---|
| 黑翼多策略 | 100 万 | 4 项（30/30/30/10） | 30 / 30 / 30 / 10 万 |
| 量派CTA | 100 万 | 1 项（100） | 100 万 |
| 金和全天候 | 120 万 | 5 项（25/25/20/20/10） | 30 / 30 / 24 / 24 / 12 万 |
| 钧富纳指100 | 110 万 | 1 项（100） | 110 万 |
| 优美利低波金牛 | 100 万 | 4 项（35/35/20/10） | 35 / 35 / 20 / 10 万 |
| **合计** | **530 万** | **15 项** | **530 万（一分不差）** |

### 4.6 总仓合并：三个维度，各自相加

```
国家   ← 卫星仓 regionId  + 核心仓 asset.regionId
风格   ← 卫星仓 groupId   + 核心仓 asset.style      （两边是同一组 进攻/均衡/防御）
资产类别 ← 卫星仓整仓记作「股票」 + 核心仓 asset.name
```

两条规则：

1. **资产类别合并**：核心仓资产名里只要含「股票」两个字，一律并入「股票」一项。
   「股票-中证A500」「股票-沪深300」「股票-标普500」「股票-纳斯达克100」
   「股票-中证红利」→ 全部并成「股票」。当前应合并 5 项。
   理由：「股票多头」「股票中性」「股票指增」是同一类资产的不同做法，拆开列看不出总量。
   **卫星仓全是个股，整仓按一类「股票」计**，不拿主题去冒充资产类别。
2. **排序**：国家与资产类别按金额降序；**风格按定义顺序**
   `进攻 → 均衡 → 防御`，不按金额。按金额排会让同一页里两个视图顺序不一致，
   读者每次都要重新找。

### 4.7 三条不可违反的不变量

1. **三种切分的 Σ 必须相等**，且等于总仓。它们不可相加。
2. **同一次刷新里，任何一块的合计 = 各明细之和**，不留零头。
3. **不可计算 ≠ 0**。任何地方都不许把 null 当 0 加进去。

实现完后请自查：把三个 Σ 打印出来比对，不相等就是有卡片被算进了某些维度却没算进另一些。

### 4.8 地区别名（跨仓合并时必踩）

卫星仓用 `asia` / `europe`，核心仓用 `jp` / `eu` / `hk`，同一块地方两个 id。
体检里必须归一，否则会出现「日本 3%」和「日韩台 11%」并排，读者以为漏了一块。

```
china → cn    hk → cn    us → us
asia  → asia  jp → asia  europe → eu  eu → eu  other → other
```

## 5. 持仓体检（本页的核心模块）

### 5.1 结构：左边是写的，右边是算的

```
┌──────────────────────────┬─────────────────────────┐
│ 当前情势                  │ 读 数 · 现状对目标       │
│  （一段标签 + 一段正文）   │  中国（含港）  33.6%  ●  │
│ 结构判断                  │  进攻         44.8%  ●  │
│  （一段标签 + 一段正文）   │  均衡         12.5%  ◐欠5.5│
│ ┌──────────────────────┐ │  防御         42.7%  ●  │
│ │ 中国这块不用减：…     │ │  真防守        33.9%  ●  │
│ └──────────────────────┘ │  AI/半导体因子  32.5% ◐超7.5│
├──────────────────────────┼─────────────────────────┤
│ 哪 里 有 问 题（四条）    │ 如果只动三处（三条动作）  │
├────────────────────────────────────────────────────┤
│ 会让它作废 / 另外盯住 / 口径 / 该重写了              │
└────────────────────────────────────────────────────┘
```

**左边全部来自 `review.json`，程序一个字都不生成。**
这不是「做不到自动生成」，是产品红线：数据每天动、读数实时变、**正文不动**。
一个会自动改口的结论——跌了说早就提示风险、涨了说结构健康——那不叫判断。
两者并排，就是为了让「说的」和「量的」当场对得上；对不上，就是判断该重写了。

### 5.2 七个读数：定义必须精确到能复核

| key | 名称 | 分母 | 定义 |
|---|---|---|---|
| `region.cn` | 中国（含港） | 总仓 | `(china + hk) / 总仓` |
| `style.attack` | 进攻 | 总仓 | 进攻风格金额 / 总仓 |
| `style.balance` | 均衡 | 总仓 | 均衡风格金额 / 总仓 |
| `style.defense` | 防御 | 总仓 | 防御风格金额 / 总仓 |
| `band.real_def` | 真防守 | 总仓 | 见下① |
| `factor.ai` | AI / 半导体因子 | 总仓 | 见下② |
| `conc.top5` | 前五集中度 | **卫星仓** | 卫星仓金额最大的 5 项之和 / 卫星仓合计 |

**① 真防守 = 与股票不相关的部分，不是「防御」这一档**

```
核心仓：资产名匹配 /国债|黄金|中性|套利|CTA/ 的金额
卫星仓：标的 name 含「黄金」的金额（它挂在「贵金属」主题下，但性质是商品）
分母：总仓
```

**红利与可转债不算**——它们是低 beta 股票，股灾里照样跌，只是跌得少。
把它们算成防守，会让「防御」这一档显得比实际扎实。

**注意：「防御」与「真防守」不是同一口径的加减关系，不要用前者减后者推任何东西。**

当前 42.71% 与 33.89% 差 8.82pp，而这个差**不等于**红利+可转债（那是 9.15pp）。
原因是两个方向相反的错误在互相抵消：

| 项 | 金额 | 在「防御」里 | 在「真防守」里 |
|---|---|---|---|
| 核心仓 红利 + 可转债 | 75 万 | ✅ 算 | ❌ 不算 |
| 卫星仓 金融/地产/能源/必选/医疗/公用/综合商事/军工 | 80 万 | ✅ 算 | ❌ 不算（都是股票） |
| 核心仓 商品时序 CTA + 黄金（挂在「进攻」策略下） | 66 万 | ❌ 不算 | ✅ 算 |
| 卫星仓 黄金（挂在「均衡」的贵金属主题下） | 17 万 | ❌ 不算 | ✅ 算 |

两个数字各自按定义算，各自解释自己那件事。**碰巧接近不等于口径相同**，
把它们并排放是为了让人看见「防御做得扎实，但扎实的部分与股票不相关」，
不是为了相减。

**② AI / 半导体因子 = 同一条产业链，跨地区也算一处**

```
核心仓：资产名含「纳斯达克」→ 全额
        否则含「标普500」   → × 0.33（标普里科技约三分之一）
卫星仓：所属主题列名以「AI」开头 → 全额
分母：总仓
```

为什么纳指按全额、标普按三分之一：这是**启发式，不是精算**。
持有纳指 100 等于持有它的权重结构，而它的波动几乎由大型科技与 AI 硬件驱动；
标普 500 里科技权重约三分之一。文档里要写清这是估算，不要包装成精确值。

**这个指标存在的理由**：地区分散 ≠ 因子分散。美国 32.5%、日韩台 11.3% 看着是两块，
但三星、SK 海力士、台积电、日本半导体 ETF、DRAM、博通、英伟达、Coherent、阿斯麦
是同一条 AI 硬件链。地区标签贴的是「在哪里买」，风险来自「买的是什么」。

### 5.3 轨道与状态

每个读数画一条轨道，0–100% 映射到轨道宽度：

```
浅绿带  = 目标区间 [lo, hi]，left = lo%，width = max(hi − lo, 1)%
赭色刻线 = 当前值，left = 当前值%，宽 2px，高 14px
轨道底  = 1px 浅灰横线
```

状态文字（右侧，定宽）：

```
v > hi + 1e-9  →  超 X.Xpp   （赭底赭字）
v < lo − 1e-9  →  欠 X.Xpp   （蓝底蓝字）
否则            →  区间内     （浅绿底绿字）
```

容差用 `1e-9` 而不是 0.1：区间边界本身是合法值，落在边界上应显示「区间内」。

**表头必须写一句口径**：「带＝目标区间，刻线＝现在；未注明的均为占总仓」。
七条里六条是总仓，逐条标「· 总仓」等于每行重复一次默认值，是噪音。
只在 `scope !== "总仓"` 时标注（例如「前五集中度 · 占卫星仓」）。

### 5.4 页脚三块

**读数区底部（`src`）** —— 让「这个数是怎么来的」成立：

```
总仓 ¥819.7万（核心 64.7% / 卫星 35.3%）· 卫星 52 项、等效 36 只 · 单只均 0.68% 总仓
卫星仓按 7.00 折 ¥289.7万；按即期 6.671 折 ¥276.1万，记账口径比即期口径高 ¥13.6万（1.7% 总仓）。
```

- **等效只数** = `1 / Σ(单项占比²)`，即 HHI 的倒数。当前 36.5。
- **即期汇率**：若行情数据里有 `fxUSDCNY` 就用它，没有就只给记账口径并写明「这次没取到」。
  即期**只出现在这一行**，不进任何合计。

**口径说明**（一句话，写死）：

> 真防守＝国债＋黄金＋股指中性＋期权套利＋CTA；红利与可转债是低 beta 股票，不算。
> AI / 半导体因子＝卫星 AI 主题＋纳指 100＋标普 500×⅓。
> 前五占比的分母是卫星仓，不是总仓。

**过期提示**（两种都要报，红色行）：

| 条件 | 文案 |
|---|---|
| `今天 − as_of > 30 天` | 判断写于 N 天前，宏观的时效比仓位短，该重写了 |
| `\|当前总仓 − anchor.total_wan\| / anchor.total_wan > 10%` | 总仓相对写判断时（¥819万）变了 +X.X%，前提已经不同 |

第二种更重要：这段话是照着某个仓位形状说的。形状变了，不是数字过期，是**前提过期**。

### 5.5 review.json 缺失时的降级

不要显示空白，也不要编造。显示：

> 这个位置是对整张表的判断，不是数字总结。判断存在 `review.json`，现在没读到。
> 读数（地区 / 风格 / 因子 / 集中度）仍然会自动算，缺的只是「怎么读这张表」那几句话。

**右侧七个读数照常渲染**——它们不依赖 review.json。
只有 `targets` 来自 review.json，缺了就只显示数值、不画轨道、不给状态。

```
│ ¥819.7万            │ ● 核心仓 ¥530.0万  5 只基金 · 15 项资产   │
│ = 核心仓 ¥530.0万    │ ● 卫星仓 ¥289.7万  52 张 · US$413.8k × 7.00│
│   + 卫星仓 US$413.8k × 7.00 │                                  │
└────────────────────┴──────────────────────────────────────────┘
```

- 左栏固定 280px，大数字 32px / 字重 600 / 字距 −1.2px，前面带小号 `¥`。
- 右侧构成条高 30px，两段宽度 = 占比；**占比为 0 的段显示灰底「零」**，
  不给它撑一条假色块——「没有」和「很小」是两件事。
- 合计为 0 时大数字显示 `—`，字号降到 22px，并写「两个仓都还没有可计算的金额」。

### 6.3 区块 ③：两仓构成

一行一仓，四列 `88px / 46px / 1fr / auto`：

```
核心仓         CNY   ████████████████████  5 只基金 · ¥530.0万 × 1.00 = ¥530.0万
core.json
卫星仓         USD   ██████████            52 张 · US$413.8k × 7.00 = ¥289.7万
matrix.json
──────────────────────────────────────────────────────────────
总仓           CNY                          人民币合计 ¥819.7万
```

中间那句 `几只 · 原币 × 汇率 = 折人民币` 是刻意的：让「这个数是怎么来的」
在同一条视线上成立，不用横向追六列。

表格下方的小字（每条只在有数据时出现）：

- 折算率是常量：`PM_FX = 7.00`（前端）与 `portfolio.FX`（后端），**两处必须一致**。
- 核心仓另有 N 只基金金额不是「数字 k」，不计入合计。
- 卫星仓有 N 张卡片备注不是完整的「数字 k」，**既不计入也不当作 0**。
- 卫星仓有 N 张未归类卡片（¥X）不计入。
- 卫星仓观察中 N 张、期权 N 张，按口径不进普通合计。

### 6.4 区块 ④：合并切分

三列等宽（`grid-template-columns: repeat(3, 1fr)`，间距 14px），
每列一个盒子，行格式 `62px / 1fr / 92px`：

```
按国家 · 两仓合并          按风格 · 两仓合并         按资产类别 · 两仓合并
中国       ████████ 33.6%   进攻   ██████████ 44.8%   股票        ████████ 62.7%
美国       ███████ 32.5%    均衡   ███ 12.5%          商品截面CTA  ██ 12.2%
其他       █████ 20.3%      防御   █████████ 42.7%     商品时序CTA  █ 6.6%
日韩台印   ██ 11.3%                                   可转债       █ 5.5%
欧洲       ▌ 2.4%                                     国债         ▌ 4.9%
                                                      股指中性策略  ▌ 4.3%
                                                      期权套利策略  ▌ 2.4%
                                                      黄金         ▏1.5%
```

- 条形最小宽度 0.8%，否则 2.4% 那种会看不见。
- 每列底部一句来源说明：
  - 国家：核心仓按资产的「国家」，卫星仓按卡片的「地区」。
  - 风格：核心仓按资产的「风格」，卫星仓按「策略」——两边是同一组 进攻/均衡/防御。
  - 资产类别：核心仓按资产名称逐项列；卫星仓全是个股，整仓记为「股票」一类。
    若发生合并，追加「名称含「股票」的 5 项（…）已并入股票一项统计」。
- 区块标题旁必须写：**同一总额的三种切法，彼此不可相加**。

### 6.5 响应式

| 断点 | 处理 |
|---|---|
| `≤ 980px` | 体检区改单列（say → read → iss → mov → foot）；读数区去掉左边框，改上边框 |
| `≤ 620px` | 读数行名称列 120px → 92px，隐藏「· 占卫星仓」这类 scope 标注（否则轨道被挤成短线） |

620px 下若轨道仍短于约 60px，说明名称列还是太宽——**轨道被压没，等于区间带白画了**。

## 7. 交互与持久化

### 7.1 视图切换

- 分段控件三个按钮；切换时：换页头文案 + 显示对应容器 + 关闭所有浮层 + 重绘。
- 总仓视图**隐藏**「导出 / 导入」按钮（那两个按钮属于具体某个仓）。
- 总仓视图**只读**，不提供任何编辑入口；修改要去对应的仓。

### 7.2 卫星仓（可编辑）

- **矩阵布局**：三段上下堆叠（进攻 / 均衡 / 防御），每段自带标题条 + 自己的列头 + 自己的地区行。
  段内主题从第 2 列起靠左铺开，**不居中、不跨段共列**。
  三段用同一套列宽（按最大段列数算轨道），于是第 N 个主题列在全页落在同一条竖线上。
- 点卡片 → 抽屉编辑（代码 / 名称 / 金额备注 / 状态 / 主题 / 地区）。
- 双击空格子 → 在该主题 × 地区新增卡片。
- 点主题名 → 改名 / 换策略 / 删除。**删掉主题后卡片进「未归类」，不计入合计**。
- 搜索框匹配 symbol + name + amount，不匹配的卡片变淡而不移除（保持位置感）。
- 密度切换：紧凑 / 舒适。
- 期权卡片用蓝色虚线边框区分，永不并入普通仓位金额。

### 7.3 核心仓（可编辑）

- 基金 = 一张卡（名称 + 金额 + 备注）；资产 = 卡里的一行（名称 + 国家 + 风格 + 权重）。
- 点基金名改名称与金额；点资产行改国家 / 风格 / 权重。
- 权重可留空表示等分，UI 上要标出来（不能让用户以为是真实比例）。
- 新增基金时默认给一行资产，否则金额摊不出去（校验会拒绝没有资产的基金）。

### 7.4 持久化（三层，缺一不可）

```
① 本地草稿   localStorage，键按仓分开（卫星 pmx_map_v1 / 核心 pmx_core_v2）
             防误触：每次改动即时落本地，刷新不丢
② 写回文件   POST /api/portfolio（卫星） / POST /api/core（核心）
             服务端：校验 → 备份 → 写临时文件 → 原子替换
③ 冲突处理   比较「本地草稿时间」与「源文件 mtime」
             不一致 → 顶部黄条，让用户选「用本机的 / 用文件的」，不自动覆盖
```

- **备份**：每次写盘前把现有文件复制到 `backups/<前缀>-YYYYmmdd-HHMMSS.json`，
  保留最近 30 份（一份约 13 KB，够回溯一个月）。
- **写盘必须指定 `newline="\n"`**（Windows 会默认把 `\n` 翻成 `\r\n`，
  一次保存就把整篇换行改掉，git diff 变成几千行全红）。
- 冲突状态要记在**仓**上而不是当前视图上：启动时视图是总仓，
  那会儿若把提示吞掉，等用户切到该仓时提示已经没了，旧草稿就会一直静静压着源文件。
- 写盘失败要有明确反馈（红条 + 原因），不能只把按钮恢复原状。

### 7.4.1 接口契约

只读源文件（页面装载时用来判断「源文件有没有比本机草稿更新」）：

```
GET /api/portfolio      → 卫星仓
GET /api/core           → 核心仓

200 {
  ok: bool,             // 结构校验是否通过
  matrix: {…},          // 整份 book（就是 §3 的 JSON 对象）
  book: "sat" | "core",
  currency: "USD" | "CNY",
  as_of: "2026-11-15 05:00",   // 源文件 mtime
  error: null | "…",    // 校验失败的前 3 条
  warn: ["…"]           // 提示，不阻断
}
```

写回整份 book（**不是差量**，避免并发下的半份状态）：

```
POST /api/portfolio     body: {"matrix": {…整份卫星仓…}}
POST /api/core          body: {"matrix": {…整份核心仓…}}

200 { ok: true, sum: {…服务端重算的 summary…}, book, path, bytes, backup, as_of }
400 { ok: false, error: "数据校验失败：…" }   // 校验不过一律拒写
500 { ok: false, error: "…" }                 // 写盘异常
```

- 服务端写盘流程固定四步：**校验 → 备份 → 写临时文件 → 原子替换**（`os.replace`）。
- 校验不过**宁可报错也不落半份数据**；备份写坏了能捞回来。
- 响应里带 `sum`（服务端重算的汇总），前端可以拿它跟自己的数比一次，
  对不上说明前后端口径有分叉——这是最有价值的一次自检。


### 7.5 导入 / 导出

导出：把当前仓的 JSON 下载或复制到剪贴板。
导入：粘贴 JSON → 结构校验（见 §8.7）→ 通过才落盘。校验失败逐条列出原因，不做部分导入。

## 8. 边界与降级（**逐条都要实现**）

1. **合计为 0**：显示 `—` 而不是 `0`；构成条不画假色块；体检读数全为 0 且状态显示「—」。
2. **一个仓文件缺失**：另一个仓照常显示；构成表对应行显示「文件缺失 / 0 · 没有可计算的数据」；
   总仓仍是另一仓的金额，但页脚注明「只有核心仓有数据」。
3. **备注不可计算**：卡片保留、状态保留、金额显示原文；**不计入且不当 0**；汇总栏计数提示。
4. **未归类卡片**：照常显示在矩阵里（主题列已消失），不进任何合计与切分；汇总区给出张数与金额。
5. **权重全空**：等分，并在该基金卡上标注「等分」。
6. **权重合计 ≠ 100**：按比例归一化，**不报错**，但给一条提示（warnings 级别）。
7. **结构校验失败**（id 重复 / 资产缺国家 / 风格不在三档内 / 基金没有资产）：
   **阻断写盘**，逐条列出。程序不替用户修数据——一旦「顺手修正」，
   页面显示的和用户以为的就会悄悄分叉。
8. **review.json 缺失或字段不全**：见 §5.5；`targets` 缺某一条 → 该行不渲染，其余照常。
9. **旧版 core.json（schemaVersion 1，矩阵结构）**：读入时就地迁移成「基金 → 资产」，
   **不写盘**（写盘要等用户真的改了一次，否则一打开页面就动文件太唐突）。
   迁移规则：一张旧卡片 = 一只单资产基金，资产名取卡片名，
   风格取它原来所在主题所属策略，国家沿用地区 id（`global`/`asia` → `other`）。
10. **即期汇率取不到**：只给记账口径，并写明「即期汇率这次没取到」。
11. **判断超过 30 天 / 总仓漂移 > 10%**：见 §5.4。
12. **窄屏**：见 §6.5。表格类区域允许横向滚动，页面本身不允许横向溢出。

## 10. 不做什么（红线）

1. **不接实时行情、不算市值/成本/盈亏**。这是记账页，加了行情就变成另一个产品。
2. **不自动生成判断文字**。`regime` / `verdict` / `issues` / `moves` 必须由人写。
3. **不给买卖建议**。`moves` 只允许「方向 + 比例区间 + 触发条件」，
   不点具体标的、不给目标价、不写「建议买入/卖出」。
4. **不把三种切法相加**，不把不可计算金额当 0。
5. **不改用户数据**。校验失败就阻断，不「智能修正」。
6. **不做登录、不做多用户、不做云同步**。一个人的一台电脑上的一个文件。
