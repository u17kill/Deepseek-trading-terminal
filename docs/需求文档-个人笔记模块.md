# 需求文档 · 「个人笔记」模块（单页）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0（需求版） |
| 对应实现 | 交易终端「个人笔记」页（`pane13` / `#notes`），v1.36.0 上线；截至 v1.52.2 无功能改动（仅导航层调整） |
| 数据快照 | 2026-11-26：3 条泳道 / 3 张卡片 / 296 字（`data/notes/notes.json`，1,605 字节） |
| 文档范围 | 功能需求、数据契约、写入安全、验收标准、已知缺口；不含配色细节与实现代码 |
| 读者 | 验收方、后续接手实现的人，以及需要判断「这条需求该不该做」的产品方 |

**这份文档与其它模块文档的差别。** 其它十四页描述的都是**市场**：现在什么位置、别人怎么判断、
什么时候有事、我账上有什么。这一页只描述**我自己怎么想**。它不产生数字、不参与判断、
也没有数据源——它唯一的技术难点是**不能丢字**。所以本文的重心不在排版，在
「一份人写的文件，怎么在被频繁改写的同时保持可恢复」（§5、§6、§8）。

**两种读法。**

- 要验收：直接看 §10 的 34 条，每条都给了判定方法，不依赖读代码。
- 要改这一页：先读 §2（不做什么）、§5（数据流）、§6（不变式），再看 §4。

## 0. 一页速览

**一句话定位**：一条泳道就是一个主题，一张卡片就是一条想法；写下去自动落盘，
读回来一字不改。

**六条必须守住的**（违反任意一条，这一页就失去存在意义）：

| # | 约束 | 违反后的具体后果 |
|---|---|---|
| 1 | `data/notes/notes.json` 是唯一权威副本 | 数据押在「用户不清浏览器缓存」上 |
| 2 | 页面永不改写用户写下的字 | 用户分不清哪句是自己写的，笔记失去「当时怎么想」的价值 |
| 3 | 写回顺序固定：校验 → 备份 → 原子替换 | 半份文件落盘，或写坏后没有可回滚的点 |
| 4 | `id` 全局唯一，重复即拒写 | 页面出现两张一样的卡片，删一张实际删的是另一张 |
| 5 | 自动保存必须配一个手动出口 | 「草稿比文件新」的自动策略会把用户手工恢复的文件盖回去 |
| 6 | 正文纯文本，不渲染 Markdown、不解析 HTML | 解析器要与转义、链接注入、粘贴富文本缠斗；复制出去还带标记 |

**三条现状缺口**（详见 §12）：多标签页并发无版本号（Q1）、连续编辑可能两个写回同时在飞（Q2）、
新卡片的创建/修改时间按 UTC 显示，比本地时间慢 8 小时（Q3）。这三条都不影响「不丢字」的主路径，
但都属于「安静地不对」，建议在下一版一并处理。

## 1. 产品定位

### 1.1 这一页回答什么

> **我此刻想到的这件事，三个月后还能不能原样找回来？**

它不回答「这值不值得买」「别人怎么看」「数据是多少」。整个终端里只有这一页的内容
**不是从任何地方取来的**——没有接口、没有抓取、没有口径，只有人一个字一个字写下的东西。

### 1.2 与其余十四页的分工

| 页 | 回答的问题 | 内容从哪来 |
|---|---|---|
| 市场总览 / 温度六页 / 资产方向 | 市场现在什么状态 | 行情接口 + 计算 |
| 市场新闻 / 专家观点 / 机构研报 / 财经日历 | 别人说了什么、什么时候有事 | 检索与策展 |
| 大佬持仓 / 当前持仓 | 账上有什么 | 13F + 手工记账 |
| **个人笔记（本模块）** | **我自己怎么想** | **只有我自己** |

这一页刻意放在菜单最后一组（「工具」）。它不打断「市场 → 观点 → 持仓」的阅读动线，
也不该被当成分析结论的存放处——结论写进「今日市场」的判断区，笔记只放**过程**：
半成品的假设、待查的口径、某次判断为什么错了。

### 1.3 为什么是「泳道 + 卡片」而不是一张清单

笔记的内容是发散的，用途是收敛的：同一件事会从「想法」走到「待研究」再走到「已处理」，
中间还要回头补材料。平铺的清单每次都得重读一遍，才知道某条走到哪一步——这正是看板擅长的事。
列就是泳道，列名由用户自己定（初始化给的「随手记 / 待处理 / 已归档」只是一种切法，不是规定）。

**反向的代价必须写清**：看板不适合长文。一张卡片写两千字，它在列里只显示两行半，
真要读还得点开抽屉——那时列的价值只剩「归到哪一类」。所以这一页的定位是
**短笔记与线索的收纳**，长文写作不属于它（见 §2.2）。

### 1.4 一句话概括

**这一页不是知识库，是「把想到的话落在能原样找回来的地方」。**
判断它做得好不好，只看一件事：半年后回来，那段没写完的推理还在不在、还是不是当时那个语气。

## 2. 范围

### 2.1 本模块包含

1. 单个看板：横向排列的泳道（列）× 列内纵向堆叠的卡片。
2. 泳道的增、删、改名、左右换序、拖动换序。
3. 卡片的增、删、打开编辑、跨泳道移动、列内换序。
4. 右侧抽屉：标题、正文、所属泳道、创建/修改时间、正文字数。
5. 顶部工具条：泳道数、卡片数、正文字数、匹配数、搜索框、「重读文件」、写回状态徽标。
6. 搜索：标题与正文的子串匹配（忽略大小写），命中高亮。
7. 自动保存：写浏览器草稿 + 防抖写回源文件；失败时降级并明示。
8. 导出当前看板为 JSON（备份 / 迁移）。
9. 写入安全：分级校验、写前备份、原子替换、服务端串行化。
10. 构建期注入与校验失败即中断构建。

### 2.2 本模块不包含（逐条给理由）

| 不做 | 理由 |
|---|---|
| Markdown / 富文本渲染 | 渲染要与 HTML 转义、链接注入、粘贴富文本搏斗；渲染后复制出去带一堆标记。要排版就导出或复制走（红线：页面永不改写原文） |
| 附件、图片、文件上传 | 一个 JSON 存不下二进制；一旦引入文件目录，备份与原子替换的模型全部要重做。真需要放图，用别的工具 |
| 多板（board） | 只有一组泳道。想分主题就再开一条泳道；多板会让「导出」「备份」「草稿键」三处的语义都要重新定义 |
| 版本历史界面 / 「回到上一版」 | `backups/` 与 git 已经是版本记录。页面上做历史，要处理 diff、冲突、指针失效，收益低于成本（Q6） |
| 导入 JSON | 与导出不对称是有意的：导入要处理 id 冲突、合并策略、覆盖确认，任一处做错就是丢字。迁移用文件替换 + 「重读文件」 |
| 标签、双链、反向引用 | 这是笔记软件的竞争维度，不是看板的价值。标签一旦引入，「列」的分类作用就被削弱 |
| 提醒、待办完成状态、截止日期 | 那会把这一页变成任务管理器；「已处理」是一条泳道，不是一个勾选框 |
| 多人协作 / 云同步 | 单机单用户。没有账号体系，也没有冲突合并 |
| 自动摘要 / 自动补全 / 自动润色 | 红线。见 §8.1 |
| 全文检索索引 | 现有规模（3 卡 / 296 字）下，前端子串匹配即时返回；提前建索引是无收益复杂度 |

### 2.3 扩展的边界

如果要扩，优先扩**「不丢字的保障」**，不要优先扩**「记笔记的花样」**。
§12 的 Q1~Q3 都属于前者；多板、标签、Markdown 属于后者，价值低一档。

## 3. 页面结构

### 3.1 入口、路由与菜单

| 项 | 值 |
|---|---|
| 第一层分组 | 「工具」（`data-g="note"`） |
| 第二层页签 | 「个人笔记」（`data-p="13"`、`data-g="note"`） |
| hash | `#notes` |
| pane | `pane13` |
| 默认落点 | 不是默认页。无法识别的 hash 落 `#market`（市场总览） |

**两处必须同时改。** 加页签要改导航按钮与 `PANE_HASH` 两处，`HASH_PANE` 由同一张映射表反推，
不维护第二份清单。历史上漏改页序表已经有过一次（v1.48.0 页头导航文案），所以 v1.49.0 起
组与成员的对应关系只写在 DOM 里。

`data-g` 在本组的取值是 `note`（单数），hash 才是 `#notes`（复数）。写混了不会报错，
只会让页签落在上一组的高亮里。

### 3.2 四段骨架

| 段 | DOM | 内容 | 高度行为 |
|---|---|---|---|
| ① 页头 | `.nthead` | 标题「个人笔记」+ 一段用法说明（含写回路径与备份说明）+ 右侧「导出 JSON」 | 固定 |
| ② 工具条 | `.ntbar` | 左：泳道数 / 卡片数 / 正文字数 / 匹配数；右：搜索框、「重读文件」、写回徽标 | 固定，窄屏换行 |
| ③ 看板 | `.ntboard` | 泳道横排，超出容器横向滚动；末尾是「+ 新建泳道」 | 泳道最高 `calc(100vh - 300px)`，列内纵向滚动 |
| ④ 抽屉 | `.ntmask` + `.ntdr` | 从右侧滑出，宽 520px（`max-width: 96vw`），遮罩 22% 黑 | 固定覆盖，正文区自适应 |

抽屉与看板**不是同一层**：抽屉打开时看板仍在背后可见（遮罩变暗），关掉即回到原位，
不重绘、不丢滚动位置。

### 3.3 尺寸与视觉硬要求

| 项 | 值 | 为什么是这个值 |
|---|---|---|
| 泳道宽 | 302px（`flex: 0 0 302px`） | 容器 1180px、内容宽 1132px：正好放下 3 条（934px），第 4 条露出约 2/3——**露出的那一条就是「还能横滑」的提示**，比加箭头更省地方 |
| 新建泳道按钮宽 | 216px | 比泳道窄，视觉上明确「这不是一列内容」 |
| 抽屉宽 | 520px，`max-width: 96vw` | 520px 下 13px 正文每行约 40 字，接近舒适阅读宽度 |
| 正文输入框最小高 | 260px | 保证不滚动就能看见一段完整的推理 |
| 卡片正文预览 | 2 行、最多取 140 字 | 超过两行的卡片在列里已经读不出信息，点开才是正路 |
| 卡片脚注 | 修改时间（`MM-DD HH:MM`）+ 正文字数 | 让人一眼看出「这条多久没动了」 |
| 搜索命中高亮 | 底色 `#fff3c4` | 与判断区的暖黄说明块同一族色，不引入新语义 |
| 涨跌色 | **不使用** | 这一页没有行情，红色绿色在这里只表示「删除」等操作，不表示涨跌 |

视觉沿用全站的纸感底色（看板底 `#fbfaf7`、卡片纯白）。**不使用涨跌色**是硬要求：
一旦卡片标题用了绿/红，读者会误以为它在表达方向。

### 3.4 响应式与溢出（现状）

- 没有为 `pane13` 写专用断点。窄屏下泳道仍是 302px，靠 `.ntboard` 横向滚动，
  一次只看到一到两条——可用，但不舒适。
- 抽屉 `max-width: 96vw`，手机宽度下几乎全屏；正文框 `min-height: 260px` 依旧生效。
- 工具条 `flex-wrap: wrap`，搜索框固定 150px 宽，窄屏时掉到第二行。
- 横向滚动条高 8px，列内纵向滚动条宽 7px，均为细样式（`scrollbar-width: thin`）。

**这是已知的优先级取舍**：这一页是桌面工具，窄屏只保证「能读能改」，不追求「好用」。
若要做手机端，先解决 §12 的 Q5（卡片不可聚焦）更划算。

### 3.5 空状态与首次进入

| 状态 | 表现 |
|---|---|
| 文件不存在 / 一条泳道都没有 | 看板区居中提示「还没有泳道」+「+ 新建泳道」按钮；计数全是 0 |
| 泳道存在但没有卡片 | 列内提示「还没有卡片，点下面新建」，列底常驻「+ 新建卡片」 |
| 搜索无匹配 | 列内提示「没有匹配的卡片」，列头计数显示 `0/N` |
| 首屏 | 先渲染构建期内嵌数据（断网也有内容），再异步 `GET /api/notes` 换成最新；徽标先按内嵌时间显示「已写入源文件」，悬停提示注明「构建期内嵌数据，正在读取源文件…」 |

## 4. 功能需求

### FR-1 看板渲染与计数

**行为**

1. 按 `columns` 数组顺序自左向右渲染泳道，按 `cards` 数组顺序自上而下渲染卡片。
2. 每个泳道头：⠿ 拖拽柄、列名（点击即改名）、计数、`‹` `›` 换序、`×` 删除。
3. 每张卡片：标题（空则显示灰色「（无标题）」）、正文预览（2 行）、脚注（修改时间 + 字数）。
4. 工具条计数：泳道数、卡片总数、正文总字数、搜索匹配数。

**口径（必须与后端一致）**

- **正文字数 = Σ `body.length`，含空白、换行、标点；不含标题。** 同一口径在 `notes.py`
  的 `stats.chars` 与前端 `ntWords()` 各算一次，两边定义必须一致——两处各算一遍又口径不同，
  是最难发现的一类错。
- 泳道计数在搜索时显示 `匹配/总数`（如 `1/3`）；不搜索时只显示总数。
- 匹配数为 0 时，工具条不显示「匹配 0 张」——「没搜到」与「没数据」是两件事，
  前者应由空态提示承担。**现状是照常显示**，属实现与本节的一处小差，修 Q4 时一并改。

**失败态**：`columns` 不是数组或为空 → 走 §3.5 空状态，不抛异常、不白屏。

### FR-2 泳道管理

| 操作 | 入口 | 规则 |
|---|---|---|
| 新建 | 看板末尾「+ 新建泳道」 | 追加到最右，默认名「新泳道」，新建后立即进入改名态 |
| 改名 | 点击列名 | 就地变输入框；`Enter` 提交、`Esc` 取消；失焦等同提交。空名允许（列头显示「未命名」） |
| 换序 | 列头 `‹` `›` | 与相邻列交换；到边界时按钮保留但不生效（不隐藏，避免列宽跳动） |
| 换序 | 拖动列头 ⠿ | HTML5 DnD，按落点水平中线判断插入位置 |
| 删除 | 列头 `×` | **必须二次确认**，并说明里面有几张卡片；确认后整列连同卡片删除 |

**约束**

- 列名上限 16 字（`COL_TITLE_MAX`）。超长是**提示**不是错误：列头用省略号截断，数据照存。
- 删除泳道不提供撤销。可恢复性依赖 `backups/`（写前备份）与 git（§6.4）。
- 所有改动立即触发保存（FR-6），没有「保存」按钮。

### FR-3 卡片管理

| 操作 | 入口 | 规则 |
|---|---|---|
| 新建 | 列底「+ 新建卡片」 | 追加到该列末尾，创建后**立即打开抽屉**并聚焦标题 |
| 打开 | 点击卡片任意位置 | 右侧抽屉滑出，卡片加选中描边（`.on`） |
| 编辑 | 抽屉内标题框 / 正文框 | 逐字符写回工作副本，就地更新卡片预览（不整体重绘，避免光标被顶掉） |
| 移动 | 拖动卡片到别的列 | 按落点判断插入位置；跨列时给一次 toast「已移到 X」 |
| 移动 | 抽屉内「所属泳道」下拉 | 触屏兜底路径（拖拽在触屏不生效）；移动后卡片追加到目标列末尾 |
| 删除 | 抽屉底部「删除卡片」 | 二次确认，文案带标题；确认后关闭抽屉并重绘 |

**约束**

- 标题上限 60 字（`TITLE_MAX`），超出只是提示（列里只显示一行，本来就会被截断）。
- 标题与正文**都为空**只是提示，不是错误——新建卡片的瞬间就是这个状态，拦住它等于在用户
  刚拿起笔时把笔抢走。
- 卡片脚注显示的是 `updated`（修改时间），不是创建时间；抽屉里两者都给。
- 任何字段修改都刷新 `updated`；只移动位置也算修改（因为「落在哪个泳道」是内容的一部分）。

### FR-4 抽屉（详情编辑）

**字段与顺序（固定，不可调换）**

1. 标题（单行输入，占位「一句话说清这张卡片是什么」）
2. 正文（多行文本域，`flex:1`，最小 260px，可纵向拉伸）
3. 所属泳道（下拉，列出全部泳道，当前值选中）
4. 元信息：`创建 YYYY-MM-DD HH:MM · 修改 YYYY-MM-DD HH:MM`
5. 底栏：左「删除卡片」，右「N 字」+「关闭」

**键盘**

| 键 | 行为 |
|---|---|
| `Esc` | 关闭抽屉（不丢改动，改动已自动保存） |
| `Ctrl/Cmd + Enter` | 关闭抽屉 |
| `Tab` | 在标题 → 正文 → 所属泳道 → 删除 → 关闭之间移动（原生控件，不拦截） |

**约束**

- 抽屉关闭不重绘看板，只移除选中态——保持滚动位置。
- 抽屉打开期间，看板不可拖拽（遮罩拦截），避免「一边编辑一边把卡片拖走」。
- 正文必须是 `white-space: pre-wrap`：换行与缩进原样显示，但不解析任何标记。

### FR-5 搜索

| 项 | 要求 |
|---|---|
| 范围 | 卡片标题 + 正文（不含泳道名、不含时间） |
| 匹配 | 子串，不区分大小写；不做模糊、不做分词、不做正则 |
| 高亮 | 命中的每一处包一层 `.hit`；正文预览先截 140 字再高亮 |
| 计数 | 工具条显示「匹配 N 张」；列头显示 `匹配/总数` |
| 清空 | 输入框内 `×`（仅在有内容时出现）；清空后立即恢复全量 |
| 与拖拽的关系 | 搜索状态下仍可拖拽，但落点按过滤后的可见顺序计算——**这是已知的语义模糊点**：被过滤掉的卡片在数组里的位置不变，拖完再看全量，位置可能与预期差一位 |

**性能**：每次输入即全量重绘。目标规模（200 卡 / 5 万字）下应在 1 帧内完成；
不引入索引、不引入虚拟列表。

### FR-6 自动保存与状态徽标

**保存链路（顺序不可换）**

1. 任何改动 → 立即写 `localStorage`（键 `notes.board.v1`，值 `{savedAt, data:{columns}}`）。
2. 防抖 600ms → `POST /api/notes`，请求体 `{notes:{columns}}`。
3. 服务端校验 → 备份 → 原子写盘 → 返回 `{ok, path, bytes, backup, as_of, stats}`。
4. 前端把徽标置为「已写入源文件 · 时间」，并把 `path / bytes / backup` 写进徽标 `title`。

**七态徽标（文案即需求，不可随意改写）**

| 态 | 文案 | 触发 |
|---|---|---|
| `ok` | 已写入源文件 · `YYYY-MM-DD HH:MM` | 写盘成功，或读盘成功 |
| `draft` | 草稿比文件新 · 正在写回 · 时间 | 进页面时草稿比文件新，已加载草稿 |
| `dirty` | 有改动，准备写回… | 防抖等待中 |
| `saving` | 正在写回源文件… | 请求在飞 |
| `offline` | 未连本地服务 · 改动只在本机 | `file://` 打开，或网络层失败（`TypeError`） |
| `fail` | 写回失败 · 草稿还在本机 | 服务端 4xx/5xx |
| `nostore` | 草稿也没写成 · 只在当前页 | `localStorage` 写入抛错（隐私模式、配额满） |

**硬要求**

- **任何一态都不许静默。** 尤其 `offline` 与 `fail`：必须在工具条留下可见文案，
  并在提示条 `#ntHint` 说明「服务起来后刷新页面会自动写回」或「改动仍在本机草稿里」。
- 写回失败**不清空**草稿，也不阻止继续编辑。
- 服务端返回的 `as_of` 覆盖本地显示时间（时间戳以服务端为准，见 §6.2 不变式 N4）。

### FR-7 重读文件（手动出口）

**为什么必须有**：草稿策略是「谁新听谁的」。如果用户手工改过 JSON（例如从 `backups/` 恢复），
浏览器里那份旧草稿的 `savedAt` 反而比文件「新」，一进页面就会把恢复的内容盖回去。
这不是 bug，是自动策略的必然副作用——**自动策略没有手动推翻路径，就会在某些情况下变成风险**。

**行为**

1. 点击「重读文件」→ 二次确认「本机草稿会被丢弃，源文件一字不改」。
2. 确认 → 删除 `localStorage` 草稿 → `GET /api/notes` → 以文件内容重建工作副本 → 重绘。
3. 失败 → 提示条说明失败原因，徽标 `fail`。

**实现注意（当前与要求的差）**：代码是「先删草稿、再读盘」。若读盘这一步失败，
草稿已经没了——虽然源文件没被改动、内容不一定丢，但「本机比文件新的那份」确实消失了。
要求改成**先读盘成功、再删草稿**；顺序反了，这个出口就从保险变成风险。

### FR-8 导出

| 项 | 要求 |
|---|---|
| 内容 | `{exported: ISO 时间, columns: [...]}`，缩进 1 |
| 文件名 | `notes-YYYY-MM-DD.json` |
| 用途 | 备份、迁移、把内容带到别处 |
| 不做 | 不做导入（§2.2）；导出**不改变**源文件，也不清草稿 |

## 5. 数据流与冲突处理

### 5.1 三层数据，各管一段

| 层 | 位置 | 作用 | 失效时 |
|---|---|---|---|
| 内嵌 | 构建产物里的 `NT`（`/*__NOTES__*/` 注入） | 断网、服务未起动也有内容可读 | 内容停在构建那一刻 |
| 接口 | `GET /api/notes`（每次请求现读磁盘） | 保证不看过期数据 | 工具条徽标转 `offline`，仍可用内嵌数据 |
| 草稿 | `localStorage["notes.board.v1"]` | 毫秒级落盘；写盘失败时不丢字 | 徽标 `nostore`，只剩当前页面 |

**只有源文件是权威副本。** 内嵌是快照、接口是视图、草稿是保险，三者都不能反向定义「正确内容」。

### 5.2 「谁新听谁的」判定

进页面时比较草稿 `savedAt` 与文件 `updated`：

```
草稿存在 且 草稿有 columns 且 时间可解析
且 (文件时间不可解析 或 草稿时间 > 文件时间 + 1500ms)
→ 用草稿，立即写回文件，提示「本机草稿比源文件新（时间），已先加载草稿并写回文件」
否则 → 用文件
```

**1500ms 容差的理由**：文件时间只精确到分钟（`YYYY-MM-DD HH:MM`），草稿时间是毫秒级 ISO。
同一次保存里两边必然有几十毫秒到几秒的差；不设容差，就会在「刚写完、立刻刷新」时
误判成「草稿更新」，触发一次无意义的写回。

**代价**：容差内的真实冲突（用户在两秒内既改了文件又改了页面）会按「文件优先」处理，
此时草稿里的那两秒改动被覆盖。概率极低，且下一次输入即写回——接受。
另一个更窄的窗口：文件时间只到分钟，若上一次成功写盘恰好发生在某一分钟的头 1.5 秒内，
紧接着的草稿可能被判为「不比文件新」而按文件加载——那 1.5 秒里的改动不会被载入，草稿虽还留着，
但页面已按文件重建，再次编辑就会覆盖它。**这是容差方案的真实代价，不是笔误**；
改乐观锁（Q1）时一并消掉。

### 5.3 写回的并发现状

- 服务端用一把进程内锁串行化 `save()`，不会两个请求同时写同一份文件。
- 前端**没有请求序号，也没有版本号**：`ntPushFile` 在保存进行中会把状态从 `saving` 改回
  `dirty`，于是可能出现两个 POST 同时在飞。按到达顺序落盘，理论上后到的旧快照会盖掉新快照。
- 多标签页之间**没有任何检测**：A 标签页与 B 标签页各持一份内存副本，谁后写谁覆盖，
  另一边的改动静默消失。

这两条都不在「主路径」上（单人、单标签页、连续输入），但都属于「安静地丢字」，
列为 Q1 / Q2，建议下一版用「服务端 `updated` + 客户端版本号」做乐观锁。

### 5.4 离线与 `file://`

| 场景 | 表现 |
|---|---|
| 双击 HTML 打开（`file://`） | 顶部红色提示条说明「更新数据 / 刷新情绪 / 写回」都不可用；笔记仍可读写，改动只在本机草稿 |
| 服务未启动（`http://` 打不开） | 同上，`fetch` 抛 `TypeError` → `offline` |
| 服务启动后 | 刷新页面即自动把草稿写回；不需要重新输入 |

`offline` 态下每次改动**不再尝试** POST（避免每次输入都打一次失败请求），只在徽标上重复说明。

## 6. 数据契约

### 6.1 文件与字段

`data/notes/notes.json`（入库文件，`data/notes/backups/` 不入库）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | int | 结构版本，当前 `1`。**加字段不必升；改字段含义必须升**，且迁移要写在读取路径上（当前 `load()` 只做读取，还没有迁移——这一天迟早会来） |
| `updated` | string | 最后写回时间，`YYYY-MM-DD HH:MM`（**本地时间**）。由服务端写，不接受客户端传值 |
| `columns[]` | array | 泳道，顺序即页面顺序 |
| `columns[].id` | string | 泳道 id，全局唯一，`col-` 前缀 |
| `columns[].title` | string | 列名，可为空（页面显示「未命名」），建议 ≤16 字 |
| `columns[].cards[]` | array | 卡片，顺序即列内顺序 |
| `cards[].id` | string | 卡片 id，**全局唯一**（跨泳道也不能重），`c-` 前缀 |
| `cards[].title` | string | 标题，可为空（页面显示「（无标题）」），建议 ≤60 字 |
| `cards[].body` | string | 正文，**纯文本**，换行就是 `\n`；无 Markdown、无 HTML、无附件字段 |
| `cards[].created` | string | 创建时间，ISO 8601 |
| `cards[].updated` | string | 修改时间，ISO 8601；每次内容或位置变化都刷新 |

**不写入的字段一律不写**：没有 `tags`、`pinned`、`order`、`color`、`archived`。
顺序由数组位置表达，状态由泳道表达。要用颜色区分，就再开一条泳道。

### 6.2 不变式

| # | 不变式 | 由谁保证 |
|---|---|---|
| N1 | 所有 `id` 非空且全局唯一（跨泳道） | 前端生成 + 服务端校验（重复即拒写） |
| N2 | `body` 是字符串，不含 HTML/Markdown 语义 | 前端 `textContent` 写入 + 后端只存不解析 |
| N3 | 页面不修改用户原文：不补全、不润色、不自动格式化、不摘要 | 代码层无任何改写路径（红线） |
| N4 | `updated` 由服务端生成 | `save()` 覆盖客户端传值 |
| N5 | 键序固定为 `schemaVersion, updated, columns`，未知字段原样保留 | `save()` 的 payload 构造顺序 |
| N6 | 文件以 `\n` 换行、UTF-8、缩进 1、末尾有换行 | 写盘时 `newline="\n"` |
| N7 | 写盘是原子的：临时文件 + `os.replace` | 断电不留半份文件 |
| N8 | 结构错误时构建失败，不生成「半坏」页面 | `build_dashboard.py` 校验失败即 `SystemExit` |

**N8 值得单独说**：构建期如果发现笔记 id 重复，页面构建直接中断，而不是「带着错误渲染」。
理由是这一页的错误形态是「两张一样的卡片」，用户看不见错误、只会误删数据。

### 6.3 校验分级

**错误（拒写，返回 400，文件一字不动）**

| 条件 | 为什么要拦住 |
|---|---|
| 顶层不是对象 | 后续所有取值都会异常 |
| `columns` 不是数组 | 看板无法渲染 |
| 泳道不是对象 / 缺 `id` / `id` 重复 | 定位与拖拽全部依赖 id |
| `cards` 不是数组 | 列内渲染中断 |
| 卡片不是对象 / 缺 `id` / `id` 重复 | 同上，且重复 id 会造成「删错卡」 |
| 有卡片但一个合法 id 都没有 | 整份数据不可操作 |

**提示（照写，只在构建日志与接口 `warnings` 里出现）**

| 条件 | 为什么不拦 |
|---|---|
| 一条泳道都没有 | 用户可能刚清空、准备重建 |
| 泳道没有名字 | 正在编辑的中间态 |
| 列名 > 16 字 | 只是显示不下，数据本身没错 |
| 卡片标题与正文都为空 | 新建卡片的瞬间就是这个状态 |
| 标题 > 60 字 | 列里只显示一行，不影响存储 |

**分级的原则**：拦住「写进去只会更难修」的，放过「用户正在打字」的。

### 6.4 备份

| 项 | 要求 |
|---|---|
| 时机 | **写前**备份（先把旧文件复制走，再写新文件） |
| 位置 | `data/notes/backups/notes-YYYYMMDD-HHMMSS.json` |
| 撞名 | 同一秒内连写两次，追加 `-1`、`-2` 后缀 |
| 保留 | 滚动 40 份（当前每份 1.6 KB；按增长到 20 KB 估算，累计仍在 1 MB 内） |
| 清理 | 每次备份后裁剪最旧的；删除失败不阻断写盘 |
| 入库 | **不入库**。git 里的 `notes.json` 历史本身就是更完整的版本记录 |

40 份而不是 30（持仓的口径）：卡片的编辑是「写字」，不像仓位可以凭记忆重填。

### 6.5 写盘细节

1. 校验不过 → 抛 `ValueError` → 接口 400，**不落盘**。
2. 组装 payload：固定键序，未知字段追加在末尾（将来迁移才有依据）。
3. 复制旧文件到 `backups/`，裁剪。
4. 写 `notes.json.tmp` → `os.replace` 原子替换。
5. 返回 `path`（相对仓库根，正斜杠）、`bytes`、`backup`（文件名）、`as_of`。

**换行必须是 `\n`**（`newline="\n"`）。Windows 默认会把 `\n` 翻成 `\r\n`，
一次保存就会让整篇 diff 变红——这个坑在别的 JSON 入库文件上踩过。

## 7. 接口契约

### 7.1 `GET /api/notes`

- **不缓存**：每次请求重新读盘。缓存住就等于让用户在自己刚改完之后看到旧内容。
- 响应：

```json
{
  "ok": true,
  "notes": {
    "schemaVersion": 1,
    "updated": "2026-11-09 05:35",
    "columns": [
      {"id": "col-inbox", "title": "随手记",
       "cards": [{"id": "c-seed-1", "title": "示例 · 这张卡片可以删",
                  "body": "点卡片会从右边拉出抽屉……",
                  "created": "2026-11-09 05:35", "updated": "2026-11-09 05:35"}]}
    ],
    "stats": {
      "columns": 3, "cards": 3, "chars": 296,
      "by_column": [
        {"id": "col-inbox", "title": "随手记", "n": 1, "chars": 97},
        {"id": "col-todo",  "title": "待处理", "n": 1, "chars": 76},
        {"id": "col-done",  "title": "已归档", "n": 1, "chars": 123}
      ]
    },
    "errors": [], "warnings": []
  },
  "errors": [], "warnings": []
}
```

- `ok = not errors`。有错误时仍返回 200 与完整内容（让人看见坏在哪），不是 500。
- 统计在**后端**算，前端不重算总数口径；但前端渲染时自己算的「匹配数」是前端专属口径
  （过滤后条数），两者不冲突。

### 7.2 `POST /api/notes`

| 项 | 要求 |
|---|---|
| 请求体 | `{"notes": {"columns": [...]}}`，`schemaVersion` 可省 |
| 成功 | 200 `{ok:true, stats, path, bytes, backup, as_of}` |
| 请求体不是合法 JSON | 400 `{ok:false, error:"请求体不是合法 JSON"}` |
| 校验失败 | 400 `{ok:false, error:"数据校验失败：…"}`（最多带前 3 条原因） |
| 其他异常 | 500，错误进服务日志，文件不动 |
| 并发 | 进程内锁串行化，同一时刻只有一个写盘 |
| 幂等性 | 不幂等。每次成功写都会产生一个新备份与新的 `updated` |

`path` 是**相对仓库根**的路径（如 `data/notes/notes.json`），用于徽标 `title` 展示；
不要把绝对路径回给页面。

### 7.3 构建期注入

| 项 | 要求 |
|---|---|
| 占位符 | `/*__NOTES__*/null`，必须存在（缺失则断言失败） |
| 注入内容 | `build()` 的完整结果（含 `stats`），紧凑 JSON，`</` 转义为 `<\/` |
| 校验 | 注入前先 `validate()`；有错误直接 `SystemExit`，不产出页面 |
| 体积 | 当前约 1.0 KB（占 HTML 1.65 MB 的千分之一） |
| 变量前缀 | `nt` / `NT`，与新闻的 `n`、日历的 `k` 区分。**同一文件里用单字母前缀迟早撞车**（v1.36.0 的 `npath/n_js/n_kb` 曾把新闻体积统计覆盖掉） |

## 8. 内容与隐私纪律

### 8.1 只存原文

页面**永不改写**用户写下的字：不补全、不润色、不纠正错别字、不自动格式化、不自动摘要、
不把「嗯」改成「好的」。理由是笔记的全部价值在于「当时是怎么想的」——包括不通顺的句子、
半途而废的推理、写错的日期。自动润色会抹掉这层痕迹，而且用户事后分不清哪句是自己写的。

派生要求：

- 正文纯文本存；写回原样序列化；备份在写之前。
- 不做「智能纠错」提示落在正文里。要改就自己改。
- 任何自动化（脚本、AI）**不得写入 `notes.json`**。这一页没有「生成」入口，
  也不接受程序补内容——包括「帮你整理成提纲」。

### 8.2 笔记会进 git

`data/notes/notes.json` 是**入库文件**（`.gitignore` 里逐条放行）。这意味着：

1. 写进去的内容会随 `git push` 进入远端仓库（若配置了远端）。
2. 删除一条卡片，历史里仍然存在。
3. 因此**不要写入**：账户密码、API 密钥、券商登录信息、他人隐私、未公开的持仓细节。

这一条不是「建议」而是使用约束：它决定了这一页能记什么、不能记什么。
如果需要记敏感信息，应改为不入库的本地文件（那是另一个需求，不在本期范围）。

### 8.3 不做事实校验

笔记里的数字、日期、结论由写的人负责。程序不核对、不提示「这个日期不对」。
唯一与时间有关的自动行为是页脚显示修改时间——那是元数据，不是内容。

推论：写「11-23 的判断错了，因为……」时，日期要自己写全（年份也要），
否则半年后无法判断是哪一年。

### 8.4 与 AI 的边界

本期**不接入**任何自动读取或写入。原因不是技术，是这一页的失败代价不对称：
写错一段行情判断，下一版可以更正；被程序改写的一段私人笔记，没有办法还原「原来的语气」。
若将来要接（例如「把本周判断摘成卡片」），必须满足：只读、草稿态、逐条人工确认后落盘。

## 9. 非功能需求

### 9.1 可靠性（第一优先级）

| 场景 | 要求 |
|---|---|
| 浏览器崩溃 / 断电 | 最多丢最后一次输入（草稿在 `input` 事件里同步写） |
| 写盘失败 | 草稿保留，徽标 `fail`，可继续编辑，服务恢复后刷新即写回 |
| 服务挂掉 | 页面仍可读写（内存 + 草稿），徽标 `offline` |
| 文件被手工改坏 | 构建中断（N8）；页面 `GET` 返回 `ok:false` + `errors`；文件不被自动覆盖 |
| 误删卡片 | 可从 `backups/` 最近一份恢复，再点「重读文件」 |

**「不丢字」优先于「写得快」「排得好看」「功能多」。** 任何与之冲突的设计，都让路。

### 9.2 性能预算

| 项 | 预算 | 现状 |
|---|---|---|
| 首屏渲染 | < 50ms（内嵌数据） | 3 卡，可忽略 |
| 输入响应 | 每次按键无阻塞（就地改预览，不重绘） | 满足 |
| 全量重绘 | 200 卡 / 5 万字下 < 16ms | 未实测（当前规模远低于此） |
| 搜索 | 输入即返回，无 loading 态 | 满足 |
| 写回 | 防抖 600ms，单次 POST < 100ms（本地） | 满足 |
| 注入体积 | < 50 KB | 约 1.0 KB |

**为什么给 200 卡 / 5 万字**：这是「一个人两年、每天写一条」的量级。超过它就该换工具，
而不是给这一页加虚拟滚动。

### 9.3 兼容性

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge 最新两个大版本（终端本身按此交付） |
| 拖拽 | HTML5 DnD。触屏不生效，兜底是抽屉里的「所属泳道」下拉 |
| `localStorage` | 隐私模式或配额满时可能抛错 → `nostore` 态，功能降级但不崩 |
| 本地文件 | `file://` 打开时只读行情、可写笔记草稿，写回禁用并明示 |

### 9.4 可访问性（现状与缺口）

- 已有：`Esc` / `Ctrl+Enter` 关闭抽屉；搜索框、输入框、下拉均为原生控件，可 Tab。
- 缺口：卡片是 `div`，**不可聚焦、不能回车打开**；纯键盘用户只能搜索，不能进卡片。
  列为 Q5。
- 颜色不是唯一信息载体：删除按钮有文字、状态徽标有文案，不单靠红/绿。

### 9.5 可维护性

- 函数与变量统一 `nt` / `NT` 前缀；CSS 统一 `#pane13` 作用域。
- 事件用**委托**绑在 `pane13` 上一次，重绘不重绑（`p.__ntBound` 防重复）。
- 新增 DOM id 前先 grep：**同一页两个 `id="ntC"` 曾让泳道下拉完全失效**，
  而 `getElementById` 只返回第一个、不报错（v1.36.0 踩坑）。

## 11. 已知局限

以下都是**有意的取舍**，不是没做完：

1. **没有版本历史界面。** 只能翻 `backups/` 或 git；页面不提供「回到上一版」。
2. **没有多板。** 只有一组泳道；想分主题就再开一条泳道。
3. **没有 Markdown / 富文本 / 图片 / 附件。** 刻意的（§2.2、§8.1）。
4. **看板不适合长文。** 一张卡两千字，列里只显示两行。
5. **触屏拖不动。** 有下拉兜底，体验低于桌面。
6. **没有撤销。** 删除只有二次确认与备份，没有 `Ctrl+Z` 撤回删除。
7. **搜索语义模糊。** 过滤状态下拖拽，落点按可见顺序算，可能与全量顺序差一位（FR-5）。

## 12. 待确认问题（Q1~Q6）

按「该不该先改」排序。前三条属于「安静地不对」，建议下一版处理。

### Q1 多标签页并发没有版本号（建议优先）

两个标签页同时打开笔记，各持一份内存副本；A 改卡片、B 改另一张卡，B 后写 → A 的改动消失，
无任何提示。当前依赖「用户只开一个标签页」，但浏览器恢复会话时很容易开出两个。

**建议**：`POST` 带 `base_updated`，服务端与磁盘上的 `updated` 不一致时返回 409，
前端提示「文件已被其它窗口修改」并给「重读文件」入口。代价是每次保存多一次比较，
收益是把「静默丢字」变成「可见冲突」。

### Q2 连续编辑可能两个写回同时在飞

`ntPushFile` 在保存中会把状态从 `saving` 改回 `dirty`，于是第二个 POST 可能并发发出。
服务端有锁，但到达顺序无保证，理论上旧快照可能后到。

**建议**：保存中再次触发只记一个 `pending` 标记，当前请求结束后再发一次（串行队列），
而不是并发。改动很小，能消掉这一类竞态。

### Q3 新卡片的创建/修改时间按 UTC 显示

卡片时间用 `new Date().toISOString()` 存，展示时直接切前 16 位 → 显示的是 UTC，
比北京时间慢 8 小时；而源文件的 `updated` 是服务端本地时间。同一条笔记，卡片脚注与工具条
可能差 8 小时。种子数据用的是本地时间字符串，所以历史上没被发现。

**建议**：统一为「存 ISO、显示转本地」。这是一处纯显示修正，但会改变已有卡片的时间显示，
需要一次性确认是否接受历史卡片的时间整体加 8 小时（这是把错的改对，不是改口径）。

### Q4 工具条「正文 X 字」在输入时不更新

`ntStat()` 只在重绘时调用。打字时只更新卡片预览与抽屉字数，工具条总数停在打开页面时的值，
直到搜索、拖拽、增删等动作触发重绘。

**建议**：`ntInput` 里顺手更新总数（或给 `body.length` 的增量），成本极低。

### Q5 卡片不可键盘聚焦

卡片是 `div`，无 `tabindex`，回车不能打开。纯键盘用户只能搜索，不能用键盘进卡片编辑。
抽屉本身可用键盘。

**建议**：卡片加 `tabindex="0"` + `role="button"`，`Enter` 打开；同时补 `aria-label`（标题或「无标题」）。

### Q6 要不要「回到上一版」

现在恢复要靠 `backups/` 文件名找时间点，或 `git checkout`。这两条对非技术用户不可行。
是否需要页面内的「最近 5 个版本，预览并恢复」？

**取舍**：做，就要处理「恢复后草稿怎么办」（否则旧草稿又把恢复盖回去，正是 FR-7 那个坑）；
不做，就把恢复流程写进页头说明，别让人以为有撤销。**当前倾向不做**，先补 Q1~Q3。

## 附录 B 沿革与踩坑

### B.1 需求原话（v1.36.0）

> 「新的功能模块需求：个人笔记。我想做成 横竖 泳道 可编辑 卡片式样记录，
> 然后点击卡片展开 展示详情，类似 Trello 这种软件样式，我可以编辑卡片、录入文字。」

追问一次确认了「横竖」的含义：**列是横排的泳道，列名可改；卡片在列内纵向堆叠**——
不是「同一份数据能横着排也能竖着排」。存储选本地 JSON 走服务写回，与持仓地图同一套。

### B.2 三次踩坑（都写进了 §9.5 的纪律）

1. **同一页两个 `id="ntC"`。** 工具条「卡片数」与抽屉「泳道下拉」同名，
   `getElementById` 只返回第一个 → 下拉被塞进 `<b>` 里，完全失效且不报错。
   重复 id 不会报错，只会让一半功能安静地不工作。
2. **`build_dashboard.py` 变量撞车。** 笔记注入沿用新闻的 `npath / n_js / n_kb`，
   把新闻的体积统计覆盖成笔记的。改为 `ntpath / nt_js / nt_kb`。
3. **探针把种子数据写脏。** 接口测试与截图都是真写回，测完必须从 `backups/` 恢复
   **并且清掉浏览器草稿**，否则草稿会把恢复的内容再盖一次——这正是 FR-7 的由来。

### B.3 导航层变更（不涉及本模块功能）

- 「笔记」组曾改名为「工具」，意图是留一个位置放以后的小工具；组内至今仍只有这一页。

  于是页签栏收窄。**这是布局问题，不要在本页里加宽度补偿。**
