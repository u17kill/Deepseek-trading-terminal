# 需求文档 · 最新风向模块

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0（需求版） |
| 对应实现 | 交易终端「最新风向」页（v1.32.0 快照） |
| 数据快照 | 2026-11-08（窗口 2026-08-01 ~ 2026-11-08） |
| 文档范围 | 功能需求、数据契约、内容写作规则、验收标准；不含配色与实现方案 |
| 读者 | 内容策展、验收方、外部开发者，**以及需要按本规范产出内容的大模型** |

**两种用法。**

- 人看：第 1–7 章是需求与验收，附录 A–C 是样例、写作要求与术语。
- 模型看：把**全文**作为上下文，然后按第 8 章的产出契约交 JSON。只给第 8 章不够——字段填得对、内容写不对，是这个模块最常见的失败方式，而内容规则在附录 B。

---

## 1. 产品定位

终端里有几页都在描述价格。本模块描述**观点的分布**：

> **谁，在什么时候，基于什么数字，给出了什么判断。**

三个要素缺一不可。只有「谁说了看空」是情绪，只有「什么时候」是新闻，只有「什么数字」是研报。合起来才回答一个问题：**现在这批真正说得上话的人，分歧在哪里。**

### 1.1 与相邻模块的分工

| 模块 | 回答的问题 | 单位 |
|---|---|---|
| 市场新闻 | 今天发生了什么 | 事件 |
| **最新风向（本模块）** | **某个人最近怎么说** | **人** |
| 机构研报 | 一类机构对一类资产怎么判断 | 机构 × 主题 |
| 大佬持仓 | 账上到底有什么 | 仓位 |

风向与持仓最容易混。区别是：风向记**语言**，持仓记**数字**。一个人可以「嘴上谨慎、13F 加仓」，这种背离在本模块里**原样保留**，不调和、不取平均——它本身就是信息。

### 1.2 一句话概括

**这一页不是「共识」，是「分歧的地图」。** 页首的主线写整理者的判断，正文的卡片写当事人的原话，两者不混。

## 2. 范围

### 2.1 本模块包含

1. 页首「本期主线」：8–11 条策展判断，每条一句标题 + 一段论证。
2. 按六大类分组的全部人物卡，一人一卡。
3. 每张卡：身份、机构、立场标签、一句话概括、2–5 条带日期与出处的要点。
4. 温度条：六类的人数与标签分布，可点击跳转到对应分类。
5. 搜索（人名 / 机构 / 立场 / 要点正文）、立场筛选、只看结论。
6. 数据校验规则与统计口径。

### 2.2 本模块不包含

| 不做 | 理由 |
|---|---|
| 由程序生成或改写观点 | 观点是检索与判断的产物。宁可显示「12 位超过 30 天没更新」，也不许自动补一条看起来新鲜的话 |
| 自动降级 / 自动填充 | 三个月没说话就显示旧日期，不降级成「上期观点」，不用同机构其他人的话代答 |
| 买卖建议、目标价、受益标的 | 本模块只记录判断，不给结论 |
| 把立场汇总成「大佬情绪指数」 | 样本有偏（见 §5.3），加权求和会把偏差伪装成指标 |
| 持仓反推观点、跟单榜单 | 与「大佬持仓」页职责重叠，且会把标签误读成仓位 |
| 编辑、评论、收藏、导出 | 内容由策展流程维护，页面只读 |

## 3. 数据范围

### 3.1 规模

| 项 | 数量 |
|---|---|
| 人物 | **125** |
| 要点 | **448** |
| 分类 | **6** |
| 主线 | **11** 条 |
| 窗口 | 2026-08-01 ~ 2026-11-08（三个月零一周） |

### 3.2 六大分类（固定，不可增删）

分类不是按「身份」切的，是按**他用什么语言影响市场**切的。

| id | 名称 | 人数 | 要点 | 多 / 中 / 空 | 判断依据 |
|---|---|---|---|---|---|
| `macro` | 宏观大师 | 25 | 94 | 6 / 10 / 9 | 看流动性、财政与资产价格的位置；给的是配置判断，不是选股 |
| `value` | 价值投资 | 9 | 30 | 5 / 4 / 0 | 算企业现金流与安全边际；多数不追叙事 |
| `tech_investor` | 科技投资人 | 16 | 62 | 13 / 3 / 0 | 看仓位；13F 与访谈能读出真实动作 |
| `tech_leader` | 科技与产业 | 34 | 134 | 28 / 6 / 0 | 看订单、产能、资本开支的一手口径 |
| `central_bank` | 央行与监管 | 10 | 27 | 2 / 1 / 7 | 看利率路径与监管口径 |
| `gov` | 政府 | 31 | 101 | 2 / 24 / 5 | 看关税、财政与谈判筹码 |

**这个分布本身就是结论**：产业口 28 偏多、0 看空；央行口 7 偏空、2 偏多。两组人看同一组数据得出相反结论——产业口看到订单售罄，央行口看到通胀没下来。页面把这个冲突摆在最前面，不平均成「中性」。

### 3.3 分组（`grp`）

三个分类有子分组，**这三个分类的每个人必须填 `grp`**；其余三类不填。

| 分类 | 分组 | 人数 |
|---|---|---|
| `macro` | `buy` 买方与媒体 / `sell_us` 卖方（美股与全球）/ `sell_eu` 卖方（欧洲）/ `sell_jp` 卖方（日本）/ `sell_cn` 卖方（中国区） | 13 / 4 / 1 / 1 / 6 |
| `tech_leader` | `us` 美国科技巨头 / `hw` 算力与硬件 / `cn` 中国科技 | 11 / 11 / 12 |
| `gov` | `us` 美国 / `cn` 中国 / `eu` 欧洲 / `ap` 亚太 / `geo` 地缘与其他 | 13 / 4 / 4 / 4 / 6 |

四条归组口径，都是踩过坑之后定的：

1. **卖方按辖区拆，不按机构品牌拆。** 目标位只在它覆盖的市场里成立。「8000 点」和「3800 点」不是同一场争论——连标的都不是同一个。同一家机构可以有两张卡（野村陆挺讲 A 股、北冈智亲讲日本），因为卖方卖的是**对某个市场的判断**，不是品牌。
2. **政府按地区拆。** 同一场关税冲击，落在不同经济体上是不同的政策反应（英国砍电费增值税、德国降电力税、日本扩财政）。混在一组会让人以为他们在回答同一个问题。
3. **价值派与科技投资人按方法归，不按身价归。** 判断标准是「他的话里有没有现金流」。艾斯曼讲应收账款集中度、表外融资动机，属信用结构判断，放宏观买方；放价值派会把「算现金流」和「算融资链条会不会断」混成一套方法。
4. **一人一卡，不许重复入册。** 同一个自然人只能出现一次。若他影响市场的方式有两种，按**主方式**归组：佩洛西只在科技投资人组（她的信息全部来自国会交易披露，是仓位语言），不在政府组。要换组可以，同时出现在两组不行。

### 3.4 字段与约束

#### 顶层

```json
{
  "as_of": "2026-11-08",
  "window": ["2026-08-01", "2026-11-08"],
  "updated": "2026-11-08 22:40",
  "brief": { "title": "本期主线", "items": [ { "h": "标题", "t": "论证" } ] },
  "cats": [ { "id": "macro", "name": "宏观大师", "desc": "…", "groups": [ { "id": "buy", "name": "买方与媒体" } ] } ],
  "people": [ ]
}
```

#### 人物（`people[]`）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | string | 是 | 全库唯一；小写字母 + 连字符；用姓氏或通行代号（`vance`、`thune`、`druckenmiller`），不用拼音缩写，不用序号 |
| `name` | string | 是 | 拉丁字母原名，按本人常用拼写（`JD Vance`、`Jamie Dimon`） |
| `cn` | string | 是 | 中文常用简称，2–6 字；**不要**写全名音译（写「万斯」不写「詹姆斯·戴维·万斯」） |
| `role` | string | 是 | **窗口末端的身份**，含生效说明。例：「美国副总统」「美国参议员（2027 年 1 月就任）」 |
| `org` | string | 是 | 机构原名，英文优先。与 `role` 重复时页面自动省略 |
| `cat` | enum | 是 | 六个 id 之一 |
| `grp` | enum | 视分类 | `macro` / `tech_leader` / `gov` 必填，其余不填 |
| `tag` | enum | 是 | `bull` / `neutral` / `bear` |
| `stance` | string | 是 | 一句话，建议 9–40 字；必须含**具体抓手或反差**，不能只写方向 |
| `points` | array | 是 | 1–5 条，**理想 2–4 条**；为空报警告 |

#### 要点（`points[]`）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `date` | string | 是 | `YYYY-MM-DD` 优先；来源只到月则写 `YYYY-MM`，**禁止编造日** |
| `src` | string | 是 | 出口名，≤20 字，不带 URL（`X 帖`、`路透社`、`FY26Q3 财报电话会`、`13F 披露`） |
| `text` | string | 是 | 60–220 字；**一句事实 + 一个可核验的数字或原话** |

字数上限 220 不是排版限制，是质量限制：一条要点塞进三个论点，等于三个论点都没说清。

### 3.5 立场标签的语义边界

`tag` 只回答「他最近怎么说」，**不回答**「他买了多少」，也不是评级。

| 标签 | 含义 | 判定问句 |
|---|---|---|
| `bull` | 对主要资产方向性偏正面 | 他是否认为价格还会涨、或基本面向好？ |
| `bear` | 方向性偏负面 | 他是否认为估值过高、泡沫、或基本面转弱？ |
| `neutral` | 两面、观望、或只陈述事实 | 他是否既讲了机会也讲了风险，且未给方向？ |

三类高频误判：

1. **把仓位当立场。** 格里芬说「几乎肯定是泡沫」却继续重仓——标签记 `bear`（他说的话），仓位写在要点里（他做的事）。两者背离是常态。
2. **把政策人物的表态当个人看空。** 沃伦记 `bear`，因为她将执掌银行委员会、把传票权对准银行与私募——这对 AI 基建与金融股是逆风，与她本人是否看好市场无关。政府组 24 位中性不是偷懒，政治表态多数时候本来就是两面的。
3. **把「窗口内没表态」记成中性。** 没表态就是没表态，卡片要点会显得稀疏，这是真实状态；不许用同机构其他人的话代答。

### 3.6 数据质量规则

**机器校验（构建期报错，不通过不构建）**

| 级别 | 规则 |
|---|---|
| E | `id` 缺失或重复 |
| E | `name` / `cn` / `role` / `cat` / `tag` 缺失 |
| E | `cat` 不存在；`grp` 在该分类下不存在；`tag` 不在三档内 |
| E | 要点缺 `date` / `src` / `text`；日期格式不合法 |
| W | 某人的 `points` 为空 |
| W | `points` 超过 5 条 |
| W | 单条 `text` 超过 220 字 |
| W | 日期落在 `window` 之外（`YYYY-MM` 按月初比较） |

**人工校验（机器查不出来，必须人过一遍）**

1. **一人一卡**：同一自然人不得出现两次。
2. **单源风险**：若某人的全部要点来自同一个出口、同一天，视为未核实。
3. **立场与要点一致**：`stance` 的概括必须在 `points` 里找得到出处，不能是整理者的推断。
4. **身份时效**：窗口内身份变化的人，`role` 记末端身份并注明生效时间，不许把「当选」写成「在任」。
5. **引语真伪**：`text` 里带引号的话必须是原话。转述不加引号。

### 3.7 统计口径

- **人数**：按 `people` 数组长度计，一人一卡，不存在重复计数。
- **要点数**：按全部 `points` 求和。
- **多 / 中 / 空**：按 `tag` 直接计数，不加权、不做净多头。
- **窗口**：`window` 是检索边界，不是数据边界——实际最新一条可能早于 `window[1]`。
- **页首计数条**：`125 位 · 448 条要点 · 2026-08-01 ~ 2026-11-08`，构建期算好写死，页面不二次计算。

## 4. 功能需求

| 编号 | 功能 | 要求 |
|---|---|---|
| F1 | 本期主线 | 8–11 条；每条 `h` ≤ 20 字、`t` 150–600 字；**由人写，不由程序拼装** |
| F2 | 温度条 | 六格横排，显示分类名、人数、标签分布；每格可点，平滑滚动到对应分类并高亮标题；不吸顶 |
| F3 | 人物卡 | 三列网格；左侧 3px 色条按 `tag` 着色；卡内：头像字、中英文名、标签胶囊、身份行、立场句、要点列表（日期 + 出处 + 正文） |
| F4 | 搜索 | 搜人名、机构、立场句、**全部要点正文**；能搜「加息」「HBM」这类词 |
| F5 | 立场筛选 | 全部 / 偏多 / 中性 / 偏空；无人的分类整段不渲染 |
| F6 | 只看结论 | 每卡压缩到立场 + 第一条要点 |
| F7 | 更新按钮 | 只做三件事：重读数据并合并分片、重建静态页、体检新鲜度（列出超过 30 天未更新的人）。**不生成观点** |
| F8 | 计数条 | 显示人数、要点数、窗口；筛选时显示当前可见数 |

F2 的两处判断：①跳转用平滑滚动不用瞬移——两万多像素的瞬移会让人失去位置感；②筛选生效时目标分类可能整块没渲染，此时先清筛选再跳，并在计数条留一句「已清除筛选」，因为清筛选有副作用，不能静默做。

F7 的新鲜度基准日取**运行当天**而非 `as_of`——用快照日算永远显示「刚更新过」，反而掩盖内容在变旧。

## 5. 非功能需求

### 5.1 体量与性能

单页正文约 3 万像素高（125 卡 × 3 列）。首屏只渲染页首与温度条；卡片网格一次性渲染，不做虚拟滚动——搜索要对全部正文做子串匹配，虚拟列表会让搜索结果与可见内容不一致。

### 5.2 可维护性

数据分片手写（`part1..part9`），合并时**按文件名排序**，重复 `id` 以先出现者为准。新增分片若命名为 `part10`，字典序会排到 `part2` 之前，导致覆盖规则失效——**新内容插进已有分片的数组头部，不要新建两位数分片**。

### 5.3 已知边界（写清楚，不粉饰）

| 边界 | 后果 |
|---|---|
| **样本有偏**：英文媒体覆盖多、买方卖方多 | 用它统计「共识」会系统性高估某几类声音 |
| **二手转述为主**：`src` 是出口不是链接 | 逐字引用必须回原源核对 |
| **日期精度不齐**：部分只到月 | 时间轴上的「同一天」不可靠 |
| **中文口径只取官方通稿** | 中国政策人物只陈述政策内容与公开数字，不作解读、不作评价 |
| **要点密度不均**：2–5 条 | 新入册者（如新当选官员）公开表态本就少，卡片高度差肉眼可见 |
| **主线与卡片存在时间断点** | 主线是策展叙事，卡片是逐条摘录，两者时间重心可以不同步 |

## 8. 给大模型的产出契约

**输入**：本文件 + 一份待补的人物名单（或一个补充方向，如「补 5 位欧洲央行系统的人」）+ 当期 `window`。

**输出**：**严格 JSON**，顶层是数组，元素为人物对象。不要 Markdown 围栏以外的任何解释文字；如需说明，单独写在 JSON 之后的「备注」段，且不超过 5 行。

```json
[
  {
    "id": "vance",
    "name": "JD Vance",
    "cn": "万斯",
    "role": "美国副总统",
    "org": "White House",
    "cat": "gov",
    "grp": "us",
    "tag": "neutral",
    "stance": "在伊朗战争上公开与白宫切割，关税上继续加码——一松一紧，是他 2028 的起手式",
    "points": [
      {
        "date": "2026-11-04",
        "src": "X 帖 / 路透社",
        "text": "公开与特朗普的伊朗战争拉开距离：「我们输掉的原因就是这场战争」，并称早前建议结束战争是「明智的建议」。路透社称白宫内部视此为外交政策上的公开分歧，而他是 2028 的领跑者之一。"
      }
    ]
  }
]
```

**交付前必须自查的六条**

1. 每个人的 `points` 都带 `date` 与 `src`，`src` 能指到一个真实出口。
2. 没有任何一条 `text` 是「他表示看好/看空」这种没有数字、没有原话的空话。
3. 带引号的话是原话；转述不加引号。
4. `role` 是窗口末端身份；当选未就任的写「（YYYY 年 M 月就任）」。
5. `stance` 与 `points` 能对上，且**不是**对 `tag` 的同义反复（不能写「偏空，看空市场」）。
6. `id` 在现有 125 个 id 里不重复。

**做不到的时候**：宁可少写一个人，也不许用「据悉」「市场普遍认为」凑一条。信息稀疏的人，`points` 只写 1–2 条并在备注里说明检索受限——这比编一条看起来饱满的卡有用。

## 附录 B · 内容撰写要求

### B.1 `stance` 一句话怎么写

**公式：他在哪件事上、跟谁不同、代价是什么。**

- ✅「在伊朗战争上公开与白宫切割，关税上继续加码——一松一紧，是他 2028 的起手式」
- ✅「嘴上说『现在是好时光』，手上按股市跌 40% 做压力准备」
- ✅「看空 AI 估值与长债，反对继续降息，但不敢做空美元」
- ❌「对市场持谨慎乐观态度」（等于没说）
- ❌「著名投资人，观点偏空」（是身份介绍不是立场）

长度 9–40 字。超过 40 字说明你把两条立场塞进了一句，拆成两条要点。

### B.2 `text` 一条怎么写

**公式：动作 + 具体数字或原话 + 与主线的关联（可省）。**

- 必须有至少一个**可核验的硬信息**：具体金额、百分比、点位、产能、日期、原话。
- 不许出现：「据悉」「市场普遍认为」「有分析指出」。
- 转述不加引号；原话才加引号。
- 60–220 字。低于 60 字通常信息不足，高于 220 字通常是两条要点没拆开。

### B.3 什么该收，什么不该收

| 收 | 不收 |
|---|---|
| 有决策权、资金规模、信息优势中至少一条的人 | 纯评论员：无仓位、无职务、无一手信息 |
| 窗口内有可引用的公开表述或可核验动作 | 只有窗口外的旧发言（除身份仍然关键） |
| 对至少一类可交易资产有方向性含义 | 纯学术、纯管理心得、纯人事变动 |
| 能查到出处 | 只有二手传闻、无法落到具体出口 |

### B.4 一人一卡的边界

- 同一自然人只出现一次。
- 同一机构可以有多张卡（卖方按辖区拆时）。
- 组织型主体（红杉两位联席掌门）可合卡，但 `id` 用机构名，`cn` 写机构简称。

## 附录 C · 术语表

| 术语 | 含义 |
|---|---|
| 要点（point） | 一条带日期与出处的摘录，是本模块的最小信息单位 |
| 立场（stance） | 整理者对某人窗口内方向性表述的概括，不是当事人原话 |
| 标签（tag） | 表态口径三档：`bull` / `neutral` / `bear`；不是评级，不是仓位 |
| 一人一卡 | 同一自然人只允许入册一次，避免两张卡两个标签 |
| 窗口（window） | 检索边界，非数据边界 |
| 新鲜度 | 每人最近一条要点距运行当天的天数；超过 30 天列入体检名单 |
| 单源风险 | 某人的全部要点来自同一出口同一天，视为未核实 |
