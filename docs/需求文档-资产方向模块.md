## 1. 产品定位

### 1.1 它回答什么，不回答什么

| 回答 | 不回答 |
|---|---|
| 四层判断各自现在什么方向（政策 / 宏观 / 产业 / 技术） | 明天涨还是跌（技术层只负责「时点」，不负责「方向」） |
| 这些判断摊到 14 类资产上，各偏多强 | 具体买哪只 ETF、买多少（不给标的与仓位） |
| 哪一层在拖后腿、哪一格传导最强 | 这个判断的胜率是多少（回测是后置项） |
| 市场内部承认了没有（确认层） | 央行下一次会议降不降息（利率路径只有代理变量） |

**一句话**：这一页是一张「方向表」，不是「信号机」。页脚那句「只陈述读数与机械合成结果，不构成投资建议」是它的边界，任何实现都不得越过。

### 1.2 为什么必须是一个矩阵，而不是一个总分

同样的利空，对美债可能是利多：

- **地缘型 risk-off**（政策分低）→ 资金涌入国债 → 债券**涨**
- **货币型 risk-off**（宏观分低、联储转鹰）→ 收益率上行 → 债券**跌**

如果只给一个「风险偏好 −30」，两类环境在页面上长得一模一样，但债券该做的事完全相反。
所以本模块同时输出一个标量（定总仓位）与一张矩阵（定结构调整），**两者不可互相替代**。

### 1.3 与相邻页签的分工

| 页签 | 边界 |
|---|---|
| 市场总览（第 1 页） | 只讲「今天发生了什么」；本页讲「未来 1~6 个月往哪偏」 |
| 动能分析 / 估值分位（第 9、10 页） | 单标的的位置与拥挤度；本页是跨资产的相对方向 |
| 当前持仓（第 8 页） | 实际仓位与编辑面板；本页不给仓位建议，也不读持仓 |
| 市场新闻 / 最新风向 / 机构研报 | 解释「为什么」；本页不解释，只陈述读数与合成结果 |

## 2. 范围

### 2.1 本模块包含

1. 五类数据源的取数、并发、失败隔离与原始响应缓存。
2. 19 项指标的分位计算、五档映射、滞后天数标注。
3. 四层模块分的合成（截尾均值、分歧度、强制降级、弱样本标记）。
4. 风险偏好总分的加权归一（含权重覆盖度）。
5. 14 类资产的分数计算（弹性矩阵摊派 + 归一化）与破位徽标。
6. 政策模块的人工 rubric（判据表 + 事实条目 + 已确认/待确认 + 参考分推演）。
7. 本地政策利率对照表（政策利率 / 12 个月 / 12 月区间 / 市场押注 / 与美国利差）。
8. 确认层四个读数（波动率期限结构、信用利差、股债相关性、黄金 vs 实际利率）。
9. 两份人写文件（`policy_answers.json` / `notes.json`）的读取与渲染，以及每日快照落盘。
10. 两个渲染出口（独立页 / 主看板内嵌片段）与构建期注入、全局刷新链路。

### 2.2 本模块不包含（且不得顺手加上）

| 不做 | 理由 |
|---|---|
| 生成判断文字 | 判断的价值在于「知道自己在说什么」；模板拼出来的话不承担后果 |
| 买卖建议 / 目标价 / 仓位建议 | 合规定位：只陈述读数与机械合成结果 |
| 回测与命中率 | 后置项。但**从第一天存每日快照**，否则将来无从回测 |
| 自动优化权重与弹性 | 先验固定，回测只用于证伪、不用于调参。想改必须先写下理由与预期影响 |
| 加「本地政策」第五个模块 | 台湾、印度的政策利率拿不到完整序列，硬造会有一半地区靠猜；且会污染「风险偏好」的语义——它回答的是「美元体系的风险状态」 |
| 用本币指数替代美元 ETF | 本币序列把汇率与本地价格混在一起（日元贬 + 日经本币涨 = 美元回报可能是负的） |
| 拿分位当唯一口径 | 有明确政策目标的指标（核心 PCE）必须按「离目标的距离」分档，见 6.2 |
| 在页面上编辑政策条目 | 政策是人工 rubric，写在 JSON 里；页面只读。表单化是二期 |

```
┌──────────────────────────────────────────────────────────────┐
│ ① 风险偏好卡                                                  │
│   ┌──────────┬───────────────────────────────────────────┐   │
│   │ −29.5    │ 政策  −64.7  ▁▁▁▁▁▁▁▁  [深红]  disp .47·3项 │   │
│   │ [浅红]   │ 宏观  −23.3  ▁▁▁▁      [浅红]  disp .41·6项 │   │
│   │ 中期1~6月 │ 产业  +18.0  ▁▁▁▁▁     [黄]    disp .53·5项 │   │

├──────────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────────┤
```

段序不可调：先给结论（①），再给「怎么摊的」（②），然后给「模型不知道的那部分」（③），

读者会先看到 14 个分数再看到它们怎么来的，顺序反了。

- 页脚必须原文保留三段：口径、限制、免责声明（见 3.5）。

## 4. 功能需求

### FR-1 风险偏好卡

**输入**：`score.risk_appetite`、`score.modules`、`score.weights`。

1. 左侧大字显示总分，保留 1 位小数，带符号（`−29.5` / `+18.0`）。`score` 为 `null` 时显示「—」、字号降到 34px、颜色转灰。
2. 总分下方是灯（`band` + `label`），再下方一行小字「风险偏好总分 · 中期 1~6 个月」。
3. 左下角一行：「覆盖 N/4 模块 · 权重 XX%」。`XX = Σ weights[m] for m in modules_used × 100`。
4. 右侧四行固定顺序：政策 → 宏观 → 产业 → 技术。每行五段：层名（50px）、分数（58px，右对齐）、
   以 0 为中心的双向条、灯 + 标记、`disp · n 项`（96px）。
5. 条宽度 = `min(|score|,100)/100 × 50%`，正向右（绿）、负向左（红）；中心线固定在 50%。
6. 标记规则：
   - 模块分 `null` 且有 `preview` → 分数后加 `*`，灯显示「参考」档，行尾写「N 条待确认」；
   - `downgraded === true` → 灯后加小字「降」（琥珀色）；
   - `weak === true` 且分数非空 → 灯后加小字「弱」（灰色）；
   - 两者互斥，`降` 优先。
7. `disp` 显示两位小数，`null` 显示「—」。

> **为什么总分不显示「置信度」**：置信度分散在四行的 `disp` 与确认层里，合成一个百分比会给出假精度。

### FR-2 模块 × 资产矩阵

**结构**：表头两行。第一行 `模块`（rowspan=2）、`模块分`（rowspan=2）、六个组名（colspan = 组内资产数）；
第二行 14 个资产名。

1. 行序固定：政策 / 宏观 / 产业 / 技术 / **合计**。
2. 列序**必须**等于 `score.groups` 展开后的顺序，且必须等于 `score.assets` 的顺序。
   渲染前做硬校验，不一致直接抛错退出——14 列的表头若与格子错开一格，读数全错却看不出来。
3. 格子值 = 该模块对该资产的贡献分，1 位小数带符号，`±3` 以内为中性灰字，`>+3` 绿底、`<−3` 红底。
4. 政策未确认时：该行格子用**参考值**（斜纹底 + 虚线框 + 灰字），并在表下注明「参考值，未计入合计」。
5. 合计行 = 资产分（见 6.5），不是上面四格之和。
6. 表下注：格子是「权重 × 模块分 × 弹性」的贡献；技术层已重构为市场因子，经弹性摊到各资产。

> **实现方注意**：矩阵的「合计」是 `num/den` 归一化后的分数，格子之和是 `num`，
> 两者差一个归一化系数，见 6.5 与 Q1。

### FR-3 本地政策利率表

**目的**：让人看见「美国模块分代表不了本地政策」这个缺口有多大。**这张表不进分。**

列序固定 7 列：地区 / 政策利率 / 12 个月 / 12 月区间 / 市场押注 / 与美国利差 / 来源。

| 列 | 格式 | 规则 |
|---|---|---|
| 政策利率 | `3.875%`；美国为 `3.75–4.00%` | 美国优先用联储目标区间（`tgt_lo/tgt_hi`），缺失才退回 BIS 单值 |
| 12 个月 | `+75bp` / `−25bp` / `0` | `(rate − prev) × 100`；`prev` 为 `null` 时显示「—」，**不是 0** |
| 12 月区间 | `3.625–3.875%` | 窗口内走过的最高/最低（`hi/lo`）；`lo == hi` 时只显示单值 |
| 市场押注 | `+28bp` / `−149bp` | 短端市场利率 − 政策利率；正=押加息（红），负=押降息（绿） |
| 与美国利差 | `−2.63 pp` | `rate − 美国 rate`；**不上色**（正负只表示高低，不是好坏） |
| 来源 | `BIS CBPOL` / `台湾央行` | 缺失显示「—」 |

- 美国行加浅底 + 加粗（`#faf8f3`）。
- 行序固定：美国 / 日本 / 韩国 / 中国 / 台湾 / 印度；某个地区没取到就整行缺席，不占位。
- 表下一段注：说明两张表的口径差异、三列读法、当前读数、台湾用重貼現率且无短端。
- 全部缺失但有 `errors` 时，整表换成一行提示「本地政策利率未获取：<原因>」。

### FR-4 资产卡

**分组与列**：六组按序渲染 —— 美股（3）/ 亚太（5）/ 利率（1）/ 外汇（1）/ 贵金属与工业金属（3）/ 能源（1）；
组内 3 列网格（≤900 两列，≤620 一列）。组头写组名 + 「N 类」。

每张卡自上而下：

1. 资产名（13.5px 粗）+ 代码（10.5px 灰），右侧灯（小号）。
2. 分数 24px 带符号；`null` 显示「—」。
3. 价格行：「价格 689.81 · 2026-11-20」（1 位小数 + 数据日）。
4. 四条贡献条（政策/宏观/产业/技术），每条三段：层名（38px）、以 0 为中心的双向条、数值（38px）。
   条宽 = `min(|v|,25)/25 × 50%`。参考值（政策未确认）用灰条 + 星号 + 整体透明度 .78。
5. 破位徽标紧贴灯右侧：`broken` → 红「已破位」；`broken_strong` → 深红「已强破位」；否则不显示。

> 破位徽标是「当下事实」，弹性是「长期倾向」，两者允许矛盾（黄金长期避险、这轮也在破位）。
> **徽标不进分数**，只做提醒。

### FR-5 读数明细表

六列：指标 / 数据日 / 读数 / 分位 / 档位 / 滞后。

1. 行序 = `score.indicators` 顺序（M1~M8、I1~I7、T1~T4），**共 19 行**。
2. 读数列直接渲染 `disp` 字符串（已含单位与括号说明），不再二次格式化。
3. 分位列 `p × 100` 取整加 `%`；`p` 为 `null` 显示「—」（T1/T3/T4 与核心 PCE 就是这样，
   T2 有分位）。
4. 档位列按档位值上色：`≥1.5` 深绿、`≥0.5` 浅绿、`>−0.5` 黄、`>−1.5` 浅红、其余深红；`band` 为 `null` 整行显示「未获取」，档位写「未获取」。
5. 滞后列：`lag` 天前；`lag > 45` 标琥珀色；`null` 显示「—」。
6. `date` 缺失显示「—」，不得回填今天。

### FR-6 确认层

四张卡，顺序固定：

| key | 标题 | 显示 | 状态判据 |
|---|---|---|---|
| `vix_ratio` | VIX / VIX3M · 波动率期限结构 | `1.160` | `≥1.0` 倒挂（真恐慌）；否则 contango |
| `hy_chg` | HY OAS 20 日变化 · 信用是否承认 | `+8 bp` | `> +30bp` 走阔（信用事件）；否则「尚未确认」 |

- **不得**把确认层的结果乘进模块分或资产分。

### FR-7 政策模块（人工）

1. 四条判据固定顺序：产业政策（0.35）/ 地缘风险（0.25）/ 技术管制（0.25）/ 财政与监管（0.15）。
2. 每条渲染：维度名 + 分数（±2，带符号）、权重百分比、灯（小号）、状态徽标
   （`confirmed` 绿底「已确认」/ 否则黄底「待确认」）、事实文字、来源、`by`（核验说明，可空）。
3. 分数为 `null` 或没有该维度条目时，该行不出现（当前 P4 就是空的），并在页脚/注释里承认这个缺口。
4. 政策未确认（`score is None`）时，卡下追加一段推演：把 `preview_score` 代入权重算一遍总分，
   写明「若确认，政策模块为 X，总分从 A 变为 B；这不是程序判断，只是按当前权重算出的结果」。
5. 没有政策条目时，风险偏好卡上方出现黄色提示框：政策 20% 权重由其余模块按比例分摊，参考分仅示意。

### 5.3 任务编排

- 41 个作业一次性提交到 `ThreadPoolExecutor(max_workers=6)`：20 FRED + 2 CBOE + 19 Yahoo。
- 每个作业单独 `try/except`：失败落 `errors`，**不中断整批**。
- 实测：6.8 秒、0 失败（2026-11 基线）。
- `local_rates()` 在作业之后同步执行（BIS zip 有 7 天本地缓存，通常不下载）。
- 支持 `--only=fred|cboe|price|local`：只更新该源，其余从上一份 `series.json` **原样继承**

### 5.4 序列裁剪与窗口

| 对象 | 规则 |
|---|---|
| FRED / CBOE | 只保留最近 **2200 天**（约 6 年）：分位窗口 5 年，多留一年缓冲 |
| Yahoo | `range=3y` 不裁剪（约 750 个交易日）：够 200DMA、52 周高与长趋势 |

### 5.5 日期口径（四种，不可混用）

| 字段 | 含义 | 来源 |

| `series.fetched_at` | 取数完成时刻（本机时区 +08:00） | `fetch.py` 运行时刻 |

## 6. 评分逻辑（本模块最复杂的一段）

> 本章每一条都对应一个真实故障。省略任何一条，复现出来的读数都会「看起来对、其实错」。

### 6.1 三级流水线

```
series.json（原始序列）
   │
   ├─ 单指标：窗口 → 分位 → 五档（−2~+2）          ← 6.2
   │
   ├─ 模块分：截尾均值 → ÷2×100 → 灯 → 分歧度降级   ← 6.3
   │
   ├─ 风险偏好：四模块加权（按可用权重归一）          ← 6.4
   │
   └─ 资产分：Σ w·s·e ÷ Σ w·|e| × 100              ← 6.5
        └─ 政策走人工 rubric（6.6）
        └─ 技术层走 4 个市场因子（6.7）
```

### 6.2 单指标 → 五档

**映射函数**（`to_s`）：`p ≥ 0.90 → +2`，`≥ 0.70 → +1`，`≥ 0.30 → 0`，`≥ 0.10 → −1`，否则 `−2`。

**两种组合方式**：

```python
# A. 水平 + 变化（band_dual）：中期口径下水平更重要
if dir_ < 0: p_level = 1 - p_level          # 方向取反
band = 0.6 * to_s(p_level) + 0.4 * to_s(p_change)

# B. 纯分位（band_abs）
q = 1 - p if dirneg else p
band = to_s(q)
```

| 用法 | 指标 |
|---|---|
| `band_dual` + 变化项 | M1 期限差、M2 实际利率、M6 金融条件、M7 美元、I5 铜金比、I6 半导体相对强弱 |
| `band_abs` 纯分位 | M3 通胀预期（倒 U）、M5 Sahm、M8 2Y 20 日变化、I1/I2 订单同比、I4 库存比、I7 HY OAS |
| 绝对档位（不用分位） | M4 核心 PCE 3M 年化 |

**变化项必须用滚动序列**：

```
p_change = pct_rank( chg_n(v, 63), rolling_changes(v, 63) )
```

`rolling_changes` = 历史上每个时点的同期变化序列。**不能**写成「在同一终点上换回看天数」
——那是把不同窗口的累计变化比大小，不是滚动分布。曾经这么写，结果 2Y 的 +19bp 紧缩
重新定价被判成「+2 有利」，方向完全反了。I5/I6 的 20 日收益分位同理（`rolling_returns`）。

**倒 U 指标**：先算偏离度 `|x − 中枢|`，再对偏离度取分位（中枢：通胀预期 2.3%、产能利用率 78.0%）。

**M4 核心 PCE 例外**（绝对档位，不看分位）：

| 3M 年化 | 档位 |
|---|---|
| ≤ 2.0% | +2 |
| 2.0~2.5% | +1 |
| 2.5~3.0% | 0 |
| 3.0~3.5% | −1 |
| > 3.5% | −2 |

理由：5 年窗口含 2022 年高通胀，2.90% 在窗口里只排 34 分位，看着温和，可它离 2% 目标还差 0.9pp。
**凡有明确政策目标的指标，按「离目标的距离」分档；其余按历史分位。**

**取不到怎么办**：记 `None`，**不填 0**；证据表显示「未获取」；模块合成时剔除该项并按剩余重新归一。

### 6.3 模块分

```python
bands = [各指标档位，剔除 None]
if len(bands) >= 4: bands = sorted(bands)[1:-1]     # 截尾：去掉一个最高、一个最低
m = mean(bands)
disp = pstdev(bands)                                # 分歧度
score = round(m / 2.0 * 100, 1)                     # → −100 ~ +100
```

1. **截尾均值而非普通均值**：防止「一个 +2 一个 −2 抵消成 0」的伪中性，也防止单一极端指标绑架整块。
2. **`n` 是截尾后的数量，不是原始指标数**。宏观 8 个指标 → `n = 6`；产业 7 → `n = 5`；
   技术 4（其中 T4 为 `None`）→ `n = 3`（不足 4，不截尾）。页面显示「6 项」，而证据表有 8 行，这是口径不是 bug（见 Q4）。
3. **弱样本**：`n ≤ 1` 时 `weak = true`。
4. **强制降级**：`disp > 1.0` 时，灯向中间挪一档：深绿→浅绿、浅绿→黄、浅红→黄。
   不确定就该显示为不确定，给个假精度比不给更糟。
   实现细节：**深红不降级、黄色不动灯但仍打「降」标**（见 Q3）。
5. 灯：`≥+55` 深绿 / `≥+20` 浅绿 / `≥−20` 黄 / `≥−55` 浅红 / 其余深红。

### 6.4 风险偏好总分

```python
avail = [m for m in ("policy","macro","industry","tech")
         if modules[m].score is not None and not modules[m].weak]
risk = Σ(modules[m].score × W[m]) / Σ W[m]     # 只对 avail 归一
```

权重：政策 **0.20** / 宏观 0.30 / 产业 0.30 / 技术 0.20（合计 1.00）。

- 某个模块缺失或弱样本时，**整块剔除**，其余权重按比例放大（分母同步缩小）。
  `modules_used` 记录实际参与计算的模块，页面「覆盖 N/4 · 权重 XX%」由它算。
- 政策未确认时，`score is None`，20% 权重被重摊；页面另有 `preview` 做示意，不参与。
- 示例（2026-11-22，四层齐全）：
  `0.2×(−64.7) + 0.3×(−23.3) + 0.3×18.0 + 0.2×(−75.0) = −29.53 → −29.5`（浅红）。

> **SPEC 与实现的偏差**：SPEC §4.2 写「仅剩 1 个有效指标时权重按一半计」，
> 实现是**整块剔除**。以实现为准，见 Q2。

### 6.5 资产分与矩阵

**符号约定（先看这一条，这是全模块最容易写反的地方）**

`e` 的含义是「**该模块对 risk-on 的支持度上升 1 单位时，这个资产往哪走**」：
正 = 跟涨，负 = 反跌。因为 `s_m` 已定义成「支持度」，`e` 必须与它配套。

曾经把政策与宏观两行按「恶化时资产往哪走」填，两种约定混用，结果宏观转鹰（s = −23）
反而给美股贡献了 +5.6 分，方向全反。**填表前先默念：支持度升，这个资产涨还是跌。**

**公式**

```
num_{m,a} = w_m × (s_m / 100) × e_{m,a}
asset_a   = 100 × Σ_m num_{m,a} / Σ_m (w_m × |e_{m,a}|)
contrib_{m,a} = 100 × num_{m,a}                  # 矩阵格子的值
```

- `s_m` = 模块分 / 100（−1 ~ +1）；`w_m` 为权重；`e` 见表 6.5.1。
- `score is None` 或 `weak` 的模块不进 `num` 与 `den`（政策 pending 例外，见下）。
- 合计行 `asset_a` 与格子之和 `Σ contrib` **不等**：格子之和是 `100×num`，
  合计还要除以 `den = Σ w|e|`（本例 0.505 ~ 1.06，可大于 1）。
  例：标普500 格子 −8.4 / −5.2 / +4.6 / −15.0 之和 = −24.0，合计 −29.7（`den = 0.81`）。
  见 Q1——页面注里「加起来就是合计行」这句是错的。
- **归一化会压缩弹性差异**：`den` 里也有 `|e|`，调大某个 `e` 分子分母同时变。
  实测韩国宏观 `e` 从 0.4 → 0.7，资产分只动 1.4 分，而矩阵那一格动了 75%。
  **要看传导强度看矩阵，不要看资产分的差值。**

**6.5.2 政策未确认时的显示（v0.1.1 修的坑）**

政策 `score is None` 时，资产循环里**必须先判 `score is None`，再判 `weak`**：

```python
if mo["score"] is None:
    if m == "policy" and preview.get("score") is not None:
        contrib.append({"m": m, "e": e, "pending": True, "v": ...})   # 参考值，不进 num/den
    continue                      # ← 必须先走这条
if mo["weak"]:
    continue                      # ← 后走这条
num += ...; den += ...
```

顺序反了，政策 pending 时 `weak = True` 会先命中，整层被跳过，资产卡从四条塌成三条。
v0.1.0 就是这么错的，矩阵走另一条路径所以四行齐全——**同一份数据两个视图各算一遍，
一处错一处对，是最难发现的一类错**。

### 6.6 政策模块（人工 rubric）

**结构**（`policy_answers.json`）：

- `dims[]`：四维判据表，每维 5 档，每档写明「什么样的事实算这一档」。只由维护者改。
- `answers[]`：当前事实条目，一条一档，必须挂 `fact`（发生了什么）、`date`（**事件日，不是报道日**）、
  `source`（链接/通稿）、`state`（`confirmed` / `pending`）。
- `as_of`：最近一次核验日。

**合成**：

```
确认分 = Σ(score_i × weight_i) / Σ weight_i     # 只取 confirmed
模块分 = 确认分 / 2 × 100
preview = 同上，但 confirmed + pending 全算     # 仅供页面示意
```

- `confirmed` 才有资格进分；`pending` 只在页面显示「待确认」。
  这样「我听说」和「有通稿」在页面上是两种东西。
- 一条 confirmed 都没有 → `score = None`，权重被重摊，页面出提示框 + 参考值（斜纹格/灰条/星号）。
- 仅 1 条 confirmed → `weak = true`，整块被剔除出总分。

**方向统一**为「对 risk-on 的支持度」：支持度越高分越高，所以管制升级、地缘紧张都是负分。

### 6.7 技术层：4 个市场因子（v0.3.0 重构）

**为什么不是逐资产打分**：原来的做法是 14 个资产各自算技术分再取均值，本质是「资产价格的
滞后画像」——股票类 8 个资产占多数票，商品与汇率的独立信息被稀释；而「股票跌没跌」宏观/产业
层已经在回答，技术层没有增量信息。重构后技术层与其余三层同构：**4 个横跨全市场的因子**。

**T1 趋势斜率**

```
篮子 = [SPY, QQQ, SOXX, FXI, EWJ, EWY]
gap_i = 现价 / 20DMA − 1（%）              # 每个资产
动量_i = 现价 / 20 日前收盘 − 1（%）
gs = 分档(mean(gap))                        # >2% → +2, >0.5% → +1, >−0.5% → 0, >−2% → −1, 否则 −2
ms = clip(mean(动量) / 8) × 2               # ±8% 打到 ±2
band = 0.5 × gs + 0.5 × ms
```

**不能用 50/200 均线关系**：那是慢信号，急速下跌时均线仍在高位、关系还是正的
（实测 SOXX 现价 123 远低于 ma20 150，50/200 却 +4.4%），会把 −22% 的暴跌读成「趋势未破」。
动量权重必须给到 0.5，否则暴跌被慢均线对冲成中性。

**T2 波动率结构**

```
p_abs = VIX 现值的 5 年分位
vabs  = band_abs(p_abs, dirneg=True)        # VIX 越高越 risk-off
ratio = VIX / VIX3M
vterm = ratio ≥ 1.0 → −2；≥ 0.95 → −1；≥ 0.92 → 0；否则 +1
band  = 0.6 × vabs + 0.4 × vterm
```

**T3 商品-股票动量差**

```
cmean = mean(铜、油 的 20 日动量)
emean = mean(SPY、QQQ 的 20 日动量)
diff  = cmean − emean
同向（都 ≥0 或都 <0）：band = +0.5（普涨）/ −0.5（普跌）
反向：                band = clip(diff / 6) × 2
```

**必须判同向性**：商品与股票同向普跌是流动性冲击/去杠杆，已由 T1/T2 覆盖，
不该在这里重复计成「衰退」。只在反向时按差值放大（再通胀为正、衰退为负）。

**T4 市场宽度**：`None`（无数据源，证据表显示「未获取」）。四个因子里目前只有三个计分。

> 技术模块分 = 这三个因子档位的截尾均值（n=3，不截尾）→ ÷2×100。
> 逐资产的 `tech_score` 仍在算，但**只用于破位徽标**，不进模块分。

### 6.8 逐资产破位徽标（T5）

```python
if len(close) < 210: 不判定
lo20   = min(low[-21:-1])                  # 前 20 个交易日最低价，不含今天
atr    = ATR(14)
vol_ma = mean(volume[-21:-1])
if close[-1] < lo20:
    depth  = lo20 − close[-1]
    strong = depth > atr and volume[-1] > vol_ma
    → "已强破位" / "已破位"
```

- 徽标是**当下事实**，不进任何分数。
- 样本不足 210 根（约 10 个月）时不判定，不显示徽标——不拿半段数据猜。

### 6.9 确认层（不进分）

| # | 读数 | 公式 | 状态 |
|---|---|---|---|
| C1 | 波动率期限结构 | `VIX / VIX3M` | `≥1.0` 倒挂=真恐慌 |
| C2 | 信用是否承认 | HY OAS 20 日变化（bp） | `> +30bp` 视为信用事件 |
| C3 | 避险是否有效 | QQQ 与 TLT 最近 62 个交易日、61 个日收益的相关系数 | `> +0.2` 正相关=避险失效 |
| C4 | 交易利率还是信用 | 黄金 20 日涨跌 vs 10Y 实际利率 30 日变化 | 利率升 + 金涨 = 交易信用 |

C3 用**共同交易日**对齐后取最近 62 个点，算 61 个日收益；不足 40 个点不显示。
C4 的语义：「金价跌、实际利率升」是反向关系，说的正是交易利率；只有两者背离才说明市场在交易信用。

### 6.10 本地利率表的四个派生字段

```python
spread = rate − 美国 rate                       # pp，负=本地比美国低
chg    = (rate − prev) × 100                    # bp，prev 为空则 null（不是 0）
mm     = 短端市场利率 − rate                     # pp；显示时 ×100 为 bp
range  = [窗口内最低, 窗口内最高]                 # 12 个月内，> (最新日 − 1 年)
```

- **12 月区间存在的理由**：只看「期末 − 期初」会把往返抹平。美国过去 12 个月先降 25bp 到
  3.625%、9 月又加回 3.75–4.00，净变化是 0，单看净变化像「按兵不动」。
- **市场押注是前瞻**：政策利率是「现在」，短端市场利率是「市场对未来的定价」。
  短端映射：美国 `DTB3`（3M 国库券）、日/韩/中 `IR3TIB01*M156N`（3M 银行间）、
  印度 `IRSTCI01INM156N`（隔夜拆借）；**台湾无短端序列，留空**。
- 美国政策利率用联储目标区间 `DFEDTARL`/`DFEDTARU` 显示（3.75–4.00%），比 BIS 单一 3.875 更准；
  但 `chg` 仍按 BIS 单值算，所以美国那格可能是 `0` 而区间上下沿在变——这是两套口径，注里写清。
- 台湾 `prev = null` → `chg` 留空。**「没数据」和「没变化」在页面上必须分开**，混起来就变成假事实。

## 7. 接口契约

本模块**没有自己的 HTTP 接口**——页面是构建期烘焙的静态 HTML。五条入口都是进程级的。

### 7.1 五条入口

| # | 入口 | 命令 / 触发 | 产物 |
|---|---|---|---|
| 1 | 取数 | `python regime/fetch.py [--only=源]`（源：fred / cboe / price / local） | `data/series.json` |
| 2 | 打分 | `python regime/score.py` | `data/score.json` + `data/snapshot/YYYY-MM-DD.json` |
| 3 | 渲染 | `python regime/build.py` | `out/regime.html`（独立页） |
| 4 | 内嵌 | `python scripts/build_dashboard.py` | 调 `build.py::fragment()` 注入 `<!--__REGIME__-->` |
| 5 | 全局刷新 | `POST /api/refresh`（既有接口，见 7.3） | 串行跑 1 → 2 → 重建主看板 |

### 7.2 文件链契约

```
series.json  ──►  score.py  ──►  score.json  ──►  build.py  ──►  fragment()
     │                              │                              │
     └── errors[] 逐项记录           └── warnings[] 逐条提示         └── 只有 HTML，不写盘
```

- `score.py` 只读 `series.json` + `policy_answers.json`，不联网。
- `build.py` 只读 `score.json` + `notes.json`，不算分。
- `fragment()` **不落盘**：`out/` 不入库，若改成读中间文件，新 clone 的仓库构建一次就会少一页。
- 渲染前硬校验 `groups 展开顺序 == assets 顺序`，不一致 `SystemExit`；
  主看板构建捕获 `BaseException`（含 `SystemExit`），整页仍能生成，只把这一页降级成提示。

### 7.3 `POST /api/refresh` 的 regime 段

| 项 | 约定 |
|---|---|
| 顺序 | 指标 → 估值 → **regime 取数** → regime 打分 → 重读判断 → 重建页面 |
| 超时 | 每个子进程 120 秒 |
| 缺项阈值 | 取数输出里 `[未获取]` 出现 **> 3 次** → 放弃重算，保留旧 `score.json` |
| 失败传播 | **不连坐**：`regime_ok=false` 只写日志与状态条尾巴，整次更新仍返回 `ok:true` |
| 响应字段 | `regime_ok`（bool）、`regime`（字符串：成功时为耗时秒数，失败时为原因） |
| 前端 | 失败时状态条追加「· 资产方向未更新」，`title` 放原因 |
| 代价 | 一次更新从约 11 秒涨到约 25 秒（regime 段 15.5 秒） |

> **为什么不连坐**：regime 取的是 FRED / Yahoo / CBOE，与 westock 是两套源。
> 一套挂了就把整次更新判失败，会让「市场总览明明取到了」也被一起回滚。

## 9. 非功能需求

### 9.1 可靠性

| 场景 | 行为 |
|---|---|
| 单个源超时/报错 | 记入 `errors`，该指标 `band = null`，显示「未获取」，模块剔除该项后重新归一 |
| 取数缺项 > 3 | 全局刷新放弃重算，保留上一份完整 `score.json` |
| `score.json` 缺失/损坏 | 主看板构建捕获异常，这一页显示「资产方向未生成 + 先跑 fetch/score」，其它页零影响 |
| 政策无 confirmed | 20% 权重重摊 + 顶部提示 + 参考值（斜纹/灰条/星号），合计不受影响 |
| BIS 不可达 | 本地利率表整表降级为一行错误提示，不影响任何分数 |
| 台湾央行抓不到 | 台湾整行缺席，不用其他口径顶 |
| 样本不足 | 技术因子不足 210 根不判定破位；序列不足 13 点不计算同比 |

### 9.2 性能

- 全量取数 ≤ 12 秒（实测 6.8s，6 并发）。
- 页面片段 ≤ 60 KB（实测 40.4 KB）；独立页 ≤ 120 KB。
- 页面无外部依赖：无 CDN、无字体、无 JS 框架、无网络请求，`file://` 直接可开。

### 9.3 可维护性

1. **资产顺序只有一份来源**：`score.py` 的 `ASSETS`。`GROUPS` 必须能按序展开成同一顺序，
   `build.py` 渲染前硬校验，不一致直接退出。三处写三份是这类模块的常见死法。
2. **两个出口一份渲染**：`render(embed=)` 被独立页与内嵌共用，只有页头不同。
   改渲染不会出现「独立页对、内嵌页错」。
3. **样式机械 scope**：内嵌时整份 CSS 经 `scope_css()` 加 `#pane14` 前缀，
   `:root`/`html`/`body` 映射到容器本身。**不做例外**——`.card`/`.tag`/`.note`/`.up`/`table`
   都是主看板在用的类名，漏一条就会把全站卡片圆角从 10px 改成 12px。
   验收动作固定：切页前后比对 `#pane0 .card` 的 `computedStyle.borderRadius` 仍为 10px。
4. **人写与机器写的文件严格分开**：`series.json`/`score.json` 可随时删掉重算；
   `policy_answers.json`/`notes.json` 丢了就找不回来。
5. **占位符替换用 `__XXX__` + `replace()`，不用 `%` 格式化**：正文里有「20%/30%」这种百分号，
   `%` 会把它当格式符（本地利率表那段踩过）。

### 9.4 合规

- 页脚固定三段（口径 / 限制 / 免责），不得删改。
- 不出现买卖建议、目标价、仓位建议、胜率。
- 政策条目只陈述政策与公开事实，不评价、不解读。
- 日期必须来自原始数据；查不到标「未获取」，不推算、不编造。

## 11. 已知边界与待确认

### 11.1 已知边界（当前实现的真实行为，不要当成 bug）

1. **利率路径不是 FedWatch**。用 2Y 收益率 20 日变化作代理，能反映「重新定价的方向与速度」，
   给不出「计价了多少 bp」。CME FedWatch 与 OIS 期货需付费/需 key。
2. **政策分完全依赖人工**。时效取决于填写频率；P4「财政与监管」当前为空（0.15 权重被重摊）。
3. **分位窗口固定 5 年**。制度突变后（如 2022 加息周期），「新常态」会被判成极端值，需人工识别。
4. **T4 市场宽度无源**，四个技术因子只有三个计分。
5. **技术模块分已不是「美股技术面」**。重构后它由全市场因子构成，14 类资产里亚太 5 个、
   商品 4 个，样本重心不在美股；要看美股技术面请单独看 SPY/QQQ/SOXX 三张卡。
6. **`as_of` 是打分日，不是数据日**。指标 `date` 与 `lag` 才是数据时效，页面三处都印了。
7. **`lag` 在打分时算一次**。页面放几天再看，「滞后 N 天」不会自动变大。
8. **资产卡的价格是最后交易日**，可能与「数据日」不同（周末、休市）。
9. **快照同一天覆盖**，不追加；跨资产比较要按 id 对齐，不能按位置。
10. **本地利率表不进分**，弹性 `e` 也不含本地项。这张表只回答「缺口有多大」，不补上。
