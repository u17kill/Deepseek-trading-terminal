## 0. 怎么用这份文档

### 0.1 一句话任务

做一个**「机构研报覆盖矩阵 + 主题卡片流」**的静态页面：纵向 5 个主题、横向 30 家机构，交叉成一个 150 格的矩阵，点格子能下钻到该机构在该主题下写的报告卡片。

### 0.2 阅读顺序

| 你只有 | 读这些节 |
|---|---|
| 5 分钟 | §0、§2、§6.1、§8 |
| 30 分钟（准备动手） | §3、§4、§5、§6、§7 |
| 要直接跑通 | 先把 **附录 A 的样例数据** 存成 JSON，再照 §4.5 的伪代码算统计，再照 §6 画 |

### 0.3 可直接粘给 ChatGPT 的系统提示

```
你要实现一个中文金融看板的单页模块，规格在附件 PRD 里。请严格遵守：
1. 交付单文件 HTML（CSS/JS 内联，数据用 <script id="DATA" type="application/json"> 内联），
   双击 file:// 打开即可用，不得依赖 fetch 或任何 CDN。
2. 所有统计数字必须在「构建期」算好并写进数据，前端只渲染、不重算（PRD §5）。
3. 数据必须过校验（PRD §4.3），错误级不通过就不许渲染。
4. 先只实现附录 A 的样例数据，把 §8 验收清单逐条跑通，再替换成完整 67 篇。
5. 不增功能：不加自动抓取、不加原文链接、不加图表、不加动画特效（PRD §2.2）。
```

### 0.4 三条不可违反的约束

1. **空格子必须留着。** 谁没覆盖哪个主题是这个页面的核心信息之一，隐藏空格等于把「覆盖 62/150」这个事实抹掉。
2. **统计只有一份来源。** 篇数、机构数、格子数、多空中性分布，全部在构建期算完写进数据；前端不许 `filter().length` 出一个新数字。
3. **立场标签（偏多/中性/偏空）不是一把跨主题的尺子。** 它只描述「该报告对它自己覆盖的对象」的方向，页面上不许汇总成任何「机构情绪指数」。

## 1. 背景与定位

终端里已经有两个「人」的页面，这一页是第三种问题：

| 页面 | 回答的问题 | 数据性质 |
|---|---|---|
| 最新风向 | **某一个人**最近说了什么 | 观点，可改口 |
| 机构研报（本页） | **一类机构对一类资产**的判断是什么 | 策展内容，可作废 |
| 大佬持仓（13F） | **账上**到底有什么 | 申报文件，有签字 |

差别落在「维度」上：人是一条条独立的观点，机构是有分工的——高盛不做印度光伏的尽调，KKR 不做 A 股行业配置。所以这一页**不能做成一条时间流**，必须做成矩阵：横向标出「谁在看」，纵向标出「看什么」。

一句话产品定义：

> 用一张 30 × 5 的覆盖矩阵回答「哪里有货」，用主题区块 + 卡片回答「说了什么」。

## 2. 目标与非目标

### 2.1 目标（每条都可验收）

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 一屏内看出 30 家机构 × 5 个主题的覆盖分布与缺口 | §8-B1、B2 |
| G2 | 三次点击内到达任意一份报告 | 点格子 → 滚动定位，§8-D1 |
| G3 | 任一数字（篇数/机构数/覆盖数）与数据文件一致 | §8-A6 |
| G4 | 数据文件是唯一内容来源，改 JSON 重开页面即生效 | §8-F1 |
| G5 | 900px 窄屏可用（矩阵不横向溢出、卡片单列） | §8-E4 |

### 2.2 非目标（附带理由，请勿"顺手加上"）

| 不做 | 理由 |
|---|---|
| **自动抓取 / 一次性抓到新报告** | 研报是策展内容。抓取只能拿到标题与摘要，论据要人写；做成「点一下就抓到新报告」的按钮，只会得到一堆没有论据的标题。页面上有一个「刷新研报」按钮（v1.28.0），但它只做**重读本地 JSON → 重新校验 → 重算统计 → 重建页面**，不联网 |
| **单篇原文链接** | `src` 是来源描述（机构 + 报告名/日期），不是 URL。公开报道大多转载且很快失效，留链接比留出处更容易骗人。 |
| 实时行情 / 股价 | 本页是观点库，不是行情页。 |
| 排序切换、筛选多选、收藏、已读 | 三个筛选维度（机构 × 主题 × 关键词）已经够用，再加会让「当前在看什么」不可解释。 |
| 汇总成「机构情绪指数」 | 见 §0.4 第 3 条。 |
| 图表（饼图/柱图/词云） | 矩阵本身就是图。再加图会与矩阵争夺同一个结论。 |
| 后端 / 数据库 | 纯静态，数据量 58 KB，没有写入需求。 |

## 3. 信息模型

### 3.1 三个实体

```
topics（主题，5 个）        insts（机构，30 家）
   │ id/name/desc/note         │ id/cn/en/grp/kind/focus
   └──────────┬────────────────┘
              │
        reports（报告，67 篇）
        id/inst/topic/scope/date/title/thesis/pts/tag/call/src
```

- 一篇报告 = 一个 `(机构, 主题)` 单元格的一份内容；**同一格可以有多篇**（实测 57 格 1 篇、5 格 2 篇）。
- 一个机构可以覆盖多个主题；一个主题有多家机构覆盖。
- 报告不挂 URL、不挂评级、不挂目标价字段——硬读数统一放在 `call` 里，用一句话表达。

### 3.2 主题 = 问题域，不是行业分类

| id | name（完整） | 短名（列头用） | desc | 覆盖什么 | 为什么单列 |
|---|---|---|---|---|---|
| `macro` | 宏观 · 各国经济 | 宏观 | 中 · 美 · 欧 · 日 · 印 | 增长、通胀、央行路径 | 所有资产判断的分母，辖区之间不可互相替代 |
| `market` | 市场 · 股市判断 | 市场 | 点位 · 盈利 · 风格 | 目标点位、盈利假设、配置与风格 | 唯一能给出「目标价」这类硬读数的地方 |
| `asset` | 特殊资产 · 配置 | 特殊资产 | 黄金 · 白银 · 债券 · 信用 | 贵金属、加密、久期、私募信贷 | 定价逻辑与股票不同，混进「市场」会被股票逻辑吞掉 |
| `ai` | AI 产业 | AI | 算力 · 电力 · 应用 | 资本开支、并网发电、芯片产能、应用变现 | 当前最大的单一变量，横跨股/债/商品三条线，必须独立 |
| `ind` | 其他产业 | 其他产业 | 医药 · 消费 · 制造 · 能源 | AI 之外的实体产业 | 剩下的一切，选股逻辑通常先看供给出清 |

**短名规则：** `name.split(" · ")[0]`。矩阵列头、导航胶囊、筛选状态条一律用短名——列宽只有 64px。
**`note` 字段：** 一段 30-60 字的方法论说明，渲染在主题区块标题下方，解释「为什么这几类放在一起」。不是可选装饰。

> 韩国与台湾不单列，由 `ai` 里的半导体产能口径承接（写在该主题的 `note` 里）。

### 3.3 机构 = 按国家/地区分组

30 家，分布：美国 13、中国 5、日本 3、英国 2、法国 2、加拿大 2、瑞士 1、德国 1、西班牙 1。

**硬规则：同一国家的机构必须连续出现，且整体按「北美 → 欧洲 → 亚太」排序，洲内按机构数量从多到少。** 违反即校验失败（§4.3 E9）——这条规则存在的唯一目的是防止手工插队插到别国中间，把「一个国家挨着排」这个可读性做废。

`grp` 白名单与中文名：

```python
GRP_CN = {"us":"美国","ca":"加拿大",
          "uk":"英国","fr":"法国","de":"德国","ch":"瑞士","es":"西班牙",
          "jp":"日本","cn":"中国"}
```

机构类型（`kind`）**不参与分组**，只在分组标题后面做一行统计（投行 7 · 资管 4 · 科技 2）。原因：补到 30 家后，同一类型里挤着七八个国家，类型这一维的解释力就掉下去了——瑞银和桑坦德都是「投行」，但一个用瑞士法郎思考、一个盯着西班牙和巴西。反过来国家这一维可以穷举：看到「日本 3 家」就知道这个市场只有三家在说话。

`kind` 约定集合与顺序：`("投行", "资管", "科技", "券商")`，不在此集合内只警告、不报错（未来可能出现「智库」「交易所」）。
`kind` 统计**仅在组内机构数 ≥ 4 时输出**，否则返回空串（两家时写「投行 2」是噪音）。

完整机构清单见 `research.json` 的 `insts`，字段含义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 短 slug，全表唯一，用作外键。`gs` / `jpm` / `cicc` |
| `cn` | string | 中文名，矩阵行首主标（12px）。中文名是索引 |
| `en` | string | 英文名，行首副标（9.5px 灰）。英文名是核对——看到 `RBC Capital Markets` 才知道是皇家银行的资本市场部而不是零售条线 |
| `grp` | string | 国家码，必须在 `GRP_CN` 里 |
| `kind` | string | 投行 / 资管 / 科技 / 券商 |
| `focus` | string | 覆盖重心，一句 8-16 字，例如「美股策略 · 宏观 · 大宗」。只在行首 `title` 悬浮提示里出现，不上屏 |

### 3.4 报告字段

| 字段 | 类型 | 必填 | 上限（实测） | 说明 |
|---|---|---|---|---|
| `id` | string | ✅ | — | 全局唯一。建议 `{inst}_{topic}_{scope_slug}`，同格第二篇加后缀 |
| `inst` | string | ✅ | — | 外键 → `insts[].id` |
| `topic` | string | ✅ | — | 外键 → `topics[].id` |
| `scope` | string | ✅ | 5 字 | 辖域，如「美国」「全球」「新兴市场」「日本」。渲染成浅灰胶囊 |
| `date` | string | ✅ | — | `YYYY-MM-DD`，必须是该报告的发布日，不是抓取日 |
| `title` | string | ✅ | 27 字 | 报告标题的中文改写，不是原文标题直译 |
| `thesis` | string | ✅ | **90 字（警告线）** | 一句话结论。见附录 B |
| `pts` | string[] | ✅ | 1-4 条，每条 110 字（警告线） | 论据。每条一句事实 + 一句判断 |
| `tag` | enum | ✅ | — | `bull` / `neutral` / `bear`，见下 |
| `call` | string | ✅ | 23 字 | **关键读数**，等宽字体单独一行。最容易被误读成建议，所以独立呈现 |
| `src` | string | ✅ | 30 字 | 来源描述：机构 + 报告名/日期 +（可选）作者 |

**`tag` 的语义边界（红线）：** 只表示**该报告对它自己覆盖对象**的方向。同一枚「偏多」在宏观格里指对风险资产，在黄金格里指对金价，在 AI 格里指对产业景气——三者不是一把尺子，**不许跨主题比较，不许汇总成指数**。

## 4. 数据契约

### 4.1 文件

- 路径：`data/research/research.json`，UTF-8，无 BOM，2 空格缩进（体积 58 KB，可读优先于紧凑）。
- 顶层 4 个字段：`as_of` / `window` / `topics` / `insts` / `reports`。
- **入库的是策展内容**：这个文件由人写，不由抓取程序写。

### 4.2 Schema

```json
{
  "as_of": "2026-11-03",
  "window": ["2026-09-01", "2026-11-02"],
  "topics": [
    {
      "id": "macro",
      "name": "宏观 · 各国经济",
      "desc": "中 · 美 · 欧 · 日 · 印",
      "note": "按辖区看增长、通胀与央行路径。韩国与台湾不单列，由 AI 产业里的半导体产能口径承接。"
    }
  ],
  "insts": [
    {
      "id": "gs",
      "cn": "高盛",
      "en": "Goldman Sachs",
      "grp": "us",
      "kind": "投行",
      "focus": "美股策略 · 宏观 · 大宗"
    }
  ],
  "reports": [
    {
      "id": "gs_macro_us",
      "inst": "gs",
      "topic": "macro",
      "scope": "美国",
      "date": "2026-10-30",
      "title": "盈利加速期结束，但还不是熊市",
      "thesis": "三季度 EPS 同比 33%，但「加速」已经到顶；2027 年增速降到 18%，仍足以支撑第四年两位数回报。",
      "pts": [
        "六成公司超预期一个标准差以上，中位数公司盈利增速 12%，低于二季度的 14%。",
```

### 4.3 校验规则

构建时执行，**错误级（E）任一命中即中止构建、不产出页面**；**警告级（W）只打印，不阻塞**。

| ID | 级别 | 判定条件 | 报错文案 |
|---|---|---|---|
| E1 | E | 文件不存在或解析为空 | `数据文件不存在或为空` |
| E2 | E | `topics` 为空 | `没有主题定义` |
| E3 | E | `insts` 为空 | `没有机构定义` |
| E4 | E | 主题 id 重复 | `主题 id 重复` |
| E5 | E | 机构 id 重复 | `机构 id 重复` |
| E6 | E | 主题缺 `id` / `name` / `desc` 任一 | `主题缺字段 {k}: {id}` |
| E7 | E | 机构缺 `id` / `cn` / `en` / `grp` 任一 | `机构缺字段 {k}: {id}` |
| E8 | E | `grp` 不在 `GRP_CN` | `机构分组未知: {id} → {grp}` |
| E9 | E | 同一国家被拆开（`grp` 序列里出现过又离开再出现） | `同一国家被拆开了: {g} 在 {last} 之后重新出现` |
| E10 | E | `window` 两项不是合法 ISO 日期 | `window 日期格式不对` |
| E11 | E | 报告 `id` 重复 | `报告 id 重复: {id}` |
| E12 | E | `topic` 外键不存在 | `{id} 的主题不存在: {topic}` |
| E13 | E | `inst` 外键不存在 | `{id} 的机构不存在: {inst}` |
| E14 | E | 报告缺 `title` / `thesis` / `scope` / `call` / `src` 任一 | `{id} 缺字段 {k}` |
| E15 | E | `tag` 不在 `bull/neutral/bear` | `{id} 的立场标签非法: {tag}` |
| E16 | E | `date` 不是合法 ISO 日期 | `{id} 的日期格式不对` |
| E17 | E | `pts` 条数不在 1-4 | `{id} 的要点数应为 1-4，实际 {n}` |
| W1 | W | `kind` 不在约定集合 | `机构类型不在约定集合内: {id} → {kind}` |
| W2 | W | `date` 落在 `window` 之外 | `{id} 的日期 {d} 在窗口 {lo}~{hi} 之外` |
| W3 | W | `thesis` 长度 > 90 | `{id} 的结论过长（{n} 字），卡片会被撑高` |
| W4 | W | 单条 `pts` > 110 字 | `{id} 第 {k} 条要点 {n} 字，偏长` |

设计意图：**上限是护栏，不是目标。** 实测 `thesis` 最长 66 字、`pts` 最长 76 字、`title` 最长 27 字——都没顶到线，因为线只用来拦住「写了三段话当结论」这种情况。三类阈值里只有 `pts` 条数是硬错误，因为 5 条要点会把三列网格里的一行拉高，连带整行卡片变形。

### 4.4 校验输出

```

  [WARN] xyz 的结论过长（104 字），卡片会被撑高
研报 67 篇 / 机构 30 家（覆盖 30）/ 主题 5 / 有稿单元格 62/150
  us   美国  13 家  投行 7 · 资管 4 · 科技 2
  ...
  macro        宏观 · 各国经济  19 篇  18 家  多/中/空 7/11/1
  ...
校验：0 错误，0 提示
```

`validate` 返回 `(errors, warnings)` 两个数组，构建脚本只判断 `len(errors)`。

### 4.5 统计计算伪代码（构建期，顺序不可调换）

```python
# 1. 全局排序：日期倒序；同日期按 id 倒序（保证「最新那篇」唯一且稳定）
reports = sorted(reports, key=lambda r: (r["date"], r["id"]), reverse=True)

# 2. 复位派生字段（幂等：同一份 dict 反复 build 结果一致）
for t in topics: t["reports"] = []; t["stat"] = {"bull":0,"neutral":0,"bear":0}; t["n"] = 0; t["n_inst"] = 0
for i in insts:  i["topics"]  = []; i["n"] = 0

# 3. 单次遍历填桶（顺序即为排序后的顺序，所以 topic.reports 与 inst.topics 都是「新→旧」）
for r in reports:
    t = tmap[r["topic"]]
    t["reports"].append(r["id"])
    t["stat"][r["tag"]] += 1
    t["n"] += 1
    if r["topic"] not in imap[r["inst"]]["topics"]:
        imap[r["inst"]]["topics"].append(r["topic"])   # 首次出现顺序 = 该机构最新的主题在最前
    imap[r["inst"]]["n"] += 1

# 4. 主题去重机构数：必须遍历 reports 而不是累加，因为同格可能多篇
for t in topics:
    t["n_inst"] = len({r["inst"] for r in reports if r["topic"] == t["id"]})

# 5. 分组：按 insts 原顺序走，首次遇到某 grp 就开一个新组
groups, seen = [], {}
for i in insts:
    g = i.get("grp", "us")
    if g not in seen:
        seen[g] = {"id": g, "name": GRP_CN.get(g, g), "insts": []}
        groups.append(seen[g])
    seen[g]["insts"].append(i)
for g in groups:
    g["kinds"] = kind_note(g["insts"])   # 组内 <4 家返回 ""
```

关键：**排序发生在统计之前。** 因此 `reports` 数组本身、`topics[].reports`、`insts[].topics` 三处都是「新 → 旧」。矩阵里「该格最新一篇的 `tag` 决定格子颜色」直接取 `cell[0].tag`，不需要前端再排序。

## 5. 派生统计字段（构建期产出，前端只读）

| 字段 | 类型 | 定义 |
|---|---|---|
| `as_of` | string | 数据快照日（≠ 最新报告日） |
| `window` | [string,string] | 收录窗口，显示用 |
| `topics[]` | array | 原数组，每项追加 `reports`（id 数组，新→旧）、`stat`、`n`、`n_inst` |
| `groups[]` | array | `{id, name, insts[], kinds}`，顺序 = 首次出现顺序 |
| `insts[]` | array | 原数组，每项追加 `topics`（首次出现顺序）、`n` |
| `reports[]` | array | 已排序的原数组 |
| `n_report` | int | `len(reports)` = 67 |
| `n_inst` | int | `len(insts)` = 30 |
| `n_inst_covered` | int | 至少有一篇报告的机构数 = 30 |
| `n_topic` | int | `len(topics)` = 5 |
| `n_group` | int | `len(groups)` = 9 |
| `n_cell` | int | 有稿单元格数 `len({(inst,topic)})` = 62 |
| `n_cell_all` | int | `n_inst * n_topic` = 150 |
| `stat` | object | 全量 `{bull, neutral, bear}` = 29 / 31 / 7 |

**为什么全部前置计算：** 页面上至少 7 处要显示这些数字（状态条 3 处、区块头 2 处、导航 6 处、矩阵列尾 30 处）。若前端各算一次，改口径时必然漏一处，最终文档与页面各说一套。此处沿用同项目「风向页」的做法：一份数字，一处产生。

**前端禁止出现**：`reports.filter(...).length` 用于任何展示性计数（筛选结果条数除外——那是「当前视图」的运行时状态，不是数据事实）。

## 7. 交互规格

### 7.1 三个状态变量

```js
let rQ = "";            // 搜索词（原始输入，比较时 trim + toLowerCase）
let rInst = "all";      // 机构筛选，"all" 或 insts[].id
let rTopic = "all";     // 主题筛选，"all" 或 topics[].id
```

**筛选结果 = 三者的交集（AND）**：

```js
reports.filter(r => {
  if (rInst !== "all" && r.inst !== rInst) return false;
  if (rTopic !== "all" && r.topic !== rTopic) return false;
  if (q) {
    const im = instOf(D, r.inst);
    const hay = [r.title, r.thesis, r.scope, r.call, (r.pts||[]).join(" "), im.cn, im.en]
                  .join(" ").toLowerCase();
    if (hay.indexOf(q) < 0) return false;
  }
  return true;
});
```

搜索覆盖面固定为 7 个字段（标题 / 结论 / 辖域 / 关键读数 / 论据全文 / 机构中文名 / 机构英文名）。**不含** `src`——来源是核对用的，不是检索词。

### 7.2 事件表

| # | 触发 | 行为 | 重绘 | 滚动 |
|---|---|---|---|---|
| D1 | 点**有稿**格子 | `rInst = data-inst`；`rTopic = data-topic` | 矩阵（选中态）+ 卡片 + 状态条 | 滚到 `#rc-{topic}`，并闪烁该区块 |
| D2 | 点**无稿**格子 | 无（`cursor:default`，不绑事件） | — | — |
| D3 | 点机构名 | 若 `rInst === 该机构` → `"all"`，否则设为该机构；**同时 `rTopic = "all"`** | 矩阵 + 卡片 + 状态条 | 滚到卡片区顶部 |
| D4 | 点导航胶囊 | `rTopic = 该项`（`all` 即全量） | 矩阵 + 导航 + 卡片 + 状态条 | 滚到对应区块（`all` → 卡片区顶部）及闪烁 |
| D5 | 输入搜索 | `rQ = 输入值` | **只重绘卡片 + 计数文本**；矩阵不动（保留选中态） | 不滚动 |
| D6 | 点「看全部」 | `rQ=""`、`rInst="all"`、`rTopic="all"`，**并清空输入框 DOM 值** | 矩阵 + 导航 + 卡片 + 状态条 | 不滚动 |
| D7 | 点状态胶囊的「清除」 | `rInst="all"`、`rTopic="all"`；**保留搜索词** | 矩阵 + 卡片 + 状态条 | 不滚动 |
| D8 | 首次加载 | 渲染全部 | 全部 | — |

D3 为什么要重置 `rTopic`：只按机构看时要的是「这家在五个主题下分别说了什么」，残留主题筛选会让人以为这家只覆盖了一个主题。

D5 为什么不重绘矩阵：边打字边重排矩阵会让光标所在的视觉位置不断跳；矩阵是「覆盖事实」，不随搜索变化。

### 7.3 高亮与动画

```css
@keyframes rflash{ 0%{background:#fff5db} 100%{background:transparent} }
.rcat.flash .rcat-h, .rcard.flash{ animation: rflash 1.6s ease-out }
```

滚动定位后：先 `classList.remove("flash")` → 读一次 `offsetWidth` 强制重排 → 加 `flash` → `1600ms+100ms` 后移除。**必须先移除再重排再加**，否则连续点同一区块不会重播动画。

滚动行为：`scrollIntoView({behavior:"smooth", block:"start"})`；区块需 `scroll-margin-top:16px`。

### 7.4 空态与边界

| 情况 | 表现 |
|---|---|
| 筛选后 0 篇 | 卡片区替换为虚线条：`当前筛选下没有报告。点「看全部」恢复全量。`（`看全部` 加粗，`44px` 内距，居中，`12.5px --ink3`）。**导航胶囊与矩阵仍在**——让人能看到自己是筛过头了，而不是以为没数据 |
| 某主题被筛空 | 该主题区块**整块不渲染**（不是渲染一个空区块） |
| `RPT` 为 `null`（数据缺失） | 页面不渲染，状态条显示「数据未就绪」；不抛异常、不留白屏半成品 |
| 数据校验有 E 级错误 | 构建阶段就中止，页面不产出（见 §4.3） |
| 格子里有 3 篇以上 | 显示数字，`title` 里全部列出；卡片按新→旧排列 |
| 同一格两篇同一天 | 按 `id` 倒序稳定排序，仍是确定顺序 |

### 7.5 可访问性

| 元素 | 要求 |
|---|---|
| 格子（有稿） | `<button>`，可 Tab 聚焦，Enter/Space 触发；`title` 给出该格全部标题 |
| 格子（无稿） | `<div>`，**不可聚焦**（没有行为的东西不该进 Tab 序列） |
| 机构名 | `<button>`，`title="{cn} · {en}｜{focus}"` |
| 导航胶囊 | `<button>`，选中项加 `aria-current="true"`（可增强） |
| 搜索框 | `autocomplete="off"`，`placeholder` 同时充当标签（本页空间紧张，不加可视 label） |
| 颜色 | 立场不**只**用颜色表达——胶囊里始终有「偏多/中性/偏空」文字；矩阵格是唯一例外，靠 `title` + 下钻补偿 |

## 附录 B · 内容撰写规范

这一页的说服力全在 `thesis` 和 `call` 两行，写法有硬要求。

### B.1 `thesis`（一句话结论，≤90 字）

| 反例 | 问题 | 正例 |
|---|---|---|
| 「我们认为市场短期仍有波动，中长期看好。」 | 没数字、没时点、不可反驳 | 「三季度 EPS 同比 33%，但加速已经到顶；2027 年增速降到 18%，仍足以支撑第四年两位数回报。」 |
| 「该机构对黄金持乐观态度。」 | 转述立场，没有理由 | 「实际利率见顶后金价中枢上移到 4200，央行购金是需求端最确定的一块。」 |
| 三段话压进一个字段 | 卡片被撑高，三列网格变形 | 拆成 1 句结论 + 2-3 条 `pts` |

规则：
1. 含**至少一个数字或明确时点**（`18%`、`12 月`、`2027 年`）。没有数字的判断无法核对。
2. 不写「我们认为」「我们维持」「看好/看空」这类评级套话——立场交给 `tag`。
3. 判断要有方向：读完后知道「比市场预期高还是低」。
4. 中文标点，不用 emoji，不用感叹号。

### B.2 `pts`（论据，1-4 条，每条 ≤110 字）

- 结构：**第 1 句事实（可核对）→ 第 2 句含义（为什么重要）**。
- 三条最合适：一条给分母（宏观/行业数据）、一条给结构（谁在贡献）、一条给风险（哪里会错）。
- 不重复 `thesis` 的话；不写免责声明。

### B.3 `call`（关键读数，≤23 字）

一个**可被后续验证对错**的读数：目标点位、增速、利率水平、时间点。「标普 500 目标 6800」「美联储 12 月 +25bp」「新增用电需求 40GW」。
反面：`看好`、`超配`、`中性偏多`——这些是立场不是读数，立场已经在 `tag` 里。

### B.4 `src`（来源，≤30 字）

`机构 + 报告名/日期 +（作者）`。**不写 URL**（见 §2.2）。若来自访谈而非报告，写「访谈」。

## 附录 C · 设计取舍与已知局限

1. **刷新按钮只重读本地文件。** 见 §2.2：它解决「改完 JSON 不必手工跑构建」，不解决「抓新研报」。
2. **没有单篇原文链接。** `src` 是出处不是链接；公开转载页失效快，留链比留出处更容易骗人。
3. **覆盖不均是有意的。** 大摩、小摩、中信建投在一格里有 2 篇，因为窗口内确实发了 2 篇；不为了格子整齐去删。空格多的机构（黑石、KKR、桥水）不是不重要，是它们本来就不发「对某个市场」的策略报告。
4. **标签不跨主题比较。** 见 §3.4 红线。
5. **矩阵是唯一没有文字标签表达颜色的地方。** 靠 `title` 与下钻补偿；这是密度换来的代价，接受。
6. **数据靠人写，脚本只校验。** 抓取能拿到标题，拿不到「论据」。所以本模块的自动化上限是「提醒你窗口里缺了哪几格」，不是「自动补稿」。
7. **150 格不用虚拟滚动。** 30 行 DOM + 5 列按钮约 330 个节点，首屏渲染 < 50ms，虚拟化只会引入滚动错位。

## 附录 D · 术语表

| 术语 | 含义 |
|---|---|
| 主题 | 问题域（宏观/市场/特殊资产/AI/其他产业），不是行业分类 |
| 格 / 单元格 | 一个 `(机构, 主题)` 组合；150 格中 62 格有稿 |
| 有稿 / 无稿 | 该格是否有至少一篇报告 |
| 覆盖 | `insts[].topics.length`，即某机构触及了几个主题 |
| 窗口 | `window`，报告日期允许的范围（实测 2026-09-01 ~ 2026-11-02） |
| 辖域 | `scope`，报告覆盖的地理/资产范围 |
| 立场标签 | `bull/neutral/bear` → 偏多/中性/偏空；**只对该报告自己的覆盖对象有效** |
| 关键读数 | `call`，最容易被误读成建议的硬读数，独立一行 |
| 策展内容 | 人写、入库、随版本更新的内容，区别于抓取流 |
| 下钻 | 从矩阵格子跳到对应主题区块的卡片 |

## 附录 E · 冲突时的优先级

1. §0.4 三条约束 > 一切。
2. 附录 A 的数字 > 正文举例的数字（正文里的 67/30/62 是完整数据，附录 A 是验收基准）。
3. 「不做什么」的清单（§2.2）优先于任何"更好的想法"。想加功能，先说明它替代了哪一条非目标。
