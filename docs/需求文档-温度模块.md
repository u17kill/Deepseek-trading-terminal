## 0. 一页速览

「温度」是顶部菜单第一层的第 4 个分组。它下面有六个页面，回答的是同一类问题：
**现在处在历史的什么位置、有多热、有多贵**。六个页面分别是：

| # | 页面 | `pane` | hash | 回答什么 | 最小可用数据 |
|---|---|---|---|---|---|
| 1 | 动能分析 | `pane1` | `#hot` | 这个指数现在有多热 | 8 只标的日线 |
| 2 | 估值分位 | `pane2` | `#val` | 现在有多贵（PE/PB 在历史上的分位） | 7 只标的的 PE 历史 |
| 3 | A股雷达 | `pane3` | `#senti` | 今天 A 股冷不冷（情绪周期） | 全市场涨跌家数、涨停跌停、连板、龙虎榜 |
| 4 | 美股雷达 | `pane4` | `#us` | 美股情绪与结构（八个模块） | CNN 情绪、四池行情、11 只行业 ETF |
| 5 | 港股全景 | `pane5` | `#hk` | 港股八块拼图，核心是沽空 | 三指数日线、112 只成分股、沽空、南向 |
| 6 | 亚太温度 | `pane6` | `#apac` | 日韩台印新五地的冷热与相对强弱 | 五地指数日线 + 两个基准 |

**三个必须先知道的结论**

1. **这一组不是「六个温度」**。前两页是一把尺子的两端（多热 / 多贵），后四页是同一把尺子
   在四个市场上的应用，其中 A 股雷达用的是另一套合成（情绪温度），不是这把尺子。
   §5 与 §5.5 的可比性矩阵说清了哪些数字能横着比、哪些绝对不能。
2. **六页各自独立取数、独立加锁、独立刷新**。没有「一键更新温度」这个按钮。
   其中「刷新动能」「刷新估值」会重建静态页，另外四个**只更新内存、不重建**
   ——按 F5 会回到构建时的那份快照。这条是现状，不是设计意图，已列为 Q1。
3. **判断文字是规则拼装的，不是人写的**。这一组六个页面里的结论句（「超跌但下跌还没止住」
   「七巨头比指数抗跌 X 个百分点」）全部由阈值规则在代码里拼出来，不由人撰写、不由模型生成。
   与看板里「市场总览的今日判断」「专家观点」那两处人工内容性质不同，见 §4.7。

## 1. 产品定位

### 1.1 这一组回答什么

一条判断链上有三个不同的问题，这一组只答后两个：

| 问题 | 由谁回答 | 性质 |
|---|---|---|
| 今天发生了什么 | 市场总览、市场新闻 | 事件 |
| **现在有多热 / 多贵 / 多极端** | **温度组（本模块）** | 描述统计 |
| 接下来往哪偏 | 资产方向 | 分层传导 |

这一组明确**不做预测**。动能分析页的页脚写着「本页为指标状态播报工具，不含任何买卖建议」，
这是整个模块的边界：所有数字都是「当前处在历史什么位置」的描述，不是信号。

### 1.2 六页各自的分工

- **动能分析（pane1）**：八个标的（A 股四只、美股四只）的复合读数。它是唯一把三个维度
  （位置 / 拥挤 / 动能）合成一个总分的页面，也是唯一带「分档检验」的页面——即用历史数据
  回头检验这个指标本身有没有用。
- **估值分位（pane2）**：七个标的的 PE/PB 分位。它与 pane1 共享「数据卡片」这一层视觉语言，
  但计算完全独立（不用日线，用估值序列）。它最重要的部分是「把两页放在一起看」——
  价格位置 × 估值分位，得出「跌了但没变便宜」这类判断。
- **A股雷达（pane3）**：不量指数冷热，量**赚钱效应**。涨跌家数、涨停跌停、连板高度、
  龙虎榜机构席位，最后合成一个 0~100 的情绪温度。它回答「今天做短线的人赚不赚钱」。
- **美股雷达（pane4）**：八个模块，其中恐惧贪婪指数（CNN）是外部现成口径，
  其余七块是自算。它同时承担「结构诊断」：防御 vs 进攻、Mag7 贡献、半导体相对强弱、
  52 周新高新低。
- **港股全景（pane5）**：八块，核心是沽空率——这是全项目唯一一个**官方口径**的情绪指标。
- **亚太温度（pane6）**：五个市场（日/韩/台/印/新）+ 恒指参照，只做位置、动能、
  相对强弱三件事。

### 1.3 与其它页的边界

| 相邻页面 | 边界 |
|---|---|
| 市场总览 | 那边给「今天市场怎么了」的事实与判断；这边给「在历史什么位置」的读数。两边的涨跌家数来自不同池子（市场总览是自选股与资产卡，这边是全市场），不要互相校验 |
| 资产方向 | 那边是四层判断摊到 14 类资产的方向；这边的位置/动能是「当期状态」，不是方向 |
| 当前持仓 | 那边回答「我拿的这些东西怎么样」；这边不涉及任何持仓 |

## 2. 范围

### 2.1 包含

1. 六个页面的完整渲染与交互（含每页独立的刷新按钮与状态条）。
2. 六个页面的取数、计算、落盘、缓存与降级。
3. 跨页共用的两个基础算子（滚动分位 `PR`、Wilder RSI），以及由它们派生的
   **位置分**与**动能分**——这两个数字在 A 股、港股、亚太、动能四页里含义相同（§5）。
4. 每页的「口径与边界」说明文字，且其中的数字必须由程序从本次结果生成，不允许写死。
5. 六份 JSON 的落盘与页面首屏数据注入（构建期烘焙）。

### 2.2 不包含（逐条给理由）

| 不做 | 理由 |
|---|---|
| 不做跨市场的统一「温度总分」 | A 股总分的 35% 是「成交额占两市比重」，港股没有可比的「两市」分母，亚太五地的成交量数据大面积缺失。硬凑一个总分，会让三页的「60 分」含义各不相同——这种跨页失真比少一个指标更危险 |
| 不做择时信号与买卖建议 | 样本内 IC 只有 0.02~0.08 量级（见 pane1 的 IC 列），不足以支撑交易信号 |
| 不做「跟着温度调仓」的组合建议 | 那是资产方向页与持仓页的职责，且需要仓位约束，不在本模块 |
| 不抓取新闻、不做事件归因 | 这一组只陈述读数，不解释原因。原因在市场新闻与专家观点 |
| 不做港股 / 亚太的行业板块热力 | 港股分类指数行情接口一律返回错误（清单有、行情无）；亚太五地拿不到统一口径的板块数据 |
| 不做港股个股估值分位 | 个股历史 PE 拿不到，「分位 = 与自己的历史比」这个定义在港股个股上无法成立 |
| 不做手机端专门的紧凑布局 | 六页在 620px 下能正常纵向排列（矩阵类表格横向滚动），但没有为手机重排信息层级 |

## 3. 页面结构与导航

### 3.1 导航位置

顶部菜单是两层结构（v1.49.0 起）：

```
第一层（胶囊）：  市场 · 观点 · 持仓 · 【温度】 · 工具
第二层（下划线）： 动能分析 · 估值分位 · A股雷达 · 美股雷达 · 港股全景 · 亚太温度
```

- 第一层「温度」被选中时，第二层显示这六个页签，其余九页签隐藏。
- 每个页签带 `data-p`（pane 编号）与 `data-g="temp"`。分组只写在 HTML 里，
  JS 从 DOM 推导，不存在第二份分组清单。
- 点第一层「温度」回到该组**上次看的那一页**（组内记忆），不是组内第一页。
- `#hot` / `#val` / `#senti` / `#us` / `#hk` / `#apac` 六个 hash 可直达，
  进入后第一层自动高亮「温度」。

### 3.2 每页的骨架

六页共用同一种骨架，实现时必须保持一致，否则切换页面时会有跳动：

```
<div class="sbar">                      ← 状态条：左侧 3~4 个关键读数，右侧状态文字 + 刷新按钮
  <div class="l">…</div>
  <div class="r"><span class="st" id="…St">…</span><button class="btn" id="…Btn">…</button></div>
</div>
<div id="…Body"></div>                  ← 正文由 JS 整块渲染
```

- pane1 / pane2 的正文是**静态 HTML 骨架 + JS 填充**（图表容器、表格容器预先存在）。
- pane3~pane6 的正文是**一个空容器，JS 一次性 innerHTML**（`renderSenti()` 等）。
  这两类写法必须照原样实现，混用会导致刷新后图表容器被重建、ECharts 实例失效。

### 3.3 响应式断点

| 宽度 | 行为 |
|---|---|
| ≥1200px | 卡片网格 5 列；`two` 双栏并排 |
| 900~1200px | 卡片网格 3 列；双栏仍并排但收窄 |
| <900px | 多数双栏改为单列 |
| <620px | 卡片单列；所有表格横向滚动，不折行 |

### 3.4 状态条的四态

每页状态条右侧的状态文字（`.st`）有四种状态，必须全部实现：

| 状态 | 触发 | 文案示例 |
|---|---|---|
| 待命 | 首屏 | 「点「刷新情绪」取最近一个收盘交易日」 |
| 进行中 | 请求发出后 | 「正在取市场总览 / 连板梯队 / 龙虎榜…」 |
| 成功 | 返回 ok | 「✅ 已更新 2026-11-06（耗时 12.3s）」 |
| 失败 | 抛错 | 「❌ 刷新失败：<原因>」 |

**`file://` 打开时必须拦住刷新**：直接双击 HTML 打开时没有后端，六个刷新按钮
（含右上角「更新数据」）全部要给出明确提示「当前是双击文件打开的（file://），
无法调用刷新接口。请访问 http://127.0.0.1:8765/」，而不是让 fetch 抛一个看不懂的错。

## 4. 功能需求

### 4.1 FR-1 动能分析（pane1）

#### 4.1.1 状态条

左侧：`标的 N 个 ｜ 最近交易日 YYYY-MM-DD ｜ 口径 位置 · 拥挤 · 动能（各 0–100 分）`。
N 为实际算出的标的数（当前 8）。日期取 `DATA[KEYS[0]].last.date`。

#### 4.1.2 八张标的卡片

八个标的是固定的，顺序即展示顺序：

| # | 卡片名 | 行情代理 | 备注 |
|---|---|---|---|
| 1 | 科创50 | 指数 | |
| 2 | 创业板指 | 指数 | |
| 3 | 沪深300 | 指数 | |
| 4 | 中证红利 | 指数 | |
| 5 | QQQ | ETF | |
| 6 | SOXX | ETF | |
| 7 | 标普500 | **IVV**（ETF 代理） | 卡片价格是 ETF 价，不是指数点位，必须标 `IVV` |
| 8 | 道琼斯 | **DIA**（ETF 代理） | 同上，必须标 `DIA` |

**代理标记不能省**：标普 500 的卡片价格约 660、道琼斯约 460，不标代理会被误读成
「标普 500 才 660 点」。代理标记的样式是 9.5px 灰字，紧跟价格右侧。

每张卡片从上到下：

1. 卡头：标的名称 + 收盘价（+ 代理标记）。
2. 大数字：总分（保留 1 位），颜色按档位取；右侧是档位标签（极端超卖/警戒超卖/正常/警戒超买/极端超买）。
3. 排名行：「截至 YYYY-MM-DD ｜ 历史排名：过去 N 个交易日里，约 X% 比今天更冷」。
   **这句话必须用实际数字拼**，不能写死 89。
4. 三根分项条：位置 / 拥挤 / 动能，每根带数值。
5. 三行读法：每根分项配一句人话（`SAY` 表，见 4.1.4）。
6. 一句话结论：「合起来看：<combo 结果>」（`combo` 12 条规则，见 4.1.5）。

#### 4.1.3 下方的固定说明区（内容全部写死在 HTML，不需要计算）

- **三条读法提示**（①②③）：分数是排名不是得分；高不代表要跌；必须看三个分项。
- **三个模块的含义**（位置/拥挤/动能），每块带一根全标的横向对比条。
- **同一个分数两副面孔**：40.9 分两种分项组合的对照示例（静态文案）。
- **分数的三档含义**与「为什么要转成分位」（静态文案）。
- **五个档位表**：每档的区间、标签、历史占比（按当前选中标的算）。表注要说明
  「占比极小的档位（如科创 50 的极端超卖只占 0.6%）样本只有个位数，那一档的统计结论不能用」。
- **历史读数与指数走势**双轴图：黑实线 = 复合读数（左轴 0–100），灰虚线 = 收盘价（右轴），
  下方五个颜色图例对应五档。可切换标的（tabs）。
- **分档检验表**：每档的交易日数、后续 5/20 日平均收益、20 日最深回撤 / 最高涨幅、20 日胜率。
  表注必须写「交易日数太小的档位没有统计意义，看方向别当结论」。
- **年度高低点对照**：每年收盘最高/最低那天的读数（检验指标认不认得顶底）。
- **极端状态事件**：连续 ≥3 日停在极端档的时段，列起止日、持续天数、峰值。
- **页脚**：样本区间、数据来源、已知局限、免责声明（见 4.1.6）。

#### 4.1.4 分项读法表（`SAY`，必须逐字实现）

| 位置 | ≤30 | 价格低于平均成本，但还没到极端 |
| 位置 | ≤70 | 价格大致贴着平均成本，不偏不倚 |
| 位置 | ≤90 | 价格明显高于平均成本 |
| 位置 | >90 | 价格冲到近一年最贵区，离平均成本很远 |
| 拥挤 | ≤15 | 交易极冷清：没什么人关注，波动也小 |
| 拥挤 | ≤35 | 交易偏清淡，注意力份额不高 |
| 拥挤 | ≤60 | 交易强度正常，跟平时差不多 |
| 拥挤 | ≤85 | 资金扎堆：成交占比和波动同时抬升 |
| 拥挤 | >85 | 交易非常激烈：成交占比高、上下剧烈震荡 |
| 动能 | ≤15 | 还在往下砸，而且速度不慢 |
| 动能 | ≤35 | 还在往下走，但力道在减弱 |
| 动能 | ≤65 | 基本走平，横着 |
| 动能 | ≤85 | 在往上走，力道不弱 |
| 动能 | >85 | 往上冲得很猛，还在加速 |

#### 4.1.5 组合判断的 12 条规则（`combo(p, c, m)`，顺序即优先级）

按顺序命中即返回，**顺序不能调换**（前面的规则更具体）：

| # | 条件 | 文案 |
|---|---|---|
| 1 | p≤30 且 m≤30 且 c≤40 | 跌得深、交易也冷清了、还在往下走 —— 超跌，但下跌还没止住 |
| 2 | p≤30 且 m≤30 且 c≥60 | 跌得深、交易却很激烈、还在往下走 —— 放量下跌，抛压在集中释放 |
| 3 | p≤30 且 m≤30 | 跌得深、还在往下走 —— 超跌，但下跌还没止住 |
| 4 | p≤30 且 c≤40 且 m≥60 | 跌得深、交易冷清、但下跌已经刹住 —— 底部区域常见的形态 |
| 5 | p≤30 且 m≥60 | 跌得深、但下跌已经刹住 —— 止跌迹象出现，还需后续确认 |
| 6 | p≤30 且 c≥60 | 跌得深，但交易非常激烈 —— 恐慌性放量杀跌，抛压在集中释放，常见于阶段性底部附近 |
| 7 | p≤30 且 m<60 | 价格已在历史低位区，但下跌劲头不强 —— 横着磨底，方向还没选出来 |
| 8 | p≥70 且 c≥60 且 m≥60 | 涨得多、交易火爆、还在加速 —— 过热，短期风险最大 |
| 9 | p≥70 且 m≤40 | 位置还很高但劲头没了 —— 强弩之末 |
| 10 | p≥70 且 c≤40 | 价格高但交易清淡 —— 缩量上行，缺后续动力 |
| 11 | p≥70 | 位置偏高，拥挤与动能都处在中间地带 —— 偏热但没有加速 |
| 12 | m≤15 且 p>30 | 位置不算极端，但在快速下滑 —— 下跌刚开始 |
| — | 以上都不匹配 | 没有明显极端信号，处在常态波动中 |

#### 4.1.6 页脚（必须由程序拼当前数字）

页脚要交代五件事：算法演进（为什么现在用 RSI6 + 风险调整动量，而不是 RSI 变化量）、
校准方式（每个标的用自身历史分布取分位，阈值不跨市场共用）、版本沿革、
已知局限（六条，含「美股样本只有约 3.6 年」「极端档样本偏少」「纯量价框架认不了缩量阴跌」）、
数据来源与免责声明。

**页脚里出现的样本数、起始日、标的数必须来自本次结果**，不允许写死。
当前实测的六个已知局限（原文即在页脚，实现时照抄并代入数字）：

1. 本指标刻画「当前处于历史什么位置」，是描述统计不是预测，高分之后指数仍可继续上涨
   （样本内复合指标 IC 仅 0.02~0.08 量级）。
2. 位置与动能的相关性高达 0.89~0.90——两者都是价格的衍生量。拥挤模块已改用资金面口径
   把相关性降到 0.33~0.36，但动能这一层无从解耦。
3. 拥挤模块改用占比与波动率后，与后续收益的 IC 由 0.08 降到 0.05 左右——
   这是拿独立性换可解释性的代价。
4. 极端档样本普遍偏少（科创 50 极端超卖仅占 0.6%），基于个位数样本的均值不具统计效力。
5. 纯量价框架无法识别「缩量阴跌型」底部——缓慢下跌不产生偏离，只产生深度。
6. 美股样本只有约 3.6 年（2023-03 起，914 个交易日），且 QQQ 在样本期内基本单边上行，
   分数分布严重向「正常」集中（86%），极端超买极少出现。

### 4.2 FR-2 估值分位（pane2）

#### 4.2.1 状态条

左侧：`估值标的 N 个 ｜ 数据截至 YYYY-MM-DD ｜ 口径 PE-TTM 分位（自算，与蛋卷历史百分位一致）`。

**这一行的「PE-TTM」是概称，不能当成事实**：页内有一只标的（SOXX）用的是前瞻 PE，
口径由每张卡片自己的 `basis` 字段驱动。状态条保持概称是为了不把行宽撑破，
真正的口径声明放在卡片角标与图表标题上（见 4.2.4）。

#### 4.2.2 「把两页放在一起看」（这一页最重要的模块）

对每个有估值数据的标的，把 **pane1 的位置分** 与 **pane2 的 PE 全历史分位** 拼在一张卡上：

- 短期位置（`s_pos`，0~100，越低越接近一年最低）
- PE 分位（`pos_all`，0~100%）
- 当前 PE
- 一句结论（9 种组合，见下表）

判定阈值：位置 ≤30 记「低」、≥70 记「高」，其余为「中」；PE 分位 ≤30 记「低」、≥70 记「高」，其余为「中」。

| 位置 | 估值 | 结论 | 颜色 |
|---|---|---|---|
| 低 | 低 | 价格跌到历史低位，估值也确实便宜了——杀估值比较彻底，中长期风险释放较充分 | 绿 |
| 低 | 高 | 价格跌到历史低位，但估值仍在高位——盈利下滑的速度比股价更快，跌了却没变便宜 | 红 |
| 低 | 中 | 价格跌到历史低位，估值却还在中位——股价跌了、盈利也同步下滑，所以没跌出便宜来 | 灰 |
| 高 | 高 | 价格和估值都在高位——双高，风险最大 | 红 |
| 高 | 低 | 价格在高位但估值不贵——盈利增长消化了涨幅，属于健康的高位 | 灰 |
| 高 | 中 | 价格在高位、估值在中位——涨得有盈利支撑，但价格本身已经不便宜 | 灰 |
| 中 | 低 | 价格在中位，估值偏便宜——没有明显泡沫，也没到被错杀的程度 | 灰 |
| 中 | 高 | 价格在中位，估值偏高——涨幅已由估值扩张承担，继续上行要靠盈利兑现 | 红 |
| 中 | 中 | 价格与估值都处在中间地带，没有明显偏向 | 灰 |

**缺数据的两种卡，文案必须不同**：

- 估值缺失（`missing: true`，如道琼斯）：「无可用估值口径，无法与价格位置对照。这不是漏配，
  是数据源不提供道指的 PE 历史——宁可空着，也不拿别的指数顶替。」
- 行情缺失：`<标的> 行情数据缺失`。

#### 4.2.3 估值卡片（七张）

每张卡：标的 + 口径角标（`PE-TTM` / `前瞻PE` / `不可得`）、当前值（大数字，颜色按分位）、
分位标签（很便宜/偏便宜/中性/偏贵/很贵）、三根窗口条（近 3 年 / 近 5 年 / 长期）、
PB 与历史中位与历史区间、一句结论、口径备注（若 `note` 存在）。

**长期窗口的标签必须按样本量决定**：`n ≥ 480` 显示「近 10 年」，否则「成立以来」。
科创 50 只有 356 个样本，所以它的第三根条必须写「成立以来」，写「近 10 年」就是错的。

道琼斯那张卡固定显示「这一格故意留空」，并给出两条替代路径：① 道指的价格位置看 pane1
（它不依赖盈利数据）；② 要看美股大盘估值用标普 500 的 PE 分位代替，但**不要用标普 500
的数值冒充道琼斯**。

#### 4.2.4 口径必须跟着 `basis` 走

这一页有 7 只标的、3 种口径，同一张表里并存。凡出现「PE」字样的地方全部要跟着 `basis` 变：

| 位置 | 规则 |
|---|---|
| 卡片角标 | `basis` 原值 |
| 图表标题 | `基础` 为 `PE-TTM` 时「PE 历史走势与指数价格」；`前瞻PE` 时「前瞻 PE 历史走势与指数价格」 |
| 三根窗口条的标签 | 「PE 分位」→「前瞻分位」 |
| 结论句 | 「的 PE 处于历史 X% 分位」→「的前瞻 PE 处于…」 |
| 表格「口径」列 | `basis` 原值 |
| 页脚 | 必须写明「前瞻 PE = 价格 ÷ 未来 12 个月共识 EPS，非 TTM，不可与 A 股 PE 横比」 |

**这是这一页最容易出的错**：只改标题不改结论，读者会以为 SOXX 的 11.69 是 TTM PE
（TTM 口径下半导体设备大概在 25~30 倍），差一倍以上。

#### 4.2.5 图表与表格

- **PE 双轴图**：左轴 PE、右轴指数收盘，三条水平虚线 = 历史 20% 分位 / 中位数 / 80% 分位。
  可切换标的。无数据（道琼斯）时图表区显示「无可用估值口径」而不是空白。
- **估值汇总表**：列 = 标的 / 口径 / 当前值 / 3 年分位 / 5 年分位 / 长期分位 / 历史中位 / 样本点。
- **表注**必须说明：分位为自算值，与数据源自带百分位口径一致、差异在四舍五入范围内；
  科创 50 的长期分位实为「成立以来」。

亚太的「极冷」是位置分位的档位。页面上不能混用同一套颜色语义来说这两件事。

#### 4.6.4 降级

| 情况 | 表现 |
|---|---|
| 某地日线取数失败 | 该地卡片缺失，其余四地照常；相对强弱表也相应少一行 |
| 恒指取数失败 | 参照条整条隐藏（`ref_src="cache"` 时用本地 CSV 兜底，仍失败才隐藏） |
| 基准缺失或过短（<150 根） | 该基准的相对强弱与曲线整块不显示 |
| 曲线点数不足（<20 点或基准缺失 >20%） | 曲线区显示「样本不足」，不画半条线 |

### 4.7 判断文字的边界（贯穿六页的硬约束）

这一组六页里，**所有结论句都是规则拼装的**。它们在代码里以阈值 + 模板字符串的形式存在，
不经过人、不经过模型。必须原样实现，理由有三：

1. 可复现：同一份数据任何人跑都得到同一句话。
2. 可审计：一句话背后是哪条阈值，翻代码就能找到（`verdict_text` / `gap_check` /
   `risk_list` / `next_day` / `combo` / `SAY`）。
3. 不会被误当成「人写的判断」：看板里真正由人写的部分是「市场总览的今日判断」
   与「专家观点」的要点，那两处有作者与日期。这一组没有作者——页脚必须写明
   「本页为市场情绪与结构的客观播报」。

**因此有一条硬约束**：不许在这一组里出现「建议」「可以买」「目标价」「看多/看空某标的」
这类词。允许出现的是「历史上这一档之后 20 日平均收益为 X%」这种描述统计。

## 5. 共用口径：那一把尺子

这一组六页里有四个页面（动能分析、港股全景、亚太温度、以及 A 股雷达的价格侧）
都在用同一套分位算法。**必须实现成一份代码，不能各页抄一遍**——抄一遍就会出现
「同一个恒指，港股页说位置 5.96，亚太页说 6.0」这种四舍五入不一致。

### 5.1 基础算子：滚动分位 `PR`

```
PR(x, w=250) = x.rolling(w, min_periods=175).rank(pct=True) × 100
```

- 窗口 250 个交易日，`min_periods = int(250 × 0.7) = 175`。
- `rank(pct=True)` 的分母**包含当期值本身**，与 pandas 默认口径一致。
- 含义：当前值在最近 250 个交易日中的百分位（0 = 最冷，100 = 最热）。
- **样本不足 175 个交易日的序列，PR 返回 NaN，该标的的分数为「—」，不填 0。**

### 5.2 位置分（`s_pos`）

```
bias20  = C / MA20 − 1                         偏离 20 日均线的幅度
bollpos = clip((C − (MA20 − 2·SD20)) / (4·SD20), 0, 1)   布林带内位置
dd250   = (C / rolling_max(C, 250, min_periods=120) − 1) × 100   距 250 日高点回撤

s_pos = 0.40 × PR(bias20) + 0.30 × PR(bollpos) + 0.30 × PR(dd250)
```

三项分别看短期偏离、波动带内位置、长周期回撤。**不能只留一项**：只留 bias20 会在
横盘时全部挤到 50 附近；只留 dd250 会把「创新高」和「刚从深跌里爬出来」混为一谈。

### 5.3 动能分（`s_mom`）

```
RSI6 = Wilder RSI，周期 6（ewm α = 1/6）
ra10 = (C / C[t−10] − 1) / (SD(daily_return, 20) × √10)      10 日风险调整收益

s_mom = 0.50 × RSI6 + 0.50 × PR(ra10)
```

**这里有过一次重要修正，实现时不要退回旧版**。初版用「RSI6 的 5 日变化量」与
「MACD 柱的 5 日变化量」，测的是加速度而非速度，且在极端低位有基数效应——
RSI 从 2.7 回到 30 就被记为「高动能」。改为当前的 RSI6 + 风险调整收益后，
同一天的动能从 89.7 降到 15.8。

### 5.4 拥挤分（`s_crowd`，仅动能分析页）

```
A 股：s_crowd = 0.50 × PR(amount / amt_all × 100) + 0.30 × PR(SD(ret, 20)) + 0.20 × PR(turnover)
美股：s_crowd = 0.50 × PR(amount / SPY_amount × 100) + 0.30 × PR(SD(ret, 20)) + 0.20 × PR(volume)
```

| 变量 | A 股 | 美股 |
|---|---|---|
| 成交额占比分母 | 沪深两市成交额之和 | SPY 成交额 |
| 换手率 | 真实换手率 | **成交量**（无换手率，作代理） |

**为什么是这三项**：这是独立性检验后的选择。原设计用「成交额 / 20 日均额」与「量价相关」，
它们与位置模块的相关性达 0.54~0.60，等于重复计算位置。改成成交额占比（相关性 0.26~0.29）
与波动率（−0.03~0.05）后，拥挤与位置的整体相关性从 0.63/0.58 降到 0.36/0.33。

**被明确剔除的指标：融资买入额占比。** 它与位置的相关性高达 0.64（杠杆资金天然追涨，
本质是价格的影子）。页面把它作为观察项显示（`lev` / `lev_pos` / `lev_date`），**不进分数**。

**降级口径**：当缺少全市场成交额序列（`amt_all` 有效率 < 80%）时，退回旧口径
（换手率 50% + 成交额/20日均额 30% + 量价相关 20%），并把 `crowd_mode` 标为 `legacy`。
页面必须显示这个标记，因为两种口径的分数不可比。

### 5.5 总分与分档（仅动能分析页）

```
raw   = 0.40 × s_pos + 0.35 × s_crowd + 0.25 × s_mom
score = raw.ewm(span=3, adjust=False).mean()
      ≡ score_t = 0.5 × raw_t + 0.5 × score_{t−1}
```

分档（左开右闭）：

| 区间 | 标签 | 颜色 |
|---|---|---|
| (−0.1, 15] | 极端超卖 | `#1f6feb` |
| (15, 30] | 警戒超卖 | `#6aa9f0` |
| (30, 70] | 正常 | `#b4b2a9` |
| (70, 85] | 警戒超买 | `#e08b3a` |
| (85, 100.1] | 极端超买 | `#d64545` |

**边界要精确**：30.0 归「警戒超卖」，30.1 才是「正常」。用 `<=` / `<` 写错会产生
「同一天在两张表里档位不同」的 bug。

### 5.6 可比性矩阵（这一节是整份文档里最该先读的）

这一组有五种 0~100 的数，长得像但含义不同。页面上必须能看出区别，文档里必须说死：

| 数字 | 出处 | 输入 | 能横比的范围 | **不能**与谁比 |
|---|---|---|---|---|
| 位置分 | 动能1 / 港股5 / 亚太6 | 价格自身的分布 | **四页通用**（同一个 62 是同一个含义） | — |
| 动能分 | 动能1 / 港股5 / 亚太6 | 价格自身的分布 | **四页通用** | — |
| 拥挤分 | 仅动能1 | 成交额占比 + 波动率 + 换手 | 仅 A 股四只之间、美股四只之间 | A 股与美股不能互比（分母不同：两市 vs SPY）；也不能只做四只之间的「谁更热」比较而不看分母 |
| 情绪温度 | 仅 A股雷达3 | 涨跌家数 + 涨停 + 跌停 | 只与**自己的历史**比 | 与位置分/动能分/港股热度/CNN 恐惧贪婪**全部不可比** |
| 热度 | 仅港股5 | 位置 + 动能 + 量能 | 只与**自己的历史**比 | 与 A 股总分不可比（权重虽同为 5:3:2，输入完全不同） |

**为什么必须写这一条**：A 股总分 60 分、港股热度 60 分、亚太位置 60 分，三个 60 表达的是
三件不同的事。如果实现时把它们画进同一张图，读者会立刻得出错误结论。当前实现的选择是
**各页各画、页内声明**，不允许跨页并列展示。

### 5.7 一个必须守住的显示纪律

所有分位类数字在页面上**保留 1 位小数**，所有百分比涨幅**保留 2 位**，
金额（成交额）按「亿 / 万亿 / 万美元」自动降档并保留 1~2 位。
空值统一显示「—」（不是 0，不是空白，不是 N/A）。这一条在六页里全部适用。

## 6. 各页专用算法

### 6.1 A 股情绪温度

```
温度 = 0.5 × 上涨家数占比
     + 0.3 × min(涨停家数, 100)
     + 0.2 × max(0, 100 − 跌停家数 × 10)
```

三个分项分别代表：普涨广度、赚钱效应强度、亏钱效应惩罚。结果 0~100。

分档（与 pane1 的档位**不是同一套语义**）：

| 区间 | 标签 | 颜色 |
|---|---|---|
| <20 | 冰点 | `#1f6feb` |
| <40 | 低温 | `#6aa9f0` |
| <60 | 中性 | `#b4b2a9` |
| <80 | 升温 | `#e08b3a` |
| ≤100 | 亢奋 | `#d64545` |

**温度只看赚钱效应，不看指数涨跌**：指数可能微跌而温度极低（个股普跌），
也可能指数微涨而温度不高（权重拉抬、个股分化）。页面上必须写明这一点。

### 6.2 连板梯队

- 取涨停天数 ≥1 的个股（上限 120 条），按「板数降序 + 换手率降序」排序。
- 明细只展示板数 ≥2 的样本，最多 14 只。
- 每只补：当日涨跌、换手率、成交额（亿）、20 日涨幅、60 日涨幅、是否一字（振幅 ≤1% 或换手 <2%）。
- 分布表：几板几只，按板数升序。
- **同一高度内按换手率降序**：换手最高的那只才是真正的风向标，放最前面。

### 6.3 复盘标的日的选择（这一条最容易做错）

```
若现在是交易日 15:05 之前 → 用上一交易日
否则 → 用当天
周末与节假日 → 用最近一个已收盘交易日
```

**为什么盘中不能用当天**：连板梯队与龙虎榜当日尚未定稿，用未完成的数据做复盘会给出
错误的温度（通常偏低，因为涨停家数还没走完）。实现在 `resolve_target()` 里，
优先走交易日历接口；日历接口异常时退化为「工作日近似」。

### 6.4 龙虎榜机构席位去重

同一只票会同时出现在「1 日榜」与「3 日榜」两行。规则：

1. 按代码去重；
2. 同时存在时**优先保留 `tdDays == 1`（1 日口径）**；
3. 去重后按机构净买入额排序，买入前 6 / 卖出前 6。

实测：40 行 → 37 只。不去重会让同一只票占两格，且合计金额重复计算。

### 6.5 美股四池定义

| 池 | 成分 | 实际只数 |
|---|---|---|
| 道指 | `us.DJI` | 30 |
| 标普500 | `us.SPX` | 503 |
| 纳指100 | `us.NDX` | 101 |
| 中概 | 中概股清单，**成交额 ≥ 500 万美元过滤** | 464 → 79 |

三者高度重叠（纳指与道指成分几乎全在标普内），去重后 **518 只**；加上中概后合计 595 只。

**中概过滤不可省**：不过滤则模块失效——全池涨幅第一的 `usSEII` 涨 100%、成交额 0、
市值 0，还混有大量认股权证。

### 6.6 港股热度

```
热度 = 0.50 × 位置分 + 0.30 × 动能分 + 0.20 × PR(amount / MA20(amount))
```

量能项是「成交额相对自身 20 日均额的倍数」再取 250 日分位。这是港股本地口径，
**不与 A 股总分的「成交额占两市比重」等价**。

三指数（恒指 / 恒生科技 / 国企指数）各算一套，互不相加。

### 6.7 港股涨跌榜门槛

成交额 ≥ **1000 万港币**。港股有大量成交额为 0 的仙股，不设门槛的话涨幅榜前排全是
0.01 元跳到 0.02 元的品种，看起来涨了 100%，实际一分钱都没成交。

### 6.8 港股沽空聚合

```
池内沽空率 = Σ(个股卖空金额) / Σ(个股成交额) × 100
```

- **金额加权，不是等权平均**：等权会被小盘股极端值带偏。
- 权重用当日成交额——它同时是 `ShortRatio` 的分母，用它聚合才与个股口径一致。
- 分档：≥30% / 10~30% / <10%（实测池内中位数约 23%，阈值设 10% 会让 95% 的成分股都「偏高」）。
- 基线：从 `short_archive.json` 取「今天之前」最近 20 个有效日的均值，**不含今天**。
- 覆盖判定：`cover = 成功批次 / 总批次`，`cover < 0.90` 判降级。

**为什么基线要自建归档**：`fund short` 的区间请求限频极严（当日快照三批连发全成功，
区间连发第三批只剩 2/10），硬拉 20 天不现实。归档与 F&G 存档同性质：**不可重建的累积资产**。

### 6.9 亚太五地的位置与动能

完全复用 §5.2 / §5.3 的公式，`PR` 窗口同为 250 日。因此「位置 62」在 A 股页、
港股页、亚太页是同一个含义——这是这一组里唯一真正跨页可比的数字（§5.6 节）。

**不合成总分**：A 股总分的 35% 来自「成交额占两市比重」，亚太拿不到该分母。
若按 0.40/0.25 归一再合成，会得到另一种刻度，页面上的「60 分」与 A 股页的「60 分」
不再是同一件事。

### 6.10 相对强弱的窗口对齐（这一条错了整块都是假的）

各市场交易日数不同：实测同一天，台湾 61 根回溯到 07-31，而标普500 61 根回溯到 08-06,
两边根本不是同一个时间窗。直接相减，算出的「超额」里有一半是窗口错位造成的。

实现规则：

1. 取目标市场的每个交易日，基准取**同一天**的收盘；对方休市则往前取最近一个有效收盘
   （`reindex(dates, method="ffill")`）。
2. 这样得到的是「同期表现差」，与谁先开市无关，不含隔夜效应。
3. 曲线取 **n+1 个点（n 个收益）**，保证曲线末值 = 表格里的「120 日超额」，
   两个模块不会互相打脸。
4. 表格同时给「本地 / 基准 / 超额」三个数，让读者能自己校验。

### 6.11 相关性矩阵

用共同交易日（inner join）后的日收益算 Pearson 相关系数，窗口 60 日。
各市场节假日不同，实际样本会少于 60 天，页面上必须显示实际样本天数与起止日期。

### 6.12 估值分位

- 自算，**不用数据源自带的分位**。
- 取当前值在过去 N 年周度样本中的百分位，同时给 3 年 / 5 年 / 长期三个窗口。
- 长期窗口的标签由样本量决定：`n ≥ 480` → 「近 10 年」，否则「成立以来」。
- 同时给 `min / max / median / p20 / p80`，用于画便宜线与偏贵线。

**双口径不能混**：

| 标的 | 口径 | 数据源 | 样本 |
|---|---|---|---|
| 科创50 / 创业板指 / 沪深300 / 中证红利 / QQQ / 标普500 | PE-TTM + PB | 蛋卷基金 `index_eva` | 周频，近 10 年 |
| SOXX | **前瞻 PE**（价格 ÷ 未来 12 个月共识 EPS） | History of Market（CC BY 4.0） | 周频，2016-10-31 起，581 点 |
| 道琼斯 | **不可得** | — | 无免费源提供该口径 |

道指不可得的原因必须原样保留在页面上：道指是价格加权指数，指数 PE 需按 30 只成分股
合计市值 ÷ 合计盈利另行汇总，蛋卷 / History of Market / westock 均不提供；**不建议用
其他指数的 PE 顶替**。

### 7.2 日期口径：这一组有四个不同的「今天」

这是最容易出错的区域，四个口径各有各的理由：

| 口径 | 用在哪 | 规则 |
|---|---|---|
| 复盘标的日 | A股雷达 | 盘中 15:05 前用上一交易日（§6.3） |
| 美股交易日 | 美股雷达 | 取成分股报价里 `time` 的最大值，不是本机日期 |
| 港股交易日 | 港股全景 | 取三指数日线的最后一天；时段跟数据日期走（§4.5.1） |
| 亚太交易日 | 亚太温度 | 取五地日线 `end` 的最大值 |

**统一原则：日期来自数据本身，不由程序按本机时钟推算。** 唯一例外是 A 股雷达的
「15:05 前用上一交易日」，那是业务规则不是日期推算。

### 7.3 时区

- 美股雷达需要美东时间判断盘中/收盘：优先 `zoneinfo("America/New_York")`，
  失败则 UTC−4 近似。
- CNN 恐惧贪婪的时间戳是 epoch 毫秒，转日期时用 UTC−4 近似美东，**只用于取日期**，
  不用于计算涨跌。

### 7.4 板块榜是「实时层」，不是复盘层

`sector ranking` 的实时榜**忽略 `--date` 参数**（实测三天返回值相同）。因此：

- 板块模块在页面上必须单独标注「实时层」，与复盘层分列；
- 不参与温度计算；
- 不与历史复盘数据混排（否则会出现「同一天的板块榜，第二天再看变了」的困惑）。

### 7.5 分批与限频

| 场景 | 约束 | 做法 |
|---|---|---|
| 港股沽空 | `fund short` 单次最多 10 个代码 | 112 只 → 12 批，批间隔 2 秒，每批重试 3 次；成功率 <90% 判降级 |
| 港股成分股报价 | 批量接口有上限 | 分批取，批间隔由 `wsfeed` 内部节流（约 1.2 秒） |
| 美股权重股 K 线 | 单只请求 | 串行取，失败沿用本地 CSV |
| 亚太五地 | 新浪单只 1000 根 | 串行，每地重试 3 次 |

**不要并发打同一个源**。这些接口的限频是按 IP 计的，并发只会让成功率更低。

### 7.6 缓存策略

| 数据 | 缓存位置 | 有效条件 | 用途 |
|---|---|---|---|
| A 股六日脉冲 | `data/senti/pulse_cache.json` | 按日期永久缓存（历史日不会变） | 减少 5 次取数 |
| 美股 F&G 存档 | `data/us_senti/fng_archive.json` | 按日期累积 | 攒够样本后补算分位 |
| 港股沽空基线 | `data/hk_senti/short_archive.json` | 按日期累积 | 20 日基线 |
| 恒指日线（亚太用） | `data/apac/hkHSI.csv` | 一次取 900 根 | 恒指参照条兜底 |
| 美股 ETF 日线 | `data/us/*.csv` | 每只一份 | K 线取数失败时兜底 |
| 动能历史结果 | `data/oos/result_v3_1.json` | 定稿快照 | `result_latest.json` 不存在时的兜底 |

**`fng_archive.json` 与 `short_archive.json` 是全项目仅有的两份不可重建资产**
（历史只存在于本地）。备份时优先保住这两个文件。

### 7.7 页面数据的注入方式

六个页面全部是**构建期烘焙**：`build_dashboard.py` 把六份 JSON 内联进单文件 HTML。
运行期点刷新只是把新数据塞进内存并重渲染，**不重新烘焙**。

后果（必须写进文档、也必须让用户知道）：

| 动作 | 内存 | 磁盘 json | 静态页 | 按 F5 之后 |
|---|---|---|---|---|
| 刷新动能 | 新 | 新 | **重建** | 新数据 |
| 刷新估值 | 新 | 新 | **重建** | 新数据 |
| 刷新情绪 | 新 | 新 | 不重建 | **回到构建时的旧快照** |
| 刷新美股 | 新 | 新 | 不重建 | 同上 |
| 刷新港股 | 新 | 新 | 不重建 | 同上 |
| 刷新亚太 | 新 | 新 | 不重建 | 同上 |
| 右上角「更新数据」 | 动能+估值+资产方向 | 新 | 重建 | 新数据（含四个页的 json 最新版） |

这是现状而非设计意图，见 §12 的 Q1。

### 7.8 性能预算

| 页 | 取数量级 | 说明 |
|---|---|---|
| 动能分析 | 约 11 秒 | 8 只标的日线 + 两只基准 + 市场背景，串行 |
| 估值分位 | 约 8 秒 | 7 只标的的 PE 序列，周频 |
| A股雷达 | 约 10~15 秒 | 6 次 westock 调用 |
| 美股雷达 | 约 20~40 秒 | 518 只成分股报价 + 中概 464 只 + 11 只 ETF + 7 只权重股 K 线 |
| 港股全景 | 约 40~60 秒 | 沽空 12 批占大头（批间隔 2 秒） |
| 亚太温度 | 约 5 秒（实测 4.8） | 五地各 1000 根 |
| 页面本身 | 单文件约 1.6 MB | 六页数据合计约 260 KB |

**六个刷新按钮必须各自加锁**：A 股盘中点更新时，美股频道不能被 429 挡掉。
锁的粒度是「每页一把」，不是全局一把；只有「更新数据」（全量）会去抢动能与估值两把锁。

## 八、接口契约

这一章是给实现方的硬约束。六个页面各自独立，**不共享刷新入口**——这是刻意设计：A 股盘中点「更新 A股雷达」时，美股频道不能被 429 挡掉，两条通道取的数据源、交易时段、耗时量级都不同。

### 8.1 通道总表

| 页 | 读（GET） | 刷（POST） | 落盘文件 | 刷完是否重建静态页 |
|---|---|---|---|---|
| 动能分析 | `/api/data` | `/api/momentum/refresh` | `data/oos/html_data.json` | **是** |
| 估值分位 | `/api/data` | `/api/valuation/refresh` | `data/oos/valuation.json` | **是** |
| A股雷达 | `/api/sentiment` | `/api/sentiment/refresh` | `data/senti/sentiment.json` | 否 |
| 美股雷达 | `/api/us_senti` | `/api/us_senti/refresh` | `data/us_senti/us_senti.json` | 否 |
| 港股全景 | `/api/hk_senti` | `/api/hk_senti/refresh` | `data/hk_senti/hk_senti.json` | 否 |
| 亚太温度 | `/api/apac` | `/api/apac/refresh` | `data/apac/apac.json` | 否 |

动能与估值共用同一个读接口 `/api/data`（两者是同一份指标管线的两个出口，且都参与构建期烘焙）；四个情绪页各有一个读接口。

**这个「是否重建」的差异是现状而不是设计野心**，见 §12 Q1 与 §7.7 的回退表。

### 8.2 六个刷新接口

统一约定：

- 方法 `POST`，**请求体为空**（不需要参数；不要在这几个接口上加 `date` 之类的入参——日期口径统一由后端按 §7.2 的四条规则从数据里取，不接受前端指定）。
- 成功 `200`，响应体含 `ok: true` 与 `elapsed`（秒，一位小数）。
- 已有同页任务在跑：`429`，`{"ok": false, "error": "<页名>正在更新中"}`。**不是排队，是直接拒**。
- 取数或计算抛异常：`500`，`{"ok": false, "error": "<异常文本>"}`。
- 所有响应头带 `Cache-Control: no-store, no-cache, must-revalidate`，`Content-Type: application/json; charset=utf-8`。

#### 8.2.1 `POST /api/momentum/refresh`

```json
{
  "ok": true,
  "data": { "科创50": { ... }, "创业板指": { ... }, "...": {} },
  "updated": "2026-11-22 12:43",
  "built": true,
  "build_ms": 2180,
  "elapsed": 11.4
}
```

- `data` 与 `/api/data` 的 `data` 字段同构（见 §9.1），直接喂给前端渲染函数，不需要二次整形。
- `built` 是布尔：`true` 表示静态页已重建，按 F5 拿到的是新数据；`false` 表示重建失败，`build_ms` 里放的是错误尾巴（**注意：失败时 `build_ms` 的类型从整数变成字符串**，前端必须容忍这个类型翻转，不能直接 `parseInt` 后当数字显示）。
- `updated` 是 `YYYY-MM-DD HH:MM` 本地时间。

#### 8.2.2 `POST /api/valuation/refresh`

```json
{
  "ok": true,
  "val": { "沪深300": { ... }, "...": {} },
  "updated": "2026-11-22 12:43",
  "built": true,
  "build_ms": 2180,
  "elapsed": 8.2
}
```

字段语义同上，`val` 与 `/api/data` 的 `val` 同构（§9.2）。

> 这两个接口都调 `rebuild_page()`，而 `rebuild_page()` 是一次 `subprocess` 调 `build_dashboard.py`（超时 180 秒）。所以**每次刷新都会重写整个 1.6 MB 的 HTML**。不要为了省时间把它降级成「只推前端」，那正是 §7.7 那张回退表要避免的坑。

#### 8.2.3 四个情绪页刷新

四个接口形状完全一致，只是顶层键名不同：

| 接口 | 顶层数据键 | 示例 |
|---|---|---|
| `/api/sentiment/refresh` | `senti` | `{"ok":true,"senti":{...},"elapsed":12.3}` |
| `/api/us_senti/refresh` | `us` | `{"ok":true,"us":{...},"elapsed":31.7}` |
| `/api/hk_senti/refresh` | `hk` | `{"ok":true,"hk":{...},"elapsed":48.9}` |
| `/api/apac/refresh` | `apac` | `{"ok":true,"apac":{...},"elapsed":4.8}` |

四个都**没有** `built` / `build_ms` 字段，因为它们不重建静态页。实现方如果自己重写这一层，允许加这两个字段，但要同步把 §7.7 那张表改掉——半套行为比现状更难排查。

### 8.3 错误码与前端必须做的事

| HTTP | 场景 | 前端行为 |
|---|---|---|
| 200 `ok:true` | 正常 | 用返回数据重渲染，按钮恢复，结果条写「已更新 · N.N 秒」 |
| 429 | 同页正在跑 | **按钮立即恢复可点**，结果条写「正在更新中，稍后再试」。不得进入 loading 死等 |
| 500 | 取数失败 | 按钮恢复，结果条写错误原文前 60 字。页面**保留旧数据不清空** |
| 网络中断 / fetch reject | 服务没起来 | 结果条写「连不上本地服务」，并提示重启命令 |

三条硬性要求：

1. **`finally` 里必须恢复按钮**。这个项目已经踩过：按钮文案与禁用态写在 `try` 成功分支里，`catch` 走完按钮一直灰着，用户以为页面卡死。
2. **拒绝时不得清空已有数据**。取数失败要显示旧数据 + 一条错误提示，而不是空白页。
3. **同一页按钮在请求期间必须 `disabled`**，否则用户连点两下，第二下拿到 429、第一下的结果回来时又覆盖按钮状态。

### 8.4 读接口

| 接口 | 响应 |
|---|---|
| `/api/data` | `{"ok":true,"data":{...},"val":{...},"updated":"YYYY-MM-DD HH:MM"}` |
| `/api/sentiment` | `{"ok":true,"senti":{...}}` |
| `/api/us_senti` | `{"ok":true,"us":{...}}` |
| `/api/hk_senti` | `{"ok":true,"hk":{...}}` |
| `/api/apac` | `{"ok":true,"apac":{...}}` |

读接口不做任何计算，直接返回服务内存里的那份；内存里的那份在服务启动时由 `load_cached()` 从磁盘读入。所以：

- 服务刚起来第一次读，拿到的是上一次落盘的快照。
- 在页面上点了刷新之后，内存更新，再 GET 拿到新的；但按 F5 拿到的是构建期烘焙进 HTML 的那份——除非刷新时重建过页面。

`/api/data` 的 `updated` 只反映**动能**那次更新的时间，估值有独立的 `val_updated` 但**没有在上面这个响应里暴露**。实现方若要展示估值数据时间，需要自己加字段或从 `val` 里各标的的 `detail.date` 取。

### 8.5 前端状态机

每个刷新按钮只有四态，实现方按此实现即可，不要自创第五态：

```
idle ──click──> running ──200──> idle（结果条：已更新 · N.N 秒）
                  │──429──> idle（结果条：正在更新中）
                  │──500──> idle（结果条：错误原文）
                  └──网络──> idle（结果条：连不上本地服务）
running 期间：disabled=true，文案换成「更新中…」
```

**改按钮文案必须同时改两处**：初始渲染的 `textContent`、以及异步函数 `finally` 里的恢复值。只改一处，第一次点完就会退回旧文案。这个坑项目里踩过一次（v1.49.1 把「更新风向」改名「更新观点」时验证过）。

### 8.6 并发与幂等

- 六个锁各自独立，粒度是「每页一把」。**不允许改成一把全局锁**：那会让 A 股盘中的情绪刷新把 40 秒的港股沽空一起堵住。
- 锁用 `acquire(blocking=False)`，抢不到就 429，**不排队**。理由：这几个操作都在 10~60 秒量级，排队会让用户以为点第二下没反应。
- 刷新本身是**非幂等**的（每次都会产生新的 `elapsed`、新的 `generated` 时间戳），但对数据的最终状态是收敛的——重复刷新不会让数据变差，只会多打几次数据源。所以不需要幂等键。
- 每页刷新都**先落盘再更新内存**（顺序不可颠倒）。反过来的话，内存更新成功、落盘失败，用户看到新数据、重启服务后变回旧数据，这种「幽灵回滚」比直接报错难查得多。

## 九、数据结构

六个 JSON 各自的形状。**字段名是实现契约**，改字段名等于改接口。所有文件 UTF-8、`ensure_ascii=False`、写入时 `newline="\n"`（Windows 下不加这条会把整篇 `\n` 翻成 `\r\n`，一次合并就让 git diff 变几千行）。

### 9.1 `data/oos/html_data.json` — 动能分析

顶层是 `{标的名: 标的对象}`，键就是八个标的的中文名，顺序即展示顺序：`科创50`、`创业板指`、`沪深300`、`中证红利`、`QQQ`、`SOXX`、`标普500`、`道琼斯`。

标的对象：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | str | 标的名，与键相同；跨页引用时用这个而不是键 |
| `last` | obj | 最新一日读数（见下） |
| `dist` | obj | 五档历史占比，`{档名: 百分比}`，五档合计 100 |
| `buckets` | arr | 分档前瞻统计，五项，顺序固定为极端超卖→警戒超卖→正常→警戒超买→极端超买 |
| `ic` | obj | 信息系数，`ic1/ic5/ic10/ic20` 与 `rsi1/rsi5/rsi10/rsi20` 各四个 |
| `dwell` | obj | 每档平均停留天数，`{档名: 天数}` |
| `events` | arr | 历史上的极端区间事件，每条 `{bk, from, to, days, peak}` |
| `year` | arr | 逐年高低点，每条 `{y, hi_d, hi_s, lo_d, lo_s}` |
| `series` | arr | 降采样后的走势，每条 `[日期, 分数, 收盘]` 三元组 |
| `start` / `end` | str | 样本起止日期（`YYYY-MM-DD`） |
| `n` | int | 样本交易日数 |
| `crowd_mode` | str | `v4` / `v4-us` / `legacy`，见下 |

`last` 的字段：

| 字段 | 说明 |
|---|---|
| `date` | 读数日期 |
| `score` | 总分 0~100，**3 日 EMA 后** |
| `close` | 当日收盘 |
| `rsi6` | 6 日 RSI |
| `bias20` | 20 日乖离率 % |
| `bollpos` | 布林带位置 0~100 |
| `s_pos` / `s_crowd` / `s_mom` | 三个分项得分 |
| `bk` | 当前分档名（五档之一） |
| `share` | 成交额占两市比重 % |
| `vol20` | 20 日量比 |
| `c_share` / `c_vol` / `c_turn` | 拥挤度三个分项的滚动分位 |
| `lev` / `lev_pos` / `lev_date` | 两融余额（万亿）、其 250 日分位、该读数日期 |

`crowd_mode` 是**算法降级的显式标记**，三档：

- `v4`：A 股口径，拥挤度 = `0.50·share + 0.30·vol + 0.20·turn`（换手来自两融/成交额合成）
- `v4-us`：美股口径，无两融，`turn` 项退化为成交额自身分位
- `legacy`：市场背景（两市成交额 + 两融）整体取不到，拥挤度只剩 `share` 与 `vol` 两项，页面必须打标

实现方**不得**把这个字段省掉：`legacy` 与 `v4` 的分项权重不同，混在一起横比是错的。

### 9.2 `data/oos/valuation.json` — 估值分位

顶层同样 `{标的名: 标的对象}`，八只，含 `道琼斯`（它是 `missing` 的占位对象）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` / `code` | str | 标的名与代码 |
| `basis` | str | `PE-TTM` / `前瞻PE` / `不可得`，**这是横比闸门** |
| `src` | str | 数据来源，必须在页面上显示 |
| `pe` / `pb` | arr | 周频序列，每条 `[日期, 值]` |
| `pe_stats` / `pb_stats` | obj 或 null | 统计块，无数据时为 `null` |
| `undl` | str | 底层指数（美股用 ETF 代理时要写清） |
| `note` | str | 口径注（如 SOXX 的前瞻 PE 说明） |
| `missing` / `reason` | bool / str | 不可得时置 `true` 并给理由 |
| `detail` | obj | 源站原始字段，只用于展示日期等 |

`pe_stats` 结构：

```json
{
  "cur": 13.53,
  "pos": {"3年": 63.5, "5年": 75.4, "10年": 66.9},
  "pos_all": 66.9,
  "min": 10.09, "max": 17.38, "median": 12.74,
  "p20": 11.74, "p80": 14.18,
  "n": 516
}
```

- `pos` 的三个窗口**不是**同一段样本的三种切法，是各自独立取窗口内分位。样本不足则该窗口为 `null` 或省略。
- `pos_all` 是全样本分位，页面在 10 年窗口不可用时降级用它。
- `basis` 不同的两只**不能横比**（SOXX 前瞻 PE 11.69 vs 沪深300 PE-TTM 13.53 比大小没有意义），§4.2 有九种组合的判断表。

### 9.3 `data/senti/sentiment.json` — A股雷达

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | str | **数据日期**，不是抓取日期 |
| `weekday` | str | 中文星期 |
| `generated` | str | 抓取时间 `YYYY-MM-DD HH:MM` |
| `month_end` / `week_end` | bool | 是否月末 / 周末（影响结论措辞与「下个交易日」推算） |
| `live_at` | str | 盘中实时层的时刻，`MM-DD HH:MM`；无实时层时为 `null` 或空 |
| `temp` / `temp_prev` / `temp_delta` | num | 情绪温度及与前值差 |
| `band` | str | 五档之一：冰点 / 低温 / 中性 / 升温 / 亢奋 |
| `pulse` | arr | 近 6 个交易日的脉搏，每条 `{up, lu, ld, up_pct, d, temp}` |
| `breadth` | obj | 市场宽度，见下 |
| `volume` | obj | `{amt, pct120, ma10, ma20}`，`amt` 单位万亿 |
| `index` | arr | 六只指数，每条 `{name, close, chg}` |
| `tech` | obj | 上证技术面 `{ma5, ma10, ma20, ma60, ma250, macd, rsi6}` |
| `val` | obj | `{pe, pb, pe_pct3, pe_pct5, pe_pct10}` |
| `ladder` | obj | 连板梯队 |
| `sector` | obj | 板块，`{industry: {...}, concept: {...}}` |
| `inst` | obj | 龙虎榜机构，`{lhb_count, inst_count, in: [...], out: [...]}` |
| `verdict` | obj | 结论文字 `{title, mood, trend, body}`，**规则拼装**（`verdict_text()`） |
| `gap` | obj | 差距检查 `{items: [{k, v, tone, note}]}`，`tone` ∈ `good/bad/flat` |
| `risks` | arr | 风险清单，每条 `{lv, t, b}`，`lv` ∈ 高/中/低 |
| `next` | obj | 次日推演 `{scenarios: [{tag, cond, b}]}` |

`breadth`：

```json
{"up": 758, "down": 4741, "flat": 80, "total": 5579,
 "up_pct": 13.59, "lu": 28, "ld": 2,
 "down_pct": 84.98, "ratio": 0.16,
 "nh20": 301, "nl20": 116, "nl120": 50, "nl250": 17}
```

`ladder`：`{count, max, ge2, samples: [{days, code, name, chg, turn, amt, chg20, chg60, yizi}]}`。`yizi` 是一字板标记，`days` 是连板天数。

`verdict` / `gap` / `risks` / `next` 四块全部由**规则拼装**，不是人写的（§4.7）：`verdict_text()` 按温度档位与涨跌差选措辞，`gap_check()` 按阈值给 `tone`，`risk_list()` 按连板结构与跌幅条件筛条目，`next_day()` 按当前读数匹配情景模板。

这意味着**实现方必须原样移植这四组阈值与模板字符串**，不能只搬数字自己写结论——同一份数据换个人写结论，页面就不再可复现。反过来，也不要在这四块里加任何原文没有的判断词（「建议」「值得关注」之类），§4.7 有硬约束。

### 9.4 `data/us_senti/us_senti.json` — 美股雷达

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | str | 数据日期（美东） |
| `generated` | str | 抓取时间（本地） |
| `et` | str | 同一时刻的美东时间，两个都要留 |
| `in_session` / `phase` | bool / str | 是否盘中 / 阶段文字 |
| `universe` | obj | `{main, cn_raw, cn_kept, total}` 四池口径 |
| `index` | arr | 四条 `{name, etf, px, chg, amt}` |
| `fng` | obj | CNN 恐惧贪婪，见下 |
| `gainers` / `losers` | arr | 各 10 条 |
| `sectors` | arr | 11 条，每条 `{code, name, px, chg, chg5, chg20, chg60, ytd, pos52, amt}` |
| `breadth` | obj | `{pools: [...], all: {...}}` |
| `defensive` | obj | 防御/进攻相对强弱 |
| `mag` | obj | Mag7 `{rows, avg, qqq}` |

`fng`：

```json
{"score": 9.7, "label": "极度恐惧", "raw_rating": "Extreme Fear",
 "ts": "...", "date": "2026-11-20",
 "prev_close": 18.68, "prev_week": 37.37, "prev_month": 28.74, "prev_year": 5.17,
 "parts": [{"k": "市场动能", "desc": "...", "score": 0.2, "rating": "extreme fear"}],
 "history": [[日期, 值], ...], "archive_days": 4}
```

- `parts` 七项，`score` 是 0~1 的**子指标归一值**，不是 0~100。页面上要乘 100 或单独画轨道，别和主分 `score`（0~100）混在一根轴上。
- `archive_days` 是本地归档的历史天数。CNN 只给一段近期序列，长历史靠自己攒，所以新部署的实例这里会是个小数字，页面要写清「本地归档 N 天」。

`universe` 的四个数**不是加总关系**：

- `main` 主池 518（道指 30 + 标普500 503 + 纳指100 101，去重后）
- `cn_raw` 中概原始 464 只，`cn_kept` 筛后保留 79 只（门槛见 §6.5，成交额 500 万美元）
- `total` 595 是**主池与中概的并集**，所以小于 `main + cn_kept`（597）——有 2 只中概同时在主池里

同理 `breadth.pools` 四个池的 `total` 相加是 713（30+503+101+79），远大于 595，因为一只股票可以同时属于道指与标普500。`breadth.all` 是四池去重后的并集。**页面上的「涨 131 / 跌 460」用的分母是 595，不是 713**——用错分母，宽度百分比会从 22.0% 算成 18.4%。

`defensive`：`{curve: [[日期, 防御, 进攻], ...], rel: {r5, r20, r60}, def_now, off_now, def5, off5, def20, off20}`。`rel` 是防御减进攻的超额，正数 = 防御占优。

`mag.rows`：`{code, name, chg, px, mcap, ytd, hi52, w, contrib}`。`w` 是权重 %，`contrib` 是对指数涨跌的贡献点数——`contrib` 之和应约等于 `avg`。

### 9.5 `data/hk_senti/hk_senti.json` — 港股全景

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` / `phase` / `updated` | str | 数据日期、时段（`盘中`/`收盘`）、更新时间 |
| `universe` | obj | `{total, pools: {...}}`，三指数并集去重 |
| `indices` | arr | 三条，每条含 `name/code/slug/close/chg/pos/mom/volx/volx_pr/heat/dd250/rsi6/n/start/end` |
| `breadth` | obj | `{all, pools}` |
| `gainers` / `losers` | arr | 各 10 条，带 `pools` 数组标明属于哪几个指数 |
| `short` | obj | 沽空，见下 |
| `south` | obj | 南向 `{date, top: [{code, name, amt}], total}` |
| `coef` | obj | AH 溢价或南向系数曲线 `{curve, last, chg}` |
| `valuation` | obj | 全样本估值分布 |
| `min_amt` | num | 涨跌榜成交额门槛，当前 `10000000` |

`indices[].heat` 是热度 0~100，`volx` 是量比、`volx_pr` 是其分位——**热度公式里用的是 `volx_pr` 而不是 `volx`**（§6.6）。

`short` 结构（**这是六页里最容易出坏状态的一块**）：

```json
{"date": "...", "ratio": null, "ratio20": 21.01, "base_n": 4,
 "med": null, "amt": 0, "n": 0, "hi_cnt": 0,
 "bins": {...}, "cover": 100.0, "degraded": false, "top": []}
```

- `ratio` = 当日沽空金额 / 当日成交额 ×100（%）；`ratio20` = 20 日基线中位数。
- `n` 是本次取到的沽空标的数；`cover` 是覆盖率 %，`100.0` 表示「分母取全了」。
- `degraded` 标记是否降级（批次失败、数据不全）。
- **坏状态**：`ratio=null, n=0, med=null, cover=100, degraded=false`。此时页面既不显示降级条、也没有数字，等于静默空转。这是 Q2。

### 9.6 `data/apac/apac.json` — 亚太温度

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` / `updated` / `elapsed` | | 数据日期、更新时间、取数耗时（秒） |
| `markets` | arr | 五地，每条见下 |
| `ref` | obj | 参照标的（恒指），**结构与 markets 元素相同** |
| `ref_src` | str | `live` / `cache`，标明参照是现取还是缓存 |
| `bench` | obj | 两条基准 `{SPX: {...}, CSI300: {...}}`，各含 `r5/r20/r60/r120` |
| `rs` | obj | 相对强弱表 `{SPX: [6 条], CSI300: [6 条]}` |
| `curves` | obj | 相对强弱曲线 `{SPX: {x: [...], y: [...]}, CSI300: {...}}` |
| `corr` | obj | 相关性 `{names, m, n, from, to}`，`m` 是方阵 |
| `sources` | obj | 五地数据来源与状态 |
| `horizons` | arr | `[5, 20, 60, 120]` 四个窗口，前端不得写死 |
| `notes` | arr | 口径说明，**直接渲染给用户看**，五条 |

`markets[]`：

```json
{"region": "日本", "name": "日经225", "sym": "NKY", "short": "日经",
 "close": 56436.65, "chg": -5.06,
 "pos": 1.2, "mom": 31.0, "label": "极冷",
 "rsi6": 23.1, "dd250": -22.0,
 "n": 1000, "start": "2022-11-08", "end": "2026-11-20",
 "r5": -7.7, "r20": -10.29, "r60": -14.51, "r120": -13.17}
```

`label` 五档：`极冷 / 偏冷 / 中性 / 偏热 / 极热`，**只由 `pos` 一个数切档**（≥85 极热 / ≥70 偏热 / >30 中性 / >15 偏冷 / 其余极冷），与 `mom` 无关（§4.6.3）。这一点容易搞错：页面上位置与动能并排显示，直觉会以为标签是两者的合成，实际不是。日经 `pos 1.2 / mom 31.0` 标「极冷」而不是「偏冷」，就是因为只看了 `pos`。

`rs[基准][]` 每条：`{short, region, r20: {loc, bench, ex}, r60: {...}, r120: {...}}`。`ex` = `loc − bench`，即超额。

> `curves` 的点数是 `n+1`（120 个交易日的历史需要 121 个点算首日收益）。前端画图时不要假设 `x.length === y.length - 1` 之外的形状。

## 十、非功能要求

### 10.1 性能

| 项 | 要求 | 依据 |
|---|---|---|
| 页面首屏可交互 | < 1.5 秒（本地服务） | 单文件 1.6 MB，本地磁盘读取 |
| 切页（点页签） | < 100 毫秒 | 六页 DOM 全在，纯 display 切换，不重新渲染 |
| 动能刷新 | < 15 秒 | 实测 11.4 秒 |
| 估值刷新 | < 12 秒 | 实测 8.2 秒 |
| A股雷达刷新 | < 20 秒 | 实测 10~15 秒 |
| 美股雷达刷新 | < 60 秒 | 实测 20~40 秒，595 只标的 |
| 港股全景刷新 | < 90 秒 | 实测 40~60 秒，沽空 12 批 |
| 亚太温度刷新 | < 10 秒 | 实测 4.8 秒 |

超时的处理：**不要给取数加更短的超时**。这些接口的耗时主要来自数据源限频（港股沽空批间隔 2 秒是硬要求，压到 1 秒会被封），砍超时只会让结果变成半份。宁可让用户等 60 秒看到完整数据，也不要 20 秒给一个残缺快照。

### 10.2 可视化

- 六页共用一套色板与卡片样式，**不得各自引入新配色**。
- 涨跌配色按本项目全局约定（注意与 A 股红涨绿跌相反，本项目统一用**涨绿跌红**，`--up` 绿、`--dn` 红）。新增元素必须复用已有 CSS 变量，不得硬编码色值。
- 三列等高 grid：卡片不足一行就留白，**不要改成自适应列宽**。这会影响同页其它组的高度对齐。
- 数值显示位数固定：分数 1 位小数、百分比 2 位、金额按亿/万亿自动换档。同一页内不得出现「31.2」和「31.20」混排。

### 10.3 可访问性

- 六个页签必须是真实可聚焦元素，支持键盘 Tab 与 Enter 切换。
- 分档颜色不能是唯一的信息载体：极端超买/超卖除颜色外必须有文字标签。
- 数字与单位之间不加空格，中文与数字之间按项目既有排版（`31.2 分`、`13.59%`）。

### 10.4 健壮性

- 任一数据源失败 → 该模块显示「未获取」+ 原因，**不影响同页其它模块**。
- 单页刷新失败 → 其它五页的数据与按钮状态不受影响（锁独立）。
- 服务重启后 → 六页都能从落盘文件恢复到上次状态，不需要重新抓取。
- `file://` 打开 → 必须能看六页的构建期快照，只是刷新按钮要给出明确拦截提示（§3）。

### 10.5 兼容性

- 目标浏览器：Chromium 内核（Edge / Chrome）近两年版本。不要求兼容 IE 或 Safari 旧版。
- 响应式四档断点见 §3.3。
- 不依赖任何 CDN 资源：图表、字体、图标全部内联。断网状态下页面必须完整可读。

## 十二、已知边界与待确认问题

这一章是这份文档最有价值的部分：把实现里已经存在、但没人明说过的东西摆到台面上。标注 **【现状】** 的是发现了但不打算在本轮改的，**【必须定】** 的是实现方动工前必须给答复的。

### Q1【必须定】四个页刷新后不重建静态页，F5 会回退

现状：`/api/momentum/refresh` 与 `/api/valuation/refresh` 调 `rebuild_page()`；`/api/sentiment/refresh`、`/api/us_senti/refresh`、`/api/hk_senti/refresh`、`/api/apac/refresh` 只更新内存与磁盘 json，**不重建**。

后果：用户在 A股雷达点了刷新、看到新数据，一按 F5 回到构建时（可能是几天前）的快照。这时页面上的日期会跳回去，用户会认为刷新是假的。

为什么当初没统一：四个情绪页的取数耗时 10~60 秒，重建页面要再跑一次 `build_dashboard.py`（约 2 秒）并重写 1.6 MB 文件。当时判断为「不值得」。但这个判断没有写进任何文档，只存在于代码注释之外。

**需要答复**：要么六页统一重建（推荐，代价是每页多 2 秒），要么六页统一不重建并在页面上明示「按 F5 会回到 N 月 N 日的快照」。**不要维持两种行为并存。**

### Q2【必须定】港股沽空存在静默空转状态

`short` 块在「12 个批次全部成功返回、但每批都没取到读数」时会产出：

```json
{"ratio": null, "med": null, "amt": 0, "n": 0, "cover": 100.0, "degraded": false}
```

`degraded=false` 意味着页面不显示降级提示；`ratio=null` 意味着不显示数字。结果就是沽空模块变成一块既没内容也没说明的空卡片。2026-11-23 的实际数据就是这一状态。

**需要答复**：`n==0` 时必须视为降级（`degraded=true`）并显示「本次未取到沽空读数」。这是一个 `if` 的改动，但它决定了用户看到的是「今天没有沽空」还是「今天没抓到」——两者含义完全相反。

### Q3【现状】板块实时榜忽略 `--date`

A股雷达的 `sector` 模块走的是实时行情接口，不接受历史日期参数。所以当 `date` 是 11-06 而 `generated` 是 11-08 时，情绪温度是 11-06 的、板块涨跌是抓取当下的。两者不是同一天的数据，但页面上并排显示。

**处理**：页面上板块模块必须单独标注「实时榜 · 抓取于 HH:MM」，不能让它继承页首的数据日期。

### Q4【现状】六个刷新按钮两种行为

同 Q1 的另一面。如果 Q1 决定统一，Q4 自动解决；如果决定保持现状，则必须在按钮 tooltip 里写清「本页刷新后按 F5 会回退」。

### Q5【现状】A股雷达数据停在 2026-11-06

`data/senti/sentiment.json` 的 `date=2026-11-06`、`generated=2026-11-08`，截至本轮（2026-11-23）已 17 天未更新。同一时间新闻页的 `news.json` 也只有 1.3 KB 的空壳。

用户已明确这块滞后处理，不属本轮范围。但**文档必须记这一笔**：一个模块连续 17 天不更新而页面没有任何「数据已过期」提示，是比算法错更严重的问题。建议实现方加一条通用规则：**`generated` 距今超过 3 个交易日，页首显示黄色过期条**。

### Q6【必须定】`legacy` 拥挤度口径要不要保留

`crowd_mode=legacy` 时拥挤度只剩两项（`share` + `vol`），权重和仍是 1.0 但含义变了。现在八个标的里没有一个是 `legacy`，说明市场背景取数一直成功。那这条降级路径是保留（作为兜底）还是删掉（简化）？

**建议保留但加页面标记**。理由是市场背景来自两融数据，两融数据源在月末/季末有过延迟的先例。

### Q7【现状】道琼斯估值永久不可得

`valuation.json` 里 `道琼斯` 是 `missing: true` 的占位，`basis: 不可得`。理由写在 `reason` 里（价格加权指数需按成分股合计市值÷合计盈利另行汇总，三个源都不提供）。

**处理**：不要为了「八只都齐」去估算一个数。缺一个格子比填一个错数好。页面上该格显示「不可得」+ 悬停看理由。

### Q8【现状】亚太不合成总分

亚太页只有 `pos` 与 `mom` 两个分项，没有合成 0~100 的总分。原因写在 `notes` 里：缺成交额占比这一项，合成出来是另一种刻度，和另外五页的 `score` 不可比。

**处理**：保持不合成。但要确保 `label`（极冷~极热）**不被误读为**与动能页的分档同义——两者用了不同的切分依据。页面需要在标签旁加口径说明。

### Q9【现状】SOXX 用前瞻 PE，与其余七只不可横比

`basis: 前瞻PE`（价格 ÷ 未来 12 个月共识 EPS），其余是 `PE-TTM`。前瞻 PE 系统性低于 TTM，所以「SOXX 11.69 比沪深300 13.53 便宜」是错的结论。

**处理**：`note` 字段已有说明，页面须在 SOXX 卡片上显式标「前瞻」二字，并且在任何横比视图中把它单独分栏。

### Q10【必须定】`build_ms` 失败时类型从 int 变 str

`/api/momentum/refresh` 与 `/api/valuation/refresh` 的 `build_ms`：成功是整数毫秒，失败是错误文本。这是类型不稳定，前端若按数字解析会显示 `NaN` 或抛错。

**建议**：拆成 `build_ms: int|null` 与 `build_error: str|null` 两个字段。若维持现状，前端必须显式判类型。

**验收**：AC-21~AC-28。同时必须在 M2 结束前给出 Q1 的决策，否则 AC-24 无法定稿。

科创50 的三个分项：`s_pos 36.08`、`s_crowd 81.52`、`s_mom 46.27`，`crowd_mode=v4`，`lev 8.8`（万亿，2026-11-05）。

手算原始分：`0.40×36.08 + 0.35×81.52 + 0.25×46.27 = 14.432 + 28.532 + 11.569 = 54.53`。

但页面显示的是 `score 57.0`，**差 2.5 分**。原因是 `score` 是原始分的 3 日 EMA（`raw.ewm(span=3, adjust=False)`），前两日原始分分别是 63.79（11-19）与 56.78（11-18），把当日拉高了。用同一份数据复算可得 EMA 尾部 `53.58 → 53.82 → 55.30 → 59.54 → 57.04`。

**这条要特别提醒实现方**：如果照 `0.40/0.35/0.25` 直接算完就上屏，会得到 54.5 而不是页面上的 57.0，然后误以为算法抄错了。EMA 是**必须**的一步，不是可选平滑——它让分数不会因为单日成交额异动而跳变（11-19 到 11-20 原始分从 63.79 掉到 54.53，EMA 只从 59.54 到 57.04）。

反过来说，验收时也不能拿「手工加权 == 页面分数」当断言，两者本来就不等。
