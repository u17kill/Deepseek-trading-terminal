> **对应实现基线**：v1.50.0（2026-11-24）　**模块起始版本**：v1.8.0

## 0. 一页速览

| 项 | 结论 |
|---|---|
| 这一页回答什么 | 「今天发生了什么」——一句话判断 + 全市场读数 + 我的持仓今天怎么样 |
| 页面位置 | 第一个页签（默认落地页），`#market` 可直达 |
| 三个区块 | ① 今日市场（人写判断）② 指数与大类资产（可增删的 28 张卡）③ 自选股（双视图：市场×板块 / 地区×风格） |
| 数据源个数 | 6 类：腾讯 westock、OKX、新浪 gi、日本财务省 CSV、雅虎 chart、本地持仓本子 |
| 外部依赖 | 一个本地 HTTP 服务（默认 8765）+ 一个构建脚本；无数据库、无前端框架、无 CDN |
| 最大风险 | **混批取数会静默丢品种**；**代码推导猜错会显示成另一只产品**；**判断文字跨日不失效会被当当日结论** |
| 明确不做 | 不做择时信号、不做买卖建议、不自动推荐标的、不做逐笔实时、不做回测 |

## 1. 产品定位

### 1.1 三段的职责，一句话各自说清

| 区块 | 回答的问题 | 谁产生内容 | 更新方式 |
|---|---|---|---|
| ① 今日市场 | 今天该怎么说？ | **人写**（`brief.json`） | 收盘后由任务写入；页面只渲染，不生成 |
| ② 指数与大类资产 | 全市场现在什么位置？ | 程序取数 | 「刷新行情」或定时任务重取 |
| ③ 自选股 | 我关注的 / 我持有的，今天怎么样？ | 一半手动、一半镜像持仓本 | 手动视图由用户维护；镜像视图随持仓与行情自动同步 |

### 1.2 与相邻页签的分工（避免重复建设）

| 页签 | 与市场总览的边界 |
|---|---|
| 资产方向（第 2 页） | 给「未来 1~6 个月往哪偏」的方向判断；市场总览只讲「今天发生了什么」，不预测 |
| 动能分析 / 估值分位（第 9、10 页） | 单标的的深度读数（位置、拥挤、分位）；市场总览只给当日涨跌与形状 |
| 当前持仓（第 8 页） | 持仓的编辑面板；市场总览的「地区 × 风格」是它的**只读镜像**，改不了原物 |
| 市场新闻 / 最新风向 | 解释「为什么」；市场总览不解释，只陈述读数 |

**一句话概括**：市场总览是一张「今天的仪表盘」——左边一句人写的判断，中间一片全市场读数，
下面一张自己持仓与关注标的的当天分布图。它不做预测，也不给动作。

## 2. 范围

### 2.1 本模块包含

1. 三段式页面的完整渲染（含空态、降级态、加载态）。
2. 资产清单的增、删、排序、按品种筛选、按关键字本地过滤。
3. 资产搜索（指数 / ETF / 期货 / 外汇 / 债券收益率 / 加密），带别名与口径提示。
4. 六类数据源的取数、批量分派、节流、并发与失败降级。
5. 自选股的批量导入、板块归类、拖动改归类、列序调整。
6. 卫星仓镜像：代码推导、行情双通道、未接入与取数失败两种灰态、脏标记。
7. 六个后端接口与两把并发锁。
8. 页面配置（`config.json`）与行情缓存（`market.json`）的分离持久化。

### 2.2 本模块不包含（且不得顺手加上）

| 不做 | 理由 |
|---|---|
| 生成判断文字 | 判断的价值在「知道自己在说什么」；模板拼出来的话不承担后果 |
| 买卖建议 / 目标价 / 仓位建议 | 合规定位：本页只陈述读数 |
| 自动推荐标的或打分排序 | 那会变成「选股器」，与「今天发生了什么」是两种产品 |
| 逐笔（tick）实时行情 | 现有源是分钟级；标称「实时」会误导 |
| 回测与命中率统计 | 后置项，不在本模块 |
| 在镜像视图里直接编辑持仓 | 镜像改不了原物，必须回「当前持仓」页 |
| 自建行业分类体系之外的智能分类 | 行业归类由本终端维护，认不出落「未分类」，**不猜** |

### 3.4 视觉与文案硬要求

1. **涨绿跌红**（欧美习惯，覆盖 A 股默认的红涨绿跌）：涨 `#3b6d11`、跌 `#a32d2d`。

4. 空态文案必须说清「为什么空」与「怎么让它不空」，不能只写「暂无数据」。

## 4. 功能需求

### FR-1 今日市场（判断卡）

**输入**：`data/market/brief.json` 与 `market.date`。

**行为**：

1. 若 `brief.headline` 为空 → 整卡替换为空态：
   > 今日判断尚未生成。这一段由收盘后的定时任务读取当日快照写成，写入 `data/market/brief.json`
   > 后刷新页面即出现。在它生成之前，下面两个模块的读数照常可用——判断可以晚到，数字不能编。
2. 定调标签三色：`tone=risk` → 红底「风险」类；`tone=calm` → 绿底；其余 → 暖黄底。
   标签文字取 `verdict`（如「芯片崩塌·A股独立」）。右侧可带 `mood`（如「分化」），前缀写「风险偏好」。
3. 标题：`headline`，允许内嵌 `<span class="u">`（绿）/`<span class="d">`（红）着色涨跌数字。
4. 导语：`lead`，2~3 行。
5. 要点：`points[]`，编号 `01…0N`，每条 **必须带数字**；建议 5 条。
6. 卡尾两个信息：
   - 「数据截至 {as_of} 收盘」（无论是否过期都这么写，**不在这里重复长句**，见第 8 条）。
   - 「判断生成 {generated}」。
   - 右端「不构成投资建议」。
7. **判断过期时，正文顶部出一整块说明**（v1.50.0 起；此前只有卡尾一行 11px 褐字，
   实测没人读到，于是「点更新数据左边不动」被反复当成刷新故障）：
   > **这段判断写于 {as_of} 收盘，行情已经到 {date}。**
   > 刷新只搬数字、不写文字——所以右边读数会动，左边这段结论不动。
   > 中间几个交易日的判断还没人写，读数可用，结论请按此打折看。
   底色 `#fdf8e9`、左边框 3px `#c9a227`、圆角 7px。**暖色不用红**——数据没错，
   只是这一交易日的文字还没写。
8. 页头右侧：「数据截至 {date}　·　刷新于 {updated}（{elapsed} 秒）」；跨日时追加
   「判断停留在 {as_of}」。**两个日期必须同时出现**——只写「数据已跨日」会被读成
   「行情是旧的」，而事实相反（行情新、判断旧），历史上因此被误报为刷新故障。
   同一行右端跟一个「重读判断」按钮，只重读 `brief.json`、不取行情（见 §刷新行为）。
   点击后按钮自报结果：换成新版写「已换到 {as_of}」，文件没变写**「文件仍是 {as_of}」**——
   不许装成刷新成功。

**边界**：

- `brief.json` 缺失 / 解析失败 → 与「未生成」同态，不报错。
- `stale` 由后端计算（`as_of != date`），前端不得自行推断。

### FR-2 关键读数栏

固定 14 个名称，按下列顺序取 `assets[].name` 精确匹配，缺哪个就跳过哪个（不占位、不补 0）：

```
上证指数 / 沪深300 / 恒生指数 / 标普500 / 纳斯达克100 / 费城半导体 /
日经225 / 韩国 KOSPI / 台湾加权 / 印度 SENSEX /
COMEX 黄金 / WTI 原油 / 美元指数 / 比特币
```

- 布局两列；**按三组分隔**（A股+港股+美股 / 亚太 / 商品+外汇+加密），组间各插一条跨列分隔线。
  v1.50.0 之前写死「第 5 项、第 9 项之后」，加一个品种就得重数一遍，且放错位置不报错。
- 数值：`price ≥ 1000` 用千分位、无小数；否则 2 位小数。涨跌幅 2 位小数、带符号。
- 全缺时显示「暂无资产数据」。
- 栏底固定脚注（口径，不能省）：
  > 美股口径：标普=IVV、道指=DIA、费半=SOXX 均为 ETF 价格（不是指数点位）；
  > 纳指100=NQ 期货连续合约。与「指数与大类资产」一栏同源。
  写这一句是因为「费城半导体」给的是 SOXX 的 123.40，而费半指数本身在 5000 点量级，
  不标注会被读成指数点位。

> 实现注意：这里是**按显示名匹配**，不是按代码。改资产名会让关键读数静默落空，
> 因此改名要同时改这一份清单（或把匹配改为 `code`，但需同步改验收）。

### FR-3 资产清单

#### FR-3.1 卡片字段

| 位置 | 内容 | 规则 |
|---|---|---|
| 左上 | 名称 | 取配置名，不用数据源返回名（源名长达「标普500 ETF-iShares」） |
| 名称下 | 代码 | 等宽 10px，灰 |
| 中部 | 现价 | 债券 3 位小数；外汇且价 < 20 时 4 位；其余 2 位；≥10000 用千分位 |
| 现价下左 | 涨跌 | 普通品种 `+1.23%`；债券 `+1.2bp`（>0 才加正号） |
| 现价下右 | 来源角标 | `SRC_LABEL` 覆盖名，或 `OKX` / `20D` / `UST 11-06` 这类口径标签 |
| 底部 | 迷你图 | 高 26px，宽自适应，抽稀后 ≤140 点 |
| 右上 | 删除按钮 | 悬停显现，点击需确认 |

**单位口径（最易错）**：

| 品种 | `price` 含义 | `chg` 含义 | 展示 |
|---|---|---|---|
| `eq` / `fu` / `fx` / `gi` / `cr` | 价格 | 百分比（%） | `+1.23%` |
| `bd`（债券收益率） | 收益率百分数（4.86 表示 4.86%） | **基点 bp**（0.01 个百分点） | `4.860 %` + `+1.2bp` |

#### FR-3.2 筛选与本地过滤

- 六个 chip：全部 / 股指 / 商品 / 外汇 / 利率 / 加密，计数来自 `counts`。
- 选中 chip 后按 `cls` 过滤；搜索框同时做**本地**名称与代码子串过滤（不区分大小写）。
- 两者叠加（AND）。无结果时显示一行提示，不显示空网格。

#### FR-3.3 搜索添加

- 输入 1 个字符即触发，**380ms 防抖**；`GET /api/market/search?kind=asset&q=…`。
- 下拉每项三列：名称 / 代码 / 口径提示（hint）。
- 点击添加：先 `GET /api/market/config` 取全量配置 → 查重 → 追加
  `{kind, code, name, cls=mClsOf(kind)}` → `POST /api/market/config` → **触发一次全量刷新**。
- 别名表（必须实现，否则搜不到等于加不上）：
  - 费城半导体：`SOX` / `费半` / `费城半导体(指数)` / `半导体指数` → `usSOXX`（hint 写明是 ETF）
  - 收益率：`美债` / `美国国债` / `十年期美债` / `10年美债` / `ust` / `tnx` → `us10y`；
    `中债` / `中国国债` / `国债收益率` → `cn10y`；`日债` / `日本国债` / `jgb` → `jp10y`
  - 加密：`btc` / `比特币` / `bitcoin` → `BTC-USDT`；`eth` / `以太坊` → `ETH-USDT`；
    `sol` / `doge` / `xrp` 同理
- 四个类型（index / futures / forex / etf）**并发**检索，合并后最多返回 14 条；
  串行要 3 秒，下拉框会像卡死。

#### FR-3.4 删除

- 点击 × → 确认框「从资产清单中移除「{name}」？」→ 从配置删除 → 全量刷新。
- 不提供「撤销」；配置已入库，可手工回滚。

#### FR-3.5 拖动排序

- HTML5 drag and drop；落点判定：指针在目标卡片**右半格**则插到其后，否则插到其前；
  拖到空白处 = 放到最后。
- **过滤视图下只重排可见槽位**：取可见卡在完整数组中的**位置集合**，把新顺序填回这些位置，
  被筛掉的卡关系不动。
- 落盘：`POST /api/market/config`（`assets` 按新序）→ 服务端 `apply_order()` 就地重排缓存并写盘
  → `GET /api/market` 取回。**不重跑取数**（价格与分时一个字节都没变）。
- 失败时：页面内顺序已生效，但 alert「新顺序已在本页生效，但没能写进配置」。

#### FR-3.6 迷你图

- 单一渲染路径，同时支持两类数据：
  - `spark.type = "minute"`：`[[HHMM, price], …]`
  - `spark.type = "daily"`：`[price, …]`（20 个交易日收盘）
- 归一化到 150×26 viewBox；`preserveAspectRatio="none"`（允许横向拉伸）。
- 颜色由 `chg` 决定（不是由首末点决定），保证「线与涨跌标记同色」。
- 点数 < 2 时输出等高占位（26px），不留空洞。

### FR-4 自选股 · 视图一「市场 × 板块」

#### FR-4.1 矩阵结构

- 行 = 市场（由代码前缀决定，`A股 / 港股 / 美股 / 其他`），按字符串升序固定。
- 列 = 板块（`config.sectors` 顺序，拖动列头可改），只显示**当前有标的的板块**
  （`sectors` 字段已过滤）；空单元格显示 `—`。
- 单元格内：每只一个芯片（名称 + 涨跌幅），涨绿跌红。
- 行头：`{市场}` + 小字 `{只数} 只 · 均 {均值}%`（1 位小数）。
- 页脚：图例三色（涨/跌/平）+ 「N 只中 U 涨 D 跌 · 空单元格表示该市场没有这个板块的持仓」
  + 右端「行业归类由本终端维护，非交易所官方口径」。

#### FR-4.2 拖动改归类

- 芯片拖到同市场的另一个板块格 = 改 `sector`。
- 拖到**不同市场**的格子 → **拒绝**：`dropEffect="none"`，格子标红边框，松手无效果。
  理由：市场由代码前缀唯一决定，允许跨行会造出自相矛盾的数据。
- 同格内左右拖动 = 调格内顺序（写入 `watchlist` 数组位置）。
- 落到空单元格：接在「同市场同板块」末位 → 若无，接「同市场」末位 → 再无，接整体末尾。
- 落盘：重排 `watchlist` 数组并改 `sector` → `POST /api/market/config` → `GET /api/market`。
- 列头拖动：调整 `config.sectors` 顺序，同样走配置接口。

#### FR-4.3 批量导入

解析规则（按顺序匹配，全部去重）：

| 输入形态 | 转换 |
|---|---|
| 6 位数字，首位 `6` | `sh` + 代码 |
| 6 位数字，首位 `0` 或 `3` | `sz` + 代码 |
| 6 位数字，首位其他（4/8 等） | `bj` + 代码 |
| 5 位数字 | `hk` + 代码 |
| 已有前缀 `sh/sz/bj/hk` + 5~6 位 | 原样小写 |
| `us` + 字母 | `us` + 大写（去原前缀） |
| 纯字母 1~6 位 | `us` + 大写 |

- 分隔符：空白、`,`、`，`、`;`、`；`。
- 导入项一律 `{code, name:"", sector:"未分类"}`；名称留空由行情回填（展示时 `name || q.name`）。
- 全部重复 → alert「这些代码已经都在自选里了」。
- 导入后触发全量刷新。

#### FR-4.4 板块归类面板

- 逐行：名称 / `代码 · 市场` / 下拉（`all_sectors` 全集）。
- 改变即保存（`POST config`）→ 关闭面板 → 全量刷新。
- 说明文字：「改完自动保存。行业归类由本终端维护，不是交易所口径。」

#### FR-4.5 空态

> 这里还没有手动添加的标的。
> 点上面的「批量导入」粘贴一串代码，或用搜索框逐个添加。
> （若镜像视图有 N 只）你的 N 只卫星仓持仓不用加到这里——切到右边的「地区 × 风格」就能看，
> 那一栏每次刷新自动同步，认得出的都会进来。

### FR-5 自选股 · 视图二「地区 × 风格」（默认视图）

#### FR-5.1 结构

- 行 = `matrix.regions`（地区），列 = `matrix.groups`（风格：进攻/均衡/防御，带颜色点）。
- 只渲染**有内容**的地区行（持有 / 未接入 / 取数失败任一非空）；纯观察地区不进主表。
- 单元格：持有芯片 + 未接入芯片（灰虚线）+ 取数失败芯片（灰实底）。
- 格脚：`{只数} 只 · 均 {均值}% · US${x.x}k`（金额仅在能解析出 `数字+k` 时显示）。
- 行头：`{地区}` + `{只数} 只 · 均 … · US$…k`。
- 表下「观察中 N 只」，按地区分组、浅色显示。
- 页脚：持有 N 只中 X 涨 Y 跌 ·（未接入 M 只）·（这次没取到 F 只）· 金额按备注累加，
  未接入不计入 · 代码自动匹配 A 只 / 人工登记 B 只 ·
  右端「美股 · 港股 · A 股走腾讯，日韩台与欧洲走雅虎；两张源的时间戳不完全一致」。

#### FR-5.2 只读约束

- 该视图内不渲染任何编辑入口：搜索框、批量导入、板块归类**整组隐藏**。
- 标题右侧说明文字随视图切换（两句都放 DOM，切显隐，不改文字）：
  - 视图一：「纵向看市场，横向看板块；**拖动个股到别的格子即改归类**，拖动列头可换列序」
  - 视图二：「镜像自「卫星仓」· **只读**，改那边这里跟着变」
- 操作条右侧固定一个「去改持仓」按钮，跳 `#portfolio`。

#### FR-5.3 切换与记忆

- `localStorage.mm_view_v2` ∈ `{"wl", "hold"}`，**默认 `hold`**；
  读不到或值非法一律回落到 `hold`。
- 切换不请求服务端；只切显隐、chip 选中态，并重绘矩阵容器。
- 两个 chip 各挂数量：左 = `watchlist.count`，右 = `holdings.count + holdings.watch`（0 时不显示）。

### FR-6 刷新与状态

| 入口 | 位置 | 行为 | 耗时量级 |
|---|---|---|---|
| 刷新行情 | 资产区右侧 | `POST /api/market/refresh` → 重取 28 资产 + 自选 + 镜像 → 替换内存对象 → 重绘三段 | 15~60 秒 |
| 更新数据 | 页面右上（全局） | 指标 + 估值 + 资产方向 + 重读判断 + **重建静态页**；**不重取本页行情** | 25 秒左右 |
| 自动刷新 | 数据文件变化 | 无（用户手动或定时任务） | — |
| 判断单独刷新 | 页头「重读判断」 | `GET /api/market/brief`，只重读文件 | < 1 秒 |

**必须实现的两种提示**：

1. 刷新中：按钮文案改「刷新中…」并禁用，完成后恢复。
2. 跨日：页首与判断卡同时标注（见 FR-1 第 6 条）。

## 6. 数据逻辑

> 本章是实现的核心。每一条都对应一个真实故障，省略任何一条都会以「数据看起来对、其实错」的形式复现。

### 6.1 数据源清单

| 品种 | 源 | 接口 / 文件 | 关键约束 |
|---|---|---|---|
| `eq` 股票与 ETF（含美股、港股、A 股） | 腾讯 westock（本地 CLI） | `quote <codes>` | **必须按品种分批**；每批 ≤150 |
| `fu` 期货 | 同上 | `quote` | 与股票**分开调用** |
| `fx` 外汇 | 同上 | `quote` | 与股票**分开调用** |
| 分时 | 同上 | `minute <code>` | 实测 0.78s/次，并发 5、节流 0.12s |
| 债券收益率（美/中） | 同上 | `macro indicator us_yield_curve` / `cn_yield_curve` | 返回**无序**，必须自行排序 |
| 债券收益率（日） | 日本财务省 | `jgbcme.csv` + `historical/jgbcme_all.csv` | 当前月 + 历史文件拼接；历史文件 1.2MB，缓存 24h |
| `gi` 日韩台印新指数 | 新浪 | 日线（经 `apac.sina_daily`） | 无分时，用最近 **20 个收盘**代替并标 `20D` |
| `cr` 加密 | OKX | `/api/v5/market/tickers`、`/candles?bar=1H&limit=24` | 24 小时涨跌用 `last / open24h - 1` |
| 持仓行情（美/港/A） | 腾讯 | `quote` | 与自选股同源 |
| 持仓行情（日韩台欧） | 雅虎 | `v8/finance/chart/{code}?range=5d&interval=1d` | 涨跌幅**必须用最后两根收盘算** |

### 6.2 分派与批量（第一硬约束）

1. 资产按 `kind` 分组：`eq` / `fu` / `fx` / `cr` / `gi` / `bd`。
2. `eq`、`fu`、`fx` **各自单独调用** `quote`，每批 150 个代码。
   同一批里混入期货或外汇时，源只返回股票，期货与外汇被**静默丢弃**，退出码仍为 0。
3. 每批返回后**核对条数**：缺任何一个 → 抛错，整次刷新失败，不允许悄悄少画一张卡。
   错误信息要写清「哪一类、缺几个、前 5 个代码」。
4. 加密走 OKX；`gi` 走新浪日线；`bd` 逐只单独取（三个源、三种滞后）。
5. 分时仅对 `eq` / `fu` / `fx` 取，5 路并发。

### 6.3 行情日期（`market.date`）

- **唯一权威口径**：A 股 `quote` 返回的 `time` 字段，规整为 `YYYY-MM-DD`，取**众数**。
- 期货与外汇的 quote 不带 `time`，不参与判定。
- 全部缺失时才回退：`data/oos/result_latest.json` → `data/hk_senti/hk_senti.json` → 当天日期。
- 禁止用「本机今天」作为默认行情日；那会把休市日错标成交易日。

### 6.4 涨跌幅与单位

- `quote` 若只给价格与昨收，自己算：`chg = (price / prev_close - 1) × 100`，保留 2 位。
- 债券：`chg = (今值 − 前值) × 100`，单位 bp，保留 1 位；`price` 保留 3 位。
- 雅虎：`chg = (closes[-1] / closes[-2] - 1) × 100`。
  `meta.chartPreviousClose` 是 **range 窗口起点**的收盘（`range=5d` 即 5 个交易日前），
  拿它当昨收会把一周涨幅算成一天。
- 全站涨跌配色：涨绿 `#3b6d11`、跌红 `#a32d2d`。

### 6.5 分时与抽稀

- 三种「当天」口径，**不可横向比较波动幅度**：
  - 股票：4~6.5 小时（244~393 点）
  - 期货 / 外汇：约 23 小时（1300~1450 点）
  - 加密：24 小时（1H × 24）
  - 日韩台印新：最近 20 个交易日收盘（标 `20D`）
- 抽稀算法：若点数 > 140，等距取样 139 个点 + **强制保留最后一个点**，
  保证曲线末端与卡片涨跌幅一致。
- 抽稀后注入体积从约 190KB 降到约 40KB。

### 6.6 债券收益率特例

| 项 | 规则 |
|---|---|
| 数值 | 收益率百分数（`4.860` = 4.86%） |
| 变化 | bp（1bp = 0.01 个百分点） |
| 昨值 | 序列的倒数第二个点（**排序后**） |
| 日期 | 每张卡自带 `asof`，角标写 `UST 11-06` / `中债 11-04` / `MOF 11-05` |
| 取不到 | 退回上一份缓存，角标追加「缓存」，**日期照旧**；无缓存则跳过该卡，并记入 `bond_fail` |
| 失败影响 | 不许连坐整页；`bond_fail` 在页面可见 |

美债到 T+0、日债 T+1、中债 T+2 是常态；只写页首日期等于把旧读数当今天。

### 6.7 缓存与持久化

| 文件 | 性质 | 入库 | 生命周期 |
|---|---|---|---|
| `data/market/config.json` | **用户资产**：资产清单、自选股、板块 | 是 | 永久；程序只在缺失时生成默认值 |
| `data/market/brief.json` | **人写判断** | 是 | 由收盘任务覆盖；跨日失效 |
| `data/market/market.json` | **行情缓存**（含分时） | 否 | 每次刷新整份覆盖 |
| `data/market/snapshots/*.json` | 每日快照 | 否 | 由运维动作复制，保留历史 |
| `data/market/jgb_hist.csv` | 日债历史缓存 | 否 | 24 小时 TTL |

写 JSON 必须 `ensure_ascii=False`；在 Windows 上落盘用 `newline="\n"`，否则整篇换行被改成 CRLF。

### 6.8 性能预算

| 环节 | 目标 | 实测 |
|---|---|---|
| 28 资产 + 9 只自选全量 | ≤ 20 秒 | 14.9 秒（2026-11 基线） |
| 其中分时（5 路并发） | ≤ 4 秒 | 约 3.2 秒 |
| 三条 `quote` | ≤ 3 秒 | 各约 1 秒 |
| 雅虎 13 只（8 路并发） | ≤ 4 秒 | 约 3 秒 |
| 搜索（四类并发） | ≤ 1.5 秒 | 约 0.9 秒 |

并发锁：`_market_lock`（市场刷新与判断重读互斥，与其它频道互不阻塞）。
刷新进行中再次请求 → **429**；判断重读抢锁超时 → **503**。

## 5. 自选股联动逻辑（本模块最复杂的一段）

### 5.1 两套数据，绝不能合并

```
config.json.watchlist ──► 视图一「市场 × 板块」   手动、可编辑、独立
                                                
data/portfolio/matrix.json ──► 视图二「地区 × 风格」  自动、只读、镜像
        │
        ├─ symbol（人写简称/代码）
        ├─ regionId / columnId / status / amount
        └─ 每加一只，页面自动出现（推得出的）
```

- 两套数据**没有交集**：手动添加的标的不会被镜像覆盖；镜像里的持仓也不会写进 `watchlist`。
- 合并会破坏两个语义：视图一的「市场 × 板块」靠人工归类，视图二的「地区 × 风格」靠持仓本子；
  一张表同时承载两套坐标，任何一次同步都会互相覆盖。

### 5.2 视图一的数据流

```
config.watchlist[]  {code, name, sector}
   │  按代码前缀分市场（sh/sz/bj→A股, hk→港股, us→美股, 其他）
   │  按市场分批 quote（与资产同一约束：不混品种）
   ▼
rows[] {code, name, market, sector, price, chg}
   │  sector 不在 config.sectors 内 → 强制「未分类」
   ▼
by_market / by_sector / sectors / count / up / down
```

- 取不到行情的标的：**直接不出现在视图一**（这是现有行为）。视图一没有「未接入」灰态——
  灰态只属于镜像。若实现方要对齐，需要新增字段，属于范围变更。
- 涨跌家数：`up = chg > 0`，`down = 总数 − up`（**含平盘**，即「非涨即跌」；
  展示文案写作「N 只中 U 涨 D 跌」，D 实际是「未涨」）。

### 5.3 视图二的数据流（六步，顺序不可换）

```
matrix.json.items[]
  ① 过滤 status：只收 held / add / watch；其余（期权 Sell put 等）直接跳过
  ② 取 symbol，先 derive_code() → 再查 symbols.json.map → 都没有则 missing
  ③ 得到 {code, src:"tx"|"yh", auto:bool}
  ④ 按 src 分两批取行情：tx 走腾讯 quote（一次），yh 走雅虎（8 路并发）
  ⑤ 取到的挂 price/chg；没取到的进 fail（带代码与通道）
  ⑥ status=watch → watching（观察区）；held/add → items（主表）
```

### 5.4 代码推导规则（`derive_code`）

按**顺序**匹配，命中即返回；都不命中返回 `None`（不猜）。

| # | 写法 | 通道 | 转换 | 例 |
|---|---|---|---|---|
| 1 | `^(sh|sz|bj)\d{6}$` | 腾讯 | 原样小写 | `sh601899` |
| 2 | `^hk\d{5}$` | 腾讯 | 原样小写 | `hk00700` |
| 3 | `^us[A-Za-z][A-Za-z.\-]{0,7}$` | 腾讯 | `us` + 大写余部 | `usNVDA` |
| 4 | `^jp(\d{3,4})$` | 雅虎 | 数字 + `.T` | `jp4063` → `4063.T` |
| 5 | `^kr(\d{6})$` | 雅虎 | 数字 + `.KS` | `kr005930` → `005930.KS` |
| 6 | `^tw(\d{4,6})$` | 雅虎 | 数字 + `.TW` | `tw2330` → `2330.TW` |
| 7 | `^[A-Z]{1,5}(\.[A-Z])?$` | 腾讯 | `us` + 原样 | `NVDA` → `usNVDA` |
| 8 | `^[A-Z0-9]{1,6}\.(T|KS|KQ|TW|PA|DE|AS|L|SW|MI|MC|HK)$` | 雅虎 | 原样大写 | `SU.PA` |

顺序的理由：裸美股代码（第 7 条）必须放在带前缀规则之后，否则会抢走 `jp…` 这类写法；
「代码.交易所」（第 8 条）必须放最后，避免 `BRK.B` 被当成裸美股。

### 5.5 `symbols.json`：人工表只补两类缺口

```json
{
  "map":     { "腾讯": {"code":"hk00700","src":"tx"}, "丰田": {"code":"7203.T","src":"yh"} },
  "missing": { "黄金": "场外基金，无场内代码", "通讯ETF": "同类产品多只，无法确定" }
}
```

- `map`：中文简称，或「自动推会推错」的个例（`BRK` → `usBRK.B`、`LVMH` → 美国 ADR `usLVMUY`、
  `SKHY` → 韩股本尊 `000660.KS`）。
- `missing`：明确认不出的，写**原因**，页面悬停可见。
- 判定顺序必须是 **derive → map → missing**。反过来（先查表）等于每加一只都要登记，就不叫自动同步。
- 名字**不猜**：`黄金`、`通讯ETF` 同名产品多只，蒙一个等于在页面上显示另一只产品的涨跌，
  比留白严重得多。

### 5.6 双通道与页脚披露

| 通道 | 覆盖 | 失败表现 |
|---|---|---|
| 腾讯 `quote` | 美股、港股、A 股（含 ADR / 美股 ETF） | 该批缺失 → 进 `fail` |
| 雅虎 `chart` | 日韩台与欧洲（`jp/kr/tw` 与 `代码.交易所`） | 单只失败 → 进 `fail`，不连坐 |

- 页脚固定写明两条源与「时间戳不完全一致」。
- 不允许把两条源的涨跌幅混算成一个指数或一个总数。

### 5.7 `missing` 与 `fail` 必须分开

| 字段 | 含义 | 页面文案 | 悬停原因 |
|---|---|---|---|
| `missing[]` | 认不出代码（未登记 / 场外产品） | 「未接入」灰虚线 | `symbols.missing` 的原因，或「简称推不出行情代码…」 |
| `fail[]` | 认得出，但这次没取到 | 「未取到」灰实底 | 「这次没取到行情：usXXX（腾讯）」 |

- 两者都**占格显示**，不删除——「你持有它、今天看不到涨跌」比「它悄悄不见了」更该被看见。
- 两者**分别计数**，绝不合并成一个「缺失」数。
- 页脚同时报「代码自动匹配 N 只 / 人工登记 M 只」。登记数持续上升说明该扩自动规则，
  而不是继续加手工条目。

### 5.8 脏标记（`hold_dirty`）

```
构建时：holdings.matrix_mtime = matrix.json 的 mtime（整数秒）
每次 GET /api/market：
    dirty = mtime(现在) > holdings.matrix_mtime
    只做浅拷贝，不改缓存对象，不写盘
前端：dirty && (count || watch) → 显示暖色提示「持仓本子刚改过，点『刷新行情』把新标的的行情并进来」
```

- 必须**在请求时算**，不能存进缓存（存进去就有过期的一天）。
- 没有这一条，用户在持仓页加完一只、回来看不见，会判断「自动同步坏了」。

### 5.9 改动传播矩阵

| 用户动作 | 写入 | 是否重取行情 | 页面如何变 |
|---|---|---|---|
| 拖动资产卡 | `config.assets` 顺序 | 否 | 就地重排，立即生效 |
| 增 / 删资产 | `config.assets` | **是（全量）** | 刷新完成后重绘 |
| 改板块（下拉） | `config.watchlist[].sector` | **是（全量）** | 刷新后重排矩阵 |
| 拖动芯片改归类 | `watchlist` 顺序 + `sector` | 否 | 重新拉缓存即生效 |
| 拖列头 | `config.sectors` 顺序 | 否 | 重新拉缓存即生效 |
| 批量导入 | `watchlist` 追加 | **是（全量）** | 刷新后出现在「未分类」 |
| 切视图 | `localStorage` | 否 | 仅切显隐 |
| 改持仓本子 | `matrix.json`（外部） | 需手动「刷新行情」 | 先出现脏标记，刷新后进表 |

> 设计取舍：增删与改板块走全量刷新（10~60 秒），因为新标的必须先有行情才能排版；
> 纯顺序类操作走热重排（< 1 秒）。实现方不要为了「快」把增删也改成热重排——
> 那会得到一张缺行情的卡。

### 5.10 视图状态记忆

| 键 | 值 | 默认 | 说明 |
|---|---|---|---|
| `mm_view_v2` | `wl` / `hold` | `hold` | 非法值回落到 `hold`；v1 旧键不继承 |

默认 `hold` 的理由：这一栏的用途是「看自己拿了什么」，落地先给一张空的自选股表没有意义。

## 7. 接口契约

服务默认监听 `127.0.0.1:8765`。全部返回 `application/json; charset=utf-8`，字段名大小写敏感。

| # | 方法 | 路径 | 用途 | 锁 | 失败码 |
|---|---|---|---|---|---|
| 1 | GET | `/api/market` | 取市场缓存（含 `hold_dirty`） | 无 | 200 |
| 2 | POST | `/api/market/refresh` | 全量重取并写缓存 | `_market_lock` 非阻塞 | 429 / 500 |
| 3 | GET | `/api/market/brief` | 只重读判断文件 | `_market_lock` 8s | 503 |
| 4 | GET | `/api/market/search?q=&kind=stock|asset` | 搜索标的 | 无 | 200（错误也在体内 `ok:false`） |
| 5 | GET | `/api/market/config` | 取全量配置 | 无 | 200 |
| 6 | POST | `/api/market/config` | 保存清单（部分字段） | 无（不碰外部源） | 400 |
| 7 | POST | `/api/refresh` | 全局更新：指标+估值+资产方向+判断+重建页 | `_lock` 非阻塞 | 429 |

### 7.1 `GET /api/market`

```json
{ "ok": true, "market": { /* 见 8.2，含 holdings.hold_dirty */ } }
```

### 7.2 `POST /api/market/refresh`

- 无请求体。
- 成功：`{ "ok": true, "market": {…}, "elapsed": 50.8 }`
- 进行中：`429 { "ok":false, "error":"市场总览正在更新中" }`
- 失败：`500 { "ok":false, "error":"<异常信息>" }`，同时写服务日志与堆栈。

### 7.3 `GET /api/market/brief`

```json
{ "ok": true, "brief": { /* 8.3 */ }, "date": "2026-11-23", "changed": false }
```

- `changed` 仅表示 `as_of` 是否变化；同一天补改文字时返回 `false`，但 `brief` 已是新内容。
- 抢锁失败：`503 { "ok":false, "error":"市场总览正在更新，稍后再试" }`。

### 7.4 `GET /api/market/search`

- 参数：`q`（≥1 字符）、`kind`（`stock` 默认 / `asset`）。
- 响应：`{ "ok": true, "items": [ { "kind": "eq|fu|fx|bd|cr|gi", "code": "...", "name": "...", "hint": "..." } ] }`
- 上限：`stock` 12 条、`asset` 14 条。
- 源报错时：`200 { "ok": false, "items": [], "error": "..." }`（前端显示「没有找到」）。

### 7.5 `GET /api/market/config` / `POST /api/market/config`

- GET：`{ "ok": true, "config": { /* 8.1 */ } }`
- POST 请求体只接受三个键，其余忽略（`version` / `sector_note` 不允许客户端改）：

```json
{ "assets": [...], "watchlist": [...], "sectors": [...] }
```

- 行为：读现有配置 → 覆盖传入的键 → 写盘 → 若内存已有市场缓存，调 `apply_order()`
  就地重排并写盘 → 返回新配置。
- 响应：`{ "ok": true, "config": {…} }`；异常：`400 { "ok":false, "error":"..." }`。

> 注意：POST 是**覆盖式**保存。客户端必须先 GET 全量、改、再 POST，不能只提交增量。

### 7.6 `POST /api/refresh`

- 顺序：指标 → 估值 → 资产方向（失败不连坐）→ 重读 `brief.json` → 重建静态页。
- **不重取市场行情**。市场数字只随第 2 号接口或定时任务变化。
- 响应含 `ok / updated / elapsed / built / build_ms / regime_ok / market(可选) / brief_changed`。
- 锁被占用：`429 { "ok":false, "error":"已有更新任务在进行中" }`。

#### 8.2.1 `assets[]`

```json
{

```

- `spark.type ∈ {"minute","daily"}`；`minute` 的 `pts` 为 `[time, price]`，
  `daily` 的 `pts` 为纯数值数组。
- `src` 可为空字符串；债券的 `src` 自带日期（如 `UST 11-22`）。

#### 8.2.2 `watchlist`

```jsonc
{
  "rows": [ { "code":"hk00700","name":"腾讯控股","market":"港股","sector":"科技",
              "price": 620.5, "chg": 1.23 } ],
  "by_market": { "ORDER": ["A股","港股","美股"], "港股": [ /* row */ ] },
  "sectors": ["科技","半导体"],          // 只含有标的的板块，按 config 顺序
  "all_sectors": ["科技","半导体","金融","能源材料","医药","消费","工业","公用事业","未分类"],
  "markets": ["A股","港股"],
  "count": 1, "up": 1, "down": 0,
  "note": "尚无自选股，可用「批量导入」一次粘贴代码清单"
}
```

> 空清单时后端只返回 `rows / sectors / count / note`，没有 `by_market`、`up`、`down`；
> 前端必须能处理这三个字段缺失。

### 8.3 `data/market/brief.json`（入库，人写）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `as_of` | `YYYY-MM-DD` | 是 | 必须等于撰写当日快照的交易日；不等即 `stale` |
| `generated` | `YYYY-MM-DD HH:MM` | 是 | 撰写时刻 |
| `verdict` | string | 是 | ≤10 字，定调标签（如「芯片崩塌·A股独立」） |
| `tone` | enum | 是 | `risk` / `calm` / `mix`（其它值按 `mix`） |
| `mood` | string | 否 | ≤6 字，风险偏好描述（如「分化」） |
| `headline` | string(HTML) | 是 | 一句话结论；仅允许 `<span class="u|d">` |
| `lead` | string | 否 | 2~3 行导语，纯文本 |
| `points[]` | string(HTML)[] | 是 | **3~5 条**，每条必须带数字；允许 `<b>` 与 `<span class="u|d">` |
| `disclaimer` | string | 否 | 固定写入「不构成投资建议」类声明 |

**HTML 白名单**：`<b>`、`<span class="u">`、`<span class="d">`。其余标签必须转义或不使用——
这一段是**直接 innerHTML 渲染**的。

**内容纪律**（给撰写者/模型）：

1. 每个数字必须能在当日快照里找到，不得四舍五入到失真、不得编造。
2. 只描述发生了什么与结构差异，不写「建议」「目标位」「应减仓」。
3. 五条要点各管一个面（亚太 / A 股 / 港股 / 商品 / 加密与利率），不重复同一件事。
4. 跨交易日必须重写或留空；**留空比写旧的好**——页面会明说「尚未撰写」。

### 8.4 只读依赖：`data/portfolio/matrix.json` 与 `symbols.json`

| 来源 | 本模块用到的字段 |
|---|---|
| `matrix.json` | `items[].symbol / name / regionId / columnId / status / amount`；`regions[].id/name`；`groups[].id/name/color`；`columns[].id/name/groupId` |
| `symbols.json` | `map{简称: {code, src}}`、`missing{简称: 原因}` |

本模块**不写**这两个文件。

## 9. 非功能需求

### 9.1 可靠性

| 故障 | 必须的行为 |
|---|---|
| 单一品种行情缺失 | 抛错终止本次刷新（不允许少画卡） |
| 债券某一市场失败 | 用缓存 + 标「缓存」；无缓存跳过该卡；记 `bond_fail` |
| 镜像同步异常 | 不影响前两段；`holdings.note` 写原因，视图二显示空态说明 |
| 判断文件缺失 | 判断卡空态；其余照常 |
| 搜索接口失败 | 下拉显示「没有找到」，不打断本地过滤 |
| 配置文件损坏 | 读取异常 → 接口报错，**不自动重置、不覆盖原文件**（避免二次破坏）；恢复靠手工修 JSON，或删除后由程序重新生成默认配置 |

### 9.2 性能

见 6.8。验收标准：28 资产 + 9 自选，单次全量刷新 ≤ 25 秒（当前网络条件），
页面首屏（静态内嵌）无需额外请求即可渲染三段。

### 9.3 可维护性

1. **配置即数据**：加一个资产、改一次板块，只动 `config.json`，不改代码。
2. **口径写在页面上**：任何「这个数字怎么来的」都要能在页面上找到一句话，
   而不是只存在于文档或提交记录里。
3. **单一职责**：取数（`market.py`）、渲染（模板）、服务（`server.py`）三层不互相越界。
4. 不引入前端框架、构建工具链与 CDN；产物必须是**单文件 HTML**，双击可开、离线可看、Ctrl+F 可用。

### 9.4 合规

- 页面任何位置不得出现买卖建议、目标价、评级。
- 判断卡页脚固定「不构成投资建议」。
- 不承诺预测能力；文案用「读数」「位置」「方向」这类描述性词。

## 11. 已知边界与待确认

### 11.1 已知边界（当前实现的真实行为，不要当成 bug）

1. **「刷新行情」不会重建静态页。** 它更新内存与 `market.json`，当前页面立即正确；
   但按 F5 会回到构建期的快照（除非随后跑一次「更新数据」或定时任务重建）。
   这是「取数」与「重建」分离的直接结果。
2. **「更新数据」不重取本页行情。** 它只重读判断文字并重建页面。市场数字要新，
   必须点本页的「刷新行情」。两条入口的分工必须在页面上写清，否则用户会以为刷新坏了。
3. **手动自选股当前为空**（0 只）。视图一在默认配置下是空态，这是正常状态，不是缺数据。
4. **资产网格在 620px 仍是 3 列**，卡片明显变窄；未做进一步断点。
5. **分时三种「当天」口径不可横比**：股票 4~6.5 小时、期货外汇约 23 小时、加密 24 小时、
   `gi` 是 20 个交易日。
6. **行业分类非交易所口径**：七个大类由本终端维护，认不出落「未分类」。
7. **`watchlist.count` 的 `down` 含平盘**（`总数 − 上涨数`），文案写作「跌」并不精确。

### 11.2 待确认（需要产品/用户拍板，实现方不要自行决定）

| # | 问题 | 选项 |
|---|---|---|
| Q1 | 「刷新行情」后是否自动重建静态页？ | A. 保持现状（快、但 F5 回退）；B. 自动重建（+1 秒，F5 一致） |
| Q2 | 「更新数据」是否应顺带重取市场行情？ | A. 保持分离（+50 秒的单页操作）；B. 合并（一次按钮全更新，但更慢） |
| Q3 | 视图一是否也要「未接入」灰态？ | A. 保持现状（取不到就不显示）；B. 与镜像对齐（占格） |
| Q4 | 关键读数按名称匹配，还是改成按代码？ | 名称灵活但易静默落空；代码稳但改名不跟随 |
| Q5 | 资产网格是否补 2 列 / 1 列断点？ | 手机端可读性 vs 与现有视觉的一致性 |

## 附录 B · 错误与降级矩阵

| 触发 | 后端 | 前端 | 用户看到 |
|---|---|---|---|
| 刷新被占用 | 429 | 保持画面，恢复按钮 | 「市场总览正在更新中」 |
| 取数抛错 | 500 + 日志 | 保持旧画面 | alert「刷新失败：…」 |
| 某一类缺卡 | 刷新整体失败 | 同上 | 同上（不允许部分成功） |
| 债券失败 | 缓存 + `bond_fail` | 角标加「缓存」 | 卡片日期仍是旧的那天 |
| 判断缺失 | `brief` 为 null 结构 | 空态 | 「今日判断尚未生成」+ 怎么让它出现 |
| 判断跨日 | `stale=true` | 两处橙色标注 | 「判断基于 X 收盘，行情已到 Y」 |
| 配置损坏 | 默认配置 | 正常渲染 | 资产回到默认 26 个 |
| 持仓文件缺失 | `holdings.note` | 视图二空态 | 「还没有持仓数据」+ 检查路径 |
| 搜索源失败 | `ok:false` | 下拉显示「没有找到」 | 可继续用批量导入 |

## 附录 C · 验收命令（curl 版）

```bash
# 1. 取缓存：date 必须等于当天 A 股交易日（休市则等于上一交易日）
curl -s --noproxy '*' http://127.0.0.1:8765/api/market | jq '.market.date, .market.counts'

# 2. 判断跨日：brief.as_of 与 market.date 的关系
curl -s --noproxy '*' http://127.0.0.1:8765/api/market \
  | jq '{date:.market.date, as_of:.market.brief.as_of, stale:.market.brief.stale}'

# 3. 配置：assets / watchlist / sectors 三键齐全
curl -s --noproxy '*' http://127.0.0.1:8765/api/market/config \
  | jq '.config | {assets:(.assets|length), watchlist:(.watchlist|length), sectors}'

# 4. 全量刷新：耗时与债券缺口
curl -s --noproxy '*' -X POST http://127.0.0.1:8765/api/market/refresh \
  | jq '{ok, elapsed, bond_fail, holdings:{count:.market.holdings.count, watch:.market.holdings.watch,
        missing:(.market.holdings.missing|length), fail:(.market.holdings.fail|length)}}'

# 5. 搜索别名：必须能搜出 usSOXX
curl -s --noproxy '*' 'http://127.0.0.1:8765/api/market/search?kind=asset&q=费城半导体' \
  | jq '.items[0]'
```
